## What ran

The Linux tests used real BWA, samtools, pairtools, cooler and cooltools
executables. Inputs were deterministic synthetic data generated by the tests.

* **FASTQ and BAM:** a 100 kb synthetic reference and 100 paired 150 bp reads;
  streaming quality statistics, BWA-MEM `-5SP`, BAM conversion, name sorting,
  pair parsing, filtering, deduplication and binning. Assertions confirm exactly
  100 retained matrix contacts, an unchanged source FASTA, and no index files
  written beside the original reference.
* **pairs to analysis:** 64 bins at 10 kb resolution; compressed pairs,
  balancing, expected contacts, compartment vectors, insulation, loop calling,
  pileup, a bounded region selection and the existing heatmap operator.
  Assertions check conservation of contact counts, more than 50 finite bin
  weights, table sizes, unoriented compartment metadata, a finite 5 by 5 pileup,
  a 20 by 20 selected region and a generated heatmap.
* **Local numerical and runtime tests:** coordinate flips and 1-based pairs
  validation, symmetric matrix rectangles and weights, malformed/mismatched
  FASTQ rejection, cache spill/reload without copying source payloads, process
  transport, cancellation, timeout, retained stderr, workspace path round-trips,
  parameter snapshots, and code-identity changes when scientific helpers change.
* **Batch aggregation:** an unequal 2+1 feature split with NaN/infinite pixels
  verifies per-pixel valid-count weighting. This focused adapter test complements
  the real-tool test; it is not presented as independent scientific validation.

## Issues found and resolved

1. cooltools 0.7.1 dot clustering fails with changed pandas 3 all-NA `idxmin`
   behavior. The Hi-C tool environment now pins pandas 2.2.3.
2. A successful loop call can produce only a header. The adapter now returns a
   valid empty Form instead of reporting a Reader failure.
3. Pileup aggregation excludes non-finite pixels and weights by their valid
   observation counts, including across uneven batches.
4. Scientific helpers now live inside the existing v3 code-fingerprint boundary.
   Parameter JSON remains separate and saved route values remain frozen.
5. An existing Windows preview failure occurred when a saved cache file path
   reached 265 characters. The preview/download lookup now uses the existing
   extended-path helper after validating project containment.

These are small synthetic acceptance tests, not whole-genome throughput or
peak-memory benchmarks. The loop fixture validates successful empty output, not
sensitivity for biologically enriched loops. No biological interpretation was
validated. External-process limits are sampled, not hard OS guarantees.

WSL was not available on the Windows host and remains unverified. Windows
arbitrarily deep working directories are also not generally certified: although
the saved-file preview issue is fixed, creating a deeply nested cache can still
encounter Windows path limits; use a shorter workspace for that case.

The Windows editor-to-server connection UI, remote file picker, authenticated job
submission and reconnectable remote logs are not implemented in this change.
Linux native execution with server-local paths is verified. Desktop EXEs and
GitHub releases were not updated.
