# Operon 1.122.5

## Fixed

- A fresh server install failed at `pip check` because Boltz 2.2.1 was installed
  into the shared environment with `--no-deps`; its strict pins
  (`pyyaml==6.0.2`, `requests==2.32.3`, `scikit-learn==1.6.1`, `scipy==1.13.1`)
  conflict with the resolved shared stack. Boltz now has its own declared
  environment (`boltz`), and the shared installer no longer injects conflicting
  model packages at all.
- `boltz_predict`, `boltz_complex_confidence` and `boltz_affinity_summary`
  declare `resources.environment = "boltz"` and therefore run through the
  environment bridge, with `~/.boltz` weights unaffected.

Backend version: 1.122.5 (operators 709, Readers 101).
