# Operon 2.1.0

Genome annotation I. This batch adds four genome-scale capabilities built on
official tools and real databases, and closes the dependency-contract gap that
made hosted dependency checks disagree with manual probes.

Registry: **713 operators / 101 Readers / 7 packages / 24 routes**.

## Capabilities

| Operator | What it does | Verification |
| --- | --- | --- |
| `antismash_bgc` | Runs the official antiSMASH binary on nucleotide FASTAs and returns biosynthetic gene cluster regions: coordinates, products, protocluster products, gene counts and per-region gene tables. | antiSMASH 8.0.4 with its module databases; the nisin GenBank (15,016 bp) yields one region 1..15,016 of type `lanthipeptide-class-i` with 12 genes; 3.5 s CPU. |
| `rfam_scan` | Scans nucleotide sequences with Infernal `cmscan --rfam` against the pressed Rfam covariance models and returns family, accession, coordinates, strand, score and E-value. | Rfam.cm with 4,227 pressed models; yeast tRNA-Phe (76 nt) hits RF00005 (tRNA) at 1..73, score 62.8, E-value 3.5e-14; 0.15 s. |
| `trnascan_se` | Detects tRNA genes with the official tRNAscan-SE binary in general, bacterial, archaeal or eukaryotic mode; reports coordinates, isotype, anticodon, intron bounds and score. | tRNAscan-SE 2.0.12; the same 76 nt tRNA-Phe is reported once as Phe/GAA at 1..76 with score 67.5; 0.28 s. |
| `amrfinder_plus` | Runs AMRFinderPlus in protein or nucleotide mode and returns gene symbol, element name, scope, class/subclass, method, coverage, identity and coordinates when available. | AMRFinderPlus 4.2.7 with the 2026-10-29.1 database; TEM-1 (286 aa) reports `blaTEM-116` (BETA-LACTAM, ALLELEP) at 100 % coverage and identity; 1.2 s. |

All four operators prepend the resolved tool's own `bin` directory to `PATH`, so
helper binaries (`diamond`, `blastp`, `hmmpfam2`) resolve inside a conda
environment without activation.

## Dependency contract

The 2.0.0 hosted-install incident showed that the dependency snapshot could drop
`resources.environment` / `resources.external_tools`, making the frontend report
`0/N` while a manual probe passed. This release adds
`tests/test_dependency_contract.py`, which drives the real
`DependencySession.sync -> probe -> find_tool` path and asserts:

- the snapshot keeps both resource fields and their fingerprint changes when the
  declared environment changes;
- external tools are resolved with `find_tool` (never imported as Python modules);
- isolated environments are probed through `probe_environment` with the declared
  imports;
- `find_tool` falls back to sibling `env-*/bin` directories;
- the installation receipt only upgrades entries the installer recorded as
  passed, and never hides a real failure.

## Resources

`operon/resources.json` gains `antismash`, `rfam` and `amrfinder` entries with
official URLs, install commands and expected files; `docs/large_resources.md`
documents the download/verify workflow and the fact that the antiSMASH conda
package ships no databases.

## Limits

- antiSMASH requires a separate module database download (about 1 GB compressed,
  several GB after extraction); the conda package ships none. antiSMASH 8 has no
  `--minimal` flag, so the operator requires a database directory. ClusterBlast
  is not part of the default run but can be added for comparative output.
- `rfam_scan` reports per-model hits from cmscan; it is not a complete ncRNA
  annotation pipeline and does not resolve overlapping family assignments.
- `trnascan_se` uses the general model by default; isotype-specific model scores
  (`-s`) are not parsed.
- AMRFinderPlus protein-mode hits carry no contig coordinates; nucleotide mode
  needs the per-species DNA databases and an `--organism` value.
- Real runs depend on locally installed binaries and databases; the four real
  tests are gated by `OPERON_*_REAL=1` and skip when the tools are absent.
