# BioPipe Studio 0.3.0

This release brings the latest Studio editor, input handling, package management
and memory runtime into the Windows desktop distribution. It also integrates the
upstream microbiome and axis-analysis additions without dropping the existing
disk readers, streaming operators or metadata contracts.

## Changes since 0.2.0

- 46 registered operators, 13 Readers and six manageable provider packages.
  Five reusable route templates cover GWAS, RNA-seq DE, proteomics DE, survival
  analysis and downstream 16S abundance-table analysis.
- Eight microbiome operators plus the upstream axis filtering, ranking, binning,
  clustering, summary, dot-plot and violin-plot operators use SDK declarations.
  Group comparison retains upstream two-group, one-versus-rest and pairwise modes,
  with the validated DESeq2 API and surviving-axis annotation propagation.
  Upstream task examples remain in `tasks/`; the single-cell example is not a
  preinstalled reusable route in this release.
- Built-in operators and Readers use the same package protocol as hot-installed
  wheels. Enable, disable, remove and restore packages from Studio. The existing
  streaming `describe` and H5AD/MTX disk-reader capabilities remain available.
  Newly generated wheels declare the current runtime version; existing third-party
  wheels that explicitly require Studio `<0.3` must update that requirement before
  reinstalling on 0.3. Plugin environments inherit dependencies from the active
  runtime, including indirect `.pth` paths and editable installations.
- `biopipe registry discover`, `check` and `build` discover source additions and
  route files, validate their protocols and generate deterministic JSON indexes.
  Startup reads these indexes. No fixed route-name list is embedded in the tool.
- Input upload accepts registered formats and companion-file sets before optional
  parsing libraries are installed. The old fixed 256 MiB upload cap is removed.
  Format-specific libraries are still needed to execute the corresponding Reader.
- H5AD/MTX source preparation writes dense blocks to disk with emergency eviction,
  then hands off to the existing planner. File sizing uses metadata rather than a
  complete input read. Dense reconstruction is not concatenated back into one
  unconditional RAM allocation.
- Automatic runs use 90% of available RAM scanned once at run start, without a
  fixed byte cap. Studio shows a numeric startup estimate, then the actual run
  budget. Runtime pressure is handled by emergency spill, without repeatedly
  rescanning available memory or changing the run budget.
- A quieter editor, contextual help, refined spacing and operator graphics.
  Every library category can collapse independently; search reveals matches and
  clearing it restores the prior layout. Category state survives browser reloads.
- Fixed large-workspace autosave, comma-separated dimension editing, linked axis
  names and YAML/global/runtime parameter round-trips. Expanded operator forms
  expose the declared schemas; CLI/MCP selection and atomic batch undo remain.
- English README, protocol, SDK, package, registry, input and memory documentation.

## Install or upgrade

Download `BioPipe-Studio-v0.3.0-Windows-x64.zip`, extract the entire folder and follow
`START_HERE.txt`. Python 3.11+ with BioPipe's dependencies and Microsoft WebView2
Runtime are required. The host bundles .NET and its compiled UI; Python and
analysis environments remain independent. No Node.js or .NET SDK is needed to run
the desktop package. The Python wheel contains the engine, SDK and CLI/MCP.

The default profile remains `~/.biopipe/studio`, shared by desktop and development
entry points. Existing workflows and explicit package/route management choices
are retained. Newly bundled providers are added on upgrade. User data, credentials,
runtime environments and private registries are excluded from the attachments.

`requirements-readers.txt` lists optional format dependencies;
`requirements-analysis.txt` covers survival, DESeq2, clustering and nonlinear
embeddings. Analysis data must be supplied by the user. Start Studio before
connecting your own agent through MCP.

## Compatibility and limits

Newly adapted upstream kernels use full-memory execution with resource estimates;
they do not claim generic streaming or CUDA support. Emergency spill can release
evictable data but cannot interrupt a native allocation already in progress.
The desktop package is unsigned and has no automatic updater or bundled AI service.

The original source archive in `legacy/`, previous Git history and v0.2.0 release
remain available. This release is based on upstream commit
`fa267bc46a30ee9c9483b7442ff119b9aefcf62c` and preserves its additional task examples.

## Validation

- 200 Python tests passed, including all five route templates, plugins, CLI/MCP,
  input formats, memory planning and SDK contracts. The final Reader/catalog
  adjustments also passed 44 targeted tests; 22 plugin/agent tests passed against
  an installed 0.3.0 runtime after the final installation fixes.
- 109 upstream operator numerical tests passed.
- 28 frontend tests passed; TypeScript and the production build passed.
- Frontend dependency audit: zero reported vulnerabilities.
- Real Windows/WebView2 startup, duplicate launch, occupied-port fallback, worker
  cleanup, draft recovery and relocation into a Chinese path passed.
- Registry validation reported no errors or drift. All 155 legacy source files
  matched their archived SHA-256 values.

Attachment and package-file checksums are supplied for integrity verification.
