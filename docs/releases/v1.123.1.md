# Operon 1.123.1

## Fixed

- The installer's isolated-environment step now supports the recipe Boltz needs
  on this host: conda packages (`rdkit`, `gemmi`, `dm-tree`, `numba`, `scipy`,
  `scikit-learn`, `pillow`, `tqdm`), a CPU torch wheel from
  `download.pytorch.org`, wheel-only Python packages from the Tsinghua mirror,
  `fairscale` from pypi.org, and `boltz` itself with `--no-deps`.
- The duplicated optional-extras call in the installer was removed.

## Verified on the server (glibc 2.17, Python 3.11)

- `import boltz.main` succeeds in the recorded environment
  (`external/boltz`, Python 3.11, conda rdkit/gemmi/dm-tree, CPU torch).
- The environment is declaration-driven: a fresh managed install creates it
  from `operon/environments.json` without manual steps.

Backend version: 1.123.1 (operators 709, Readers 101).
