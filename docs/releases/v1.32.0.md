# Operon v1.32.0

v1.32.0 adds five capabilities: a ProteinMPNN design-position amino-acid
profile, three aromatic interaction operators (amide-pi, cation-pi, aromatic
stacking), and conformer clustering.

## Capability table

| Operator | Category | Purpose |
| --- | --- | --- |
| `proteinmpnn_design_profile` | Machine Learning | Per-position amino-acid frequency matrix from ProteinMPNN sampled designs |
| `structure_amide_pi_bonds` | Machine Learning | Amide-pi contacts between backbone amides and aromatic side chains |
| `structure_cation_pi` | Machine Learning | Cation-pi contacts between charged side chains and aromatic rings |
| `structure_aromatic_stacking` | Machine Learning | Parallel and T-shaped aromatic stacking pairs |
| `rdkit_conformer_cluster` | Machine Learning | ETKDG conformers clustered by symmetry-corrected heavy-atom RMSD |

`esm_embedding_tsne` was considered for this batch and dropped: the existing
`tsne` operator already consumes any `[sample, feature]` matrix, so an
embedding-specific copy would be a duplicate. The `tsne` operator can be
piped directly after `esm_embedding`.

## Operator notes

### proteinmpnn_design_profile

* Runs the official `protein_mpnn_run.py` with the same contract as
  `proteinmpnn_position_entropy` (local checkout, `sys.executable` default,
  `CUDA_VISIBLE_DEVICES=""` for CPU, mandatory `--seed` because upstream
  treats `0` as random).
* Parses the generated FASTA, skips the metadata record, and counts the 20
  standard amino acids at every position. The output matrix is
  `[position, amino_acid]` with frequencies summing to one per position;
  `info` carries the native sequence, the consensus sequence, per-position
  recovery and the sample count.

### structure_amide_pi_bonds

* Amide planes are built from the carbonyl C and O of residue *i* and the
  amide N of residue *i+1* on the same chain. Ring planes come from PHE/TYR
  (one six-membered ring), TRP (fused five- and six-membered rings) and HIS
  (five-membered ring).
* A contact requires: amide carbon to ring centroid distance <= `max_distance`
  (default 4.5 Å), amide carbon offset from the ring plane <= `max_offset`
  (default 2.5 Å), and N-C-centroid angle >= `min_angle` (default 90°).
  These are geometric filters, not quantum interaction energies.

### structure_cation_pi

* Cations are LYS NZ, ARG CZ/NH1/NH2 and HIS ND1/NE2 (residue centroid).
  A contact requires the cation centroid within `max_distance` (default 6.0 Å)
  of an aromatic ring centroid and within `max_offset` (default 2.0 Å) of the
  ring plane.

### structure_aromatic_stacking

* Every aromatic ring pair within `max_distance` (default 6.5 Å) is
  classified: *parallel* when the plane angle is <= `parallel_angle`
  (default 30°) and both offsets are <= `max_offset`; *t_shaped* when the
  angle is >= 60° and at least one offset is within `max_offset`; otherwise
  *other*. The numeric matrix carries distance, angle, both offsets and a
  parallel flag; `info` repeats the labels.

### rdkit_conformer_cluster

* ETKDGv3 embedding with a fixed random seed, optional MMFF94/MMFF94s/UFF
  minimisation, pairwise symmetry-corrected RMSD via
  `rdMolAlign.GetBestRMS`, then RDKit Butina clustering at `cluster_cutoff`.
* The output is `[molecule, cluster]` where each entry is the number of
  conformers of that molecule in that cluster, so rows sum to the conformer
  count. Cluster membership lists and sizes live in `info`.

## Evidence

* `tests/test_extension170.py` – profile hand values (positions 1–6 of four
  designs), matrix sum, fake-runner command path, failure propagation, and a
  skippable real-run check on the 16-residue fixture.
* `tests/test_extension171.py` – ring/amide/cation geometry helpers, hand
  amide-pi geometry (distance 2.1 Å, offset 2.1 Å, angle 180°), hand
  cation-pi values, parallel and T-shaped stacking classification.
* `tests/test_extension172.py` – cone geometry checks against RDKit's own
  conformer RMS matrix, hand clustering matrix, membership matrix, determinism
  and error paths.
* `tests/test_extension173.py` – runner-level contract checks for the
  structure, conformer and ProteinMPNN operators, including exported JSON.
* Registry: 535 operators / 101 Readers / 7 packages / 24 routes, errors `[]`.

## Limits

* The interaction operators use geometric cutoffs, not force-field or QM
  energies; the thresholds are named parameters so callers can tighten them.
* Ring perception is limited to PHE/TYR/TRP/HIS and does not handle
  non-standard aromatic residues or ligands.
* `proteinmpnn_design_profile` needs at least two sampled sequences and a
  local official checkout with weights; the Windows CI check exercises it with
  the downloaded v_48_020 weights.
* Conformer clustering uses RDKit's symmetry-corrected all-atom RMSD
  (hydrogens included); conformer counts above 50 are rejected.

## Compatibility

No existing operator, Reader, port or parameter changes. Version 1.32.0 is a
minor expansion batch; pinned workflows keep their frozen backend version.
