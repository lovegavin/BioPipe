# Operon 1.117.1

Patch release for the managed Linux installer. Backend version 1.117.1; the
operator library is unchanged at 708 operators and 101 Readers.

## Changed

- `pdbfixer` has no PyPI distribution, so the pip solve aborted with
  `No matching distribution found for pdbfixer`. It is now installed by
  micromamba (`pdbfixer`, conda-forge) and filtered out of the pip requirement
  list (`CONDA_PROVIDED`).
- `pyarrow<22` and `libcst<1.8` are passed as pip constraints: newer releases
  no longer publish cp311 wheels for these build-fragile projects, so a search
  without constraints fell back to Rust/Arrow C++ source builds (`Failed
  building wheel for libcst`, `Failed to build pyarrow ...`).
- The source-build fallback now uses `--prefer-binary` (wheels still win) while
  keeping both constraints, instead of re-resolving every package from source.
- The managed environment also installs `rust` next to the C++ toolchain, so a
  Rust-backed sdist can still build if one is unavoidable.

## Verification

- `tests/test_remote_provision.py`: 12 passed, including a test that
  `requirements()` drops conda-provided packages and writes the constraints,
  and a test that the fallback keeps constraints and prefers wheels.
- Server-side check (172.22.148.93, user lihj): a fresh conda python 3.11
  environment with `pdbfixer gxx_linux-64 cmake make` installs the 65-spec
  requirement file with `--only-binary=:all:` and the Tsinghua mirror; the
  previous failures came from the missing pdbfixer distribution and
  unconstrained sdist fallback.

## Boundaries

- If a server cannot reach the Tsinghua mirror, the installer still fails; set
  `PIP_INDEX_URL` or a local wheelhouse.
- `pdbfixer` now comes from conda; its OpenMM dependency must stay ABI
  compatible with the pip-installed NumPy (conda-forge builds against NumPy 2).
