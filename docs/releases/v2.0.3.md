# Operon Studio 2.0.3

This candidate retains the integrated backend 2.0.0 operator library and layered
CLI/MCP/API interfaces described in [2.0.1](v2.0.1.md), plus the dedicated-environment
repair and cancellation changes from [2.0.2](v2.0.2.md). Protocol v3, independent
parameter JSON, memory planning, streaming, spill and SSH behavior are unchanged.

The 2.0.2 test-PC report passed all six agent phases in both editions. Full
closed normally, but Lite reached the eight-second fallback twice. An installing
ESM entry was observed; that entry alone did not prove the blocked call.

A deterministic local reproduction found that an installer parent could exit
while its descendant retained captured output pipes. Cancellation then waited
forever for those pipes, keeping the backend's executor alive after application
shutdown. The same failure was reproduced through the real desktop backend with
the old installer implementation. Install operations now use a Windows job
object, attached before the child starts, or a POSIX process group. Cancellation
and timeout terminate the owned group even after its original parent has exited.
The host's fallback timeout is unchanged.

Slow shutdowns also record active Python thread stacks before fallback. The host
distinguishes a still-running backend from a process that exited while output
readers were pending. These diagnostics help investigate any remaining failure.

The prior candidates and their evidence are retained. Test-PC Explorer launch,
first and repeat normal exits, and the six-phase agent check remain required for
both new packages before final promotion. See the release's `VERIFICATION.md`
for completed checks and remaining gates.
