# v1.39.1 — metal coordination indexing fix

Patch release. No operators or Readers are added; the library stays at 566
operators and 101 Readers.

## Fix

`structure_metal_coordination` passed the already-subset ion coordinates to
`coordination_shell` while indexing them with absolute atom positions. Any
structure where the metal ion was not the first atom raised
`IndexError: index 4 is out of bounds for axis 0 with size 1`. The operator now
passes the full coordinate array and indexes it with the ion positions.

## Regression coverage

`tests/test_extension204.py::test_ion_positioned_after_ligands` places the ion
after two ligand atoms and asserts the shell still reports two coordinating
atoms — the exact case the Windows smoke test hit.

## Verification

- Registry check: 566 operators, 101 Readers, 7 packages, 24 routes, no errors.
- Focused tests 201–205: 23 passed (the new regression included).
- Packaging group: unchanged from 1.39.0.
- Windows smoke runs the operator on a HETATM Zn site and reports three
  coordinating atoms at 2.0 Å mean distance.

## Compatibility

No parameter, contract or output change; existing pinned workflows keep their
frozen values.
