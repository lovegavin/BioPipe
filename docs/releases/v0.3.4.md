# BioPipe Studio 0.3.4

The entire operator and Reader library can now refresh while Studio is running.
Authors edit normal source files, click the library refresh button, and use the
validated changes immediately. All 53 built-in operators, 15 Readers, six provider
packages and five route templates remain included.

## Changes since 0.3.3

- Add a refresh button to the operator library and operator library management.
  The manager opens the actual operator, Reader or additional source directory.
- Discover new and changed classes in the existing operator/Reader directories,
  validate their public contracts, and generate the active registry without manual
  JSON editing or a separate plugin packaging step.
- Snapshot source content and publish one immutable runtime generation only after
  the complete update passes validation. Failed edits retain the active registry;
  running jobs and previously frozen generations retain their code.
- Detect implementation changes even when the version number is unchanged. Skip
  unchanged sources, preserve disabled providers, and respect explicitly removed
  or independently installed packages.
- Keep categories, optional icons, parameter forms and input/output contracts in
  the same live catalog. Preserve streaming and disk-backed Reader hooks.
- Keep Studio startup and frozen workers independent of unfinished source edits.
- Add `biopipe plugin refresh` and asynchronous, session-token-protected refresh
  endpoints. Optional additional-folder inputs support single Python modules,
  wheels and complete SDK projects.
- Include an English guide and a small source example in the desktop archive.
- Use UTF-8 for Python probe/build output on Windows and retain dependency
  resolver details from both output streams when an installation fails.

## Install or upgrade

Extract `BioPipe-Studio-v0.3.4-Windows-x64.zip` into its own directory and launch
`BioPipe Studio.exe`. The host bundles .NET and the frontend. Python 3.11+,
WebView2 and the required algorithm dependencies must already be available or
installed as described in `START_HERE.txt` and [installation](../installation.md).

Open **算子库管理 → 算子目录 / Reader 目录**, add or edit a protocol-compliant
Python module, and click **刷新算子库**. Source paths are resolved from the running
application; the shared profile stores the active registry and runtime snapshots.
No developer-specific installation path is embedded. See
[library hot refresh](../plugins.md#drop-refresh-use).

The first successful refresh freezes the source library. Historical bundled-source
pins created before that freeze cannot recover source bytes already overwritten.
Keep custom profile paths short on Windows installations without long-path support.
Existing routes, canvases, persisted logs and memory settings remain compatible.

## Validation

Release gates cover the Python and frontend suites, production frontend/desktop
builds, registry validation, portable-path auditing, the real Windows WebView2
lifecycle, and source refresh through the packaged executable. Refresh acceptance
includes discovery, generated metadata, execution, unchanged-source skipping,
failure rollback and retained generation execution.

`SHA256SUMS.txt` lists attachment digests. The desktop ZIP includes a source commit
and a per-file SHA-256 manifest; uploaded asset digests are checked before publication.
