# BioPipe Studio 0.3.3

This release retains diagnostic evidence when an analysis worker fails before it
can produce output, and makes operator categories and optional icons explicit in
the public SDK protocol.

## Changes since 0.3.2

- Record process startup, interpreter, exit code and failure independently of the
  worker. Failed launches become inspectable jobs. Silent/native exits retain a
  launcher record even when no Python traceback or run summary exists.
- Create engine events and summaries before engine/plugin initialization, and
  retain run/step/operator events when memory management is disabled.
- Drain final events before closing the UI connection. Show operator messages,
  persisted job errors and actual process output in Run logs. The downloadable
  console file is complete; the UI displays a bounded recent tail.
- Preserve historical empty logs and show their recorded job status/error without
  inventing missing diagnostics. Previously unrecorded exit codes are unrecoverable.
- Standardize optional `category` and `icon` declarations in SDK descriptors,
  schemas, registry generation and hot-installed packages. Unknown or omitted
  icons use the default. Existing descriptors remain compatible.
- Assign categories/icons to upstream `annotate`, `explode`, `order_axis`, `pivot`,
  `prioritize`, `enrich_go` and `enrichment_plot`. Keep existing library group aliases
  and avoid a separate generic Extensions category for these operators.
- Include the upstream TSV/GAF Readers and new operators from the current main
  branch. Reader-specific optional dependencies are still required for execution.

## Install or upgrade

Extract `BioPipe-Studio-v0.3.3-Windows-x64.zip` and launch `BioPipe Studio.exe`.
Existing Python 3.11+ environment discovery and the shared local profile continue
to work. WebView2 and the relevant Python dependencies are required; the ZIP
bundles .NET and the frontend, not the analysis environment. See `START_HERE.txt`
and [installation](../installation.md).

Logs live in the active user's profile, with no developer-specific paths. Existing
routes, canvases and package registrations remain compatible. Memory budgets,
streaming execution and disk-backed Readers retain their existing behavior.

## Validation

The local release gate passes 225 Python tests and 50 frontend tests, production
frontend/desktop builds, registry validation and the portable-path audit. The
real Windows WebView2 lifecycle smoke test also passes.

Regression coverage includes failed process launch, silent exit, engine import
failure, memory-disabled execution, final-event races, cancellation flushing,
large log delivery, historical empty files and restart persistence. SDK tests
cover optional metadata, safe fallback icons and hot-installed package metadata.
Release validation also runs the engine/route suite, frontend tests/build,
relocation/path audits and the real Windows WebView2 desktop lifecycle smoke test.

See [desktop diagnostics](../desktop.md#run-diagnostics) and the
[operator protocol](../operator_protocol.md) for details. Asset hashes are listed
in `SHA256SUMS.txt` and the ZIP includes its source commit and file manifest.
