# Operon 1.120.0

## Fixed

- `operon.dependencies.probe` now separates **direct** requirements from
  **transitive** pins: a direct requirement with a mismatched version still
  fails, while a transitive metadata pin (for example `antifold`'s `numpy==1.26`
  next to the shared NumPy 2 runtime) is reported as a warning. Operators whose
  package over-constrains transitive versions no longer block readiness.
- The managed Linux installer now installs the scientific extras that most
  operators need: `openmm` and `pdbfixer` come from conda-forge in the same
  micromamba transaction, and `boltz`/`antifold` are installed with `--no-deps`
  so their conservative pins cannot downgrade the shared NumPy/Torch stack.

## Documentation

- The quickstart is now split by language: `quickstart_full_flow.zh.md` keeps
  Chinese prompts, `quickstart_full_flow.en.md` keeps English prompts, and
  `quickstart_full_flow.md` is the index. The route request in both versions is
  the open "propose nodes, parameters and expected artifacts, then run after
  confirmation" pattern.

Backend version: 1.120.0 (operators 709, Readers 101).
