# Operon 1.49.0

1.49.0 turns the structure-prediction loop into a design loop: de novo binder
generation through the official RFdiffusion checkout, ligand docking through
AutoDock Vina plus a symmetry-aware pose clustering operator, SASA-based
interface core/rim annotation, and a signal-peptide heuristic for sequence QC.
The registry now publishes **610 operators and 101 Readers**.

## New capabilities

### `rfdiffusion_design` — de novo backbone generation (RFdiffusion)

Wraps the official `RFdiffusion/scripts/run_inference.py` through the same
resource gate introduced in 1.48.0 (`operon/resources.json`, id `rfdiffusion`).
The operator validates the contig syntax (`A1-120/0 B1-80`), assembles the
`contigmap.contigs=[...]` hydra override together with `inference.output_prefix`,
`inference.num_designs`, `inference.device` and an optional `inference.input_pdb`
for motif scaffolding, runs the checkout in a temporary directory, and stacks
every generated PDB into one `[design, atom, field]` Form. Tests drive a fake
`run_inference.py` that writes `design_0.pdb`/`design_1.pdb`, so no weights are
needed; a real run requires the 2.5 GB RFdiffusion weights and a GPU.

### `vina_dock` — protein–ligand docking (AutoDock Vina)

Wraps the `vina` executable: receptor and ligand must be PDBQT (the operator
explains how to convert them), the search box is either explicit
(`center_*`/`size_*`) or ligand-centred, and `--num_modes`, `--exhaustiveness` and
`--seed` are forwarded. The log parser extracts the affinities and RMSD bounds,
the pose parser reads every `MODEL … ENDMDL` block with its per-atom partial
charge and AD4 type, and the poses are stacked into `[pose, atom, field]`
(`x, y, z, charge, atomic_number`). Tests run a fake `vina` script; the real
binary is not installed on this host, so the operator is resource-gated.

### `vina_pose_cluster` — symmetry-aware pose clustering

Greedy leader clustering of docked poses using the same element-aware,
symmetry-aware RMSD as `structure_ligand_pose_rmsd`. Identical or permuted
symmetry-equivalent poses collapse into one cluster; the first pose of each
cluster is reported as its representative. Output is `[pose, statistic]` with
`cluster`, `n_atoms` and the RMSD to the representative.

### `structure_interface_core` — interface core versus rim

Computes the Shrake–Rupley SASA of the complex and of each partner in isolation
(atoms and probe radius configurable) and per-residue burial
`ΔSASA = SASA(complex relevant side) − SASA(isolated side)`. Residues whose
buried fraction reaches `core_fraction` are labelled core, the rest rim. This is
the standard interface-core definition used to prioritise hotspot candidates
before alanine scanning.

### `sequence_signal_peptide` — signal-peptide heuristic

Scans the first `max_length` residues for a hydrophobic h-region ending at a
candidate cleavage site, requires a small residue at P1 and P3 (von Heijne
motif), scores each candidate, and returns the best hit with its h-region,
n-region charge and cleavage site. It is an explicitly heuristic operator (no
neural network), useful for flagging secreted versus cytosolic constructs.

## Verification

- `61` focused tests (`tests/test_extension246.py`–`250.py` plus the protocol and
  reference-doc suites) and the full packaging group pass locally.
- Hand-computed cases: contig validation and command construction against a fake
  RFdiffusion runner; Vina log/pose parsing against a column-aligned PDBQT
  fixture; pose clustering of identical, symmetric and rotated poses (cluster
  membership and representative RMSD 0.0); interface-core burial on a two-atom
  sphere-probe case; signal-peptide detection on albumin-style and cytosolic
  sequences.
- Registry: `610 operators / 101 Readers / 7 packages / 24 routes`, `errors []`.

## Boundaries

- RFdiffusion and AutoDock Vina are **not** installed on the development host;
  both operators fail with a manifest remedy (`operon/resources.json`,
  `scripts/check_resources.py`) and are covered by fake-runner tests rather than
  real inference.
- The signal-peptide detector is a motif heuristic, not SignalP-6; it should be
  cross-checked with the official tool for production annotation.
