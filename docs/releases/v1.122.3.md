# Operon 1.122.3

## Fixed

- The environment bridge resolves the source tree for `PYTHONPATH` even when the
  package is installed into `site-packages` and the checkout lives in a sibling
  `code-<digest>` directory (managed server layout). Without this the worker
  failed with `No module named 'src.task.step.steps.<operator>'`.

## Documented

- `docs/large_resources.md` now specifies the environment resolution order
  (`OPERON_ENV_<NAME>`, `OPERON_ENVIRONMENTS_ROOT`, `<prefix>/external/<name>`),
  the bridge protocol, the inherited `HF_ENDPOINT`/`HF_HOME`, and a per-operator
  environment table (AntiFold, ESM-3, Foldseek, Boltz).
- Generated operator pages gain a **Runtime environment** section that names the
  dedicated interpreter or states that the operator runs in the shared one.

Backend version: 1.122.3 (operators 709, Readers 101).
