# Operon 1.118.3

Patch release from running the Studio frontend suite after the v1.118.2
documentation changes.

## Finding

`frontend/src/operatorPresentation.test.tsx` requires every shipped operator to
render a real icon rather than the generic placeholder. The check exposed three
regressions introduced with recent hard-capability batches: `BatteryFull` was
used by four energy/protonation operators but never registered, `File` was used
by four Readers, and `structure_md_conformational_clusters` declared
`SquaresFour`, which is the placeholder component itself. `foldseek_cluster`
had the same problem.

## Change

- `frontend/src/icons.tsx` registers `BatteryFull` and `File`.
- `foldseek_cluster` uses `TreeStructure`, `structure_md_conformational_clusters`
  uses `CirclesThree`; the operator index and package catalog are rebuilt.

## Verification

- `npm test -- --run`: 117 passed (17 files).
- `npm run build`: succeeds (3.7 s).
- Registry: 709 operators / 101 Readers / 0 errors.
- <Operon-directory> refreshed to 1.118.3 for the acceptance test.

## Boundaries

Icon metadata and generated catalog only; no operator behaviour changes.
