# Operon 1.75.1

Patch release: **real ESMFold-3B verification** for the existing
`esmfold_predict` operator, plus the fair-esm compatibility fixes it needs on
Python 3.12. Counts stay at **664 operators and 101 Readers**.

## Verification

- ESMFold-3B weights (2.77 GB, `dl.fbaipublicfiles.com`) with 2 recycles on CPU:
  a 14-residue peptide gives **94 atoms in 50.4 s**, mean pLDDT **73.3**
  (range 58.0-82.7).
- `pytest tests/test_extension245.py` with `OPERON_ESMFOLD_REAL=1`: 8 passed in
  48.01 s.

## Environment fixes (documented in `docs/large_resources.md`)

- Python 3.12 rejects the mutable dataclass defaults in
  `esm/esmfold/v1/trunk.py` and `esm/esmfold/v1/esmfold.py`; both now use
  `field(default_factory=...)`.
- The public checkpoint stores IPA point projections as plain `Linear` modules
  (`ipa.linear_q_points.weight`), while fair-esm 2.0.0 expects a nested
  `.linear` submodule; the loader remaps those keys.
- ESMFold imports `openfold.np`, and the OpenFold checkout root must not be on
  `sys.path` directly because its `scripts/` package shadows Operon's; the
  instructions use a directory that exposes only the `openfold` package.

## Boundaries

- Single sequence, no MSA; pLDDT is the model's own confidence, not an
  accuracy measurement.
- GPU inference is untested here (the environment's torch is 2.3.1+cu121).
