# Operon 1.85.0

Twenty-sixth real-computation batch: **flexible-receptor docking**. The library
grows to **674 operators and 101 Readers**.

## Added

- `structure_pdbqt_flexible_receptor` (`StructurePdbqtFlexibleReceptorStep`,
  category Docking, arity 1, output `[receptor, statistic]`):
  - selects flexible residues explicitly (`A:45,B:12`) or lists every residue
    with a rotatable side chain;
  - writes a rigid PDBQT receptor without those side chains and a
    `BEGIN_RES`/`END_RES` flex file whose ROOT is CB and whose branches follow
    the side-chain torsions (AutoDock Vina flexible-receptor format);
  - reports the number of flexible residues, flex atoms and chi torsions.
- `vina_dock_python` gained an optional `flex_path`; when present it calls
  `set_receptor(rigid, flex)` so the side chains are sampled during docking.

## Evidence (authority: AutoDock Vina 1.2.7 engine)

- 1MEL with VAL A:2 flexible (CB/CG1/CG2, one chi torsion): Vina accepts the
  rigid+flex pair and docks aspirin at **-2.36 kcal/mol** (rigid receptor
  -2.43), torsion penalty 0.41, hydrogen-bond-free pose set consistent with
  the rigid run.
- 402 of the 1MEL residues are offered as flexible candidates.
- `pytest tests/test_extension314.py`: 5 passed, including the real-engine
  test that loads the pair and completes a docking run.

## Boundaries

- Only side-chain chi torsions are flexible; the backbone stays rigid.
- Flex ROOT is CB with the CA-CB rotation counted as the first chi; residues
  without CB are rejected.
- The flex file carries no TORSDOF lines (Vina flexible-receptor convention);
  ligand TORSDOF remains in the ligand file.
