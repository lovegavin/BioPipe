# Operon backend 1.18.0

Backend release on the 1.x line. SDK remains 3.1.0 and the operator protocol
remains v3; this is a purely additive expansion, so existing workflows and
frozen parameter values keep working.

## New capabilities

| Capability | Kind | Provider | Reference implementation |
| --- | --- | --- | --- |
| `PlyReader` | Reader | `operon-readers` | trimesh 5.2.0 |
| `OffReader` | Reader | `operon-readers` | trimesh 5.2.0 |
| `optics` | operator | `operon-core` | scikit-learn 1.9.1 `OPTICS` |
| `birch` | operator | `operon-core` | scikit-learn 1.9.1 `Birch` |
| `hdbscan` | operator | `operon-core` | scikit-learn 1.9.1 `HDBSCAN` |

### Readers

`PlyReader` parses PLY polygon meshes in ASCII and both binary byte orders. It
accepts vertex properties (`x`, `y`, `z`), face list properties (preferring
`vertex_indices`/`vertex_index`), comment/obj_info records and point clouds
without faces. Polygons are fan-triangulated unless `triangulate=false`.
`OffReader` parses ASCII OFF variants (`OFF`, `COFF`, `NOFF`, `CNOFF`, `STOFF`),
with counts either on the header line or the following line; polygons use the
same fan triangulation. Both readers emit the shared `[element, field]` mesh
table used by `StlReader` and `ObjReader` (vertex rows carry x/y/z, face rows
carry v0/v1/v2).

### Clustering operators

- `optics` returns cluster, reachability and core distance per sample; infinite
  reachability is stored as NaN and counted in `info.infinite_reachability`.
- `birch` returns cluster labels plus subcluster centres, threshold, branching
  factor and the requested cluster count.
- `hdbscan` returns cluster and membership probability per sample, with noise
  samples labelled `-1`.

## Evidence

- PLY/OFF: the four fixtures are written by the reader tests and read back by
  trimesh; vertices and triangle indices match exactly, and the OFF quad has
  unit area after fan triangulation.
- Clustering: a hand-checkable 12-point three-cluster fixture is compared
  value-by-value against scikit-learn 1.9.1 for labels, OPTICS ordering,
  reachability, core distances, BIRCH subcluster centres and HDBSCAN
  probabilities; parameter-validation paths raise `StepError`.
- `tests/test_extension103.py` and `tests/test_extension17_readers.py` contain
  20 passing tests.

## Limits

- PLY: only vertex positions and face indices are exposed; normals, colours and
  texture coordinates are ignored. ASCII and binary inputs share the same fan
  triangulation order, which differs from trimesh's internal fan choice for
  quads but covers the same surface.
- OFF: ASCII only; binary OFF is rejected. Face counts must match the declared
  header.
- OPTICS/BIRCH/HDBSCAN are thin wrappers over scikit-learn; label order follows
  the upstream implementation and is not sorted by cluster size. HDBSCAN's
  `cluster_persistence_` is not exposed because scikit-learn 1.9 does not
  provide it. HDBSCAN emits a scikit-learn FutureWarning about its `copy`
  default; the step passes `copy=True` explicitly where supported.

## Verification

Focused tests, registry and documentation checks are recorded in
`docs/sop_matrix.md`; registry counts are 470 operators, 100 Readers, seven
providers and 24 route templates.

## Compatibility

- SDK 3.1.0, operator protocol v3.
- No operator or Reader IDs were changed or removed.
- No saved workflow needs re-pinning; defaults apply only to new steps.
