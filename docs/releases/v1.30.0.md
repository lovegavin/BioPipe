# v1.30.0

Release date: 2026-11-02

This expansion batch adds four capabilities: ProteinMPNN multi-model ensemble
scoring, maximum-common-substructure clustering, interface hydrogen-bond
networks, and PROSITE-style motif scanning.

| Capability | Kind | What it does |
| --- | --- | --- |
| `proteinmpnn_ensemble_score` | Operator | Scores a structure/sequence pair with several official ProteinMPNN checkpoints and returns the per-sequence mean negative log-likelihood matrix across models. |
| `rdkit_mcs_cluster` | Operator | Computes pairwise maximum common substructure similarity with RDKit and groups molecules by single-linkage clustering. |
| `interface_hbond_network` | Operator | Detects cross-chain backbone hydrogen bonds at an interface with the Kabsch-Sander energy model and reports energy plus N-O distance. |
| `prosite_scan` | Operator | Translates PROSITE-like patterns (letters, `x`, `[sets]`, `{exclusions}`) into regular expressions and reports hit counts and positions. |

## Design notes

- `proteinmpnn_ensemble_score` runs the official `protein_mpnn_run.py` once per
  requested model with `--score_only 1`, parses each `score_only/*.npz`, and
  exposes the model axis so downstream operators can compare checkpoints. The
  model list is validated against `v_48_002/v_48_010/v_48_020/v_48_030`, and
  the operator reuses the FASTA parsing and score summarisation helpers of
  `proteinmpnn_score`.
- `rdkit_mcs_cluster` measures similarity as
  `MCS atoms / min(heavy atoms of the pair)` and clusters with union-find
  single linkage at a configurable distance (`1 - similarity`). The full
  similarity matrix is kept in the output info for auditability.
- `interface_hbond_network` places amide hydrogens from the preceding carbonyl,
  excludes proline donors, applies the DSSP electrostatic energy formula, and
  keeps only bonds whose donor and acceptor sit on opposite chain groups.
- `prosite_scan` follows the PROSITE convention for pattern syntax and reports
  overlapping matches with 1-based positions. It complements the existing
  IUPAC `motif_scan` operator (which scans nucleotide sequence codes) instead of
  replacing it.

## Evidence

- 19 new tests (`tests/test_extension159.py` to `tests/test_extension163.py`):
  fake-runner command construction and matrix values, RDKit pairwise oracle,
  hand-computed hydrogen-bond energy (`-2.9026` kcal/mol, distance `2.9` A),
  PROSITE translation and hit positions, runner-level contract checks, and a
  gated real-oracle comparison of the ensemble matrix against independent
  `proteinmpnn_score` runs for the same models.
- Registry: 525 operators / 101 readers / 7 packages / 24 routes, no errors.
- Focused suite: 19 passed with the real ProteinMPNN checkout.

## Limits

- The ensemble operator needs a local ProteinMPNN checkout and one checkpoint
  per requested model; no weights are bundled.
- `rdkit_mcs_cluster` similarity uses heavy-atom counts, so molecules of very
  different size converge slowly; the timeout guards pathological pairs.
- `interface_hbond_network` uses backbone atoms only (N, C, O) and does not
  model side-chain donors or acceptors.
- `prosite_scan` supports the common PROSITE operators but not repetition
  syntax such as `x(2,4)`.

## Compatibility

No existing operator IDs or contracts changed; the new capabilities are
additive, so saved workflows keep their pins and semantics.
