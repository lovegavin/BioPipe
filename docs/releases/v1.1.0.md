# v1.1.0 — population genetics operators

Backend application **1.1.0** is an expansion batch (MINOR increment) on the
1.0.0 protocol-v3 line. The authoring protocol remains **v3 / SDK 3.1.0** and the
frontend package version remains **0.116.2**; see
[backend versioning](../backend_versioning.md).

## Added operators

All five live in the `operon-genetics` provider and accept hard-call genotypes
only: the input Form is ordered `[variant, sample]`, holds ALT allele counts in
`0..ploidy` with `NaN` for missing genotypes, and carries `ploidy` and
`missing_code` in `info`. `pos` and `chrom` are read from the variant labels or
`axis_info`. Windowed operators follow the scikit-allel window convention: the
first window starts at the first annotated position, the default step equals the
window size, and the last window is clipped to the final position.

| Operator | Output columns | Main parameters |
| --- | --- | --- |
| `tajimas_d` | start, end, n_variants, n_segregating, pi, theta_w, tajima_d | variant_dim, sample_dim, window_size, step_size, min_sites (3) |
| `nucleotide_diversity` | start, end, n_variants, n_bases, pi, pi_per_site, mean_pairwise_difference | variant_dim, sample_dim, window_size, step_size |
| `watterson_theta` | start, end, n_variants, n_bases, n_segregating, theta_w, theta_w_per_site | variant_dim, sample_dim, window_size, step_size |
| `site_frequency_spectrum` | sites, proportion (rows are allele frequencies) | variant_dim, sample_dim, folded (false) |
| `ld_decay` | bin_start, bin_end, n_pairs, mean_r2, median_r2 | variant_dim, sample_dim, max_distance (100000), n_bins (20), max_pairs (5000000) |

`site_frequency_spectrum` requires every variant to have the same number of called
chromosomes, because an unfolded spectrum is only defined for a fixed sample size.
`ld_decay` requires a single chromosome and drops sites with missing genotypes or
no alternate allele.

## Scientific basis

The implementations were checked value by value against scikit-allel 1.3.13:

- `tajimas_d` ↔ `allel.tajima_d` — π sums `mean_pairwise_difference` with missing
  pairs filled with 0, θw = S/a1, and the normalisation uses the a1/a2/b1/b2/c1/c2/e1/e2
  constants.
- `nucleotide_diversity` ↔ `allel.windowed_diversity` — per-base π with
  `n_bases = end - start + 1`.
- `watterson_theta` ↔ `allel.watterson_theta` and `allel.windowed_watterson_theta`.
- `site_frequency_spectrum` ↔ `allel.sfs` and `allel.sfs_folded`.
- `ld_decay` ↔ `allel.rogers_huff_r` — r² of the Pearson correlation between
  hard-call dosages, binned by physical distance.

## Verification

`tests/test_popgen_stats.py` contains 17 tests: value-by-value comparisons for
whole and windowed Tajima's D, π, θw, unfolded and folded spectra, and LD-decay
bins; hand computations; and failure paths (missing `ploidy`, dosage
representation, non-integer or out-of-range counts, windowed analysis without
positions, multi-chromosome LD input, the LD pair-count guard, and a non-constant
chromosome count for the spectrum).

```text
python -m pytest tests/test_popgen_stats.py -q
python -m operon registry check
python scripts/build_operator_docs.py --check
```

Registry after the batch: **410 operators / 88 Readers / 7 providers / 24 route
templates**, `errors: 0`.

## Limitations

- Hard-call genotypes only; dosage input is rejected instead of being silently
  rounded.
- Windowed statistics use the maximum called chromosome count of the whole input
  (as scikit-allel does), so a window with fewer called chromosomes is not
  rescaled.
- LD decay is descriptive and requires one chromosome; it does not model
  recombination or population structure.
- No streaming mode; the operators estimate full-memory use.
