# Operon 1.111.0

One hard capability (703 operators, 101 Readers):
**`esm3_secondary_structure`** — DSSP-style secondary-structure prediction with
the ESM-3 secondary-structure track.

## Operator

The sequence Form is decoded, the ESM-3 open model (default
`esm3_sm_open_v1`) is loaded once per (model, device) and asked to generate the
`secondary_structure` track with a configurable number of steps. The predicted
eight-letter DSSP string is normalised to the sequence length, mapped to the
three coarse classes (H/G/I helix, E/B strand, everything else coil), and
returned as a per-residue table with `state_code`, `is_helix`, `is_strand` and
`is_coil`, plus info counts and fractions.

## Verification

- `tests/test_extension343.py`: 5 passed, 1 skipped (real ESM-3 run gated by
  `OPERON_ESM3_REAL=1`) — state-code mapping, padding/truncation, generated
  track parsing through a fake model, operator round trip, and validation
  errors.
- Real ESM-3 run on the 1MEL VHH domain (132 residues, 8 steps, CPU): all-coil
  and strand output (`H=0`, `E=67`, `C=65`) matching a beta-sandwich fold, with
  **Q3 = 0.9091** against mkdssp 4.2.2 on the crystal structure.
- Registry: 703 operators / 101 Readers / 7 packages / 24 routes, `errors []`.

## Boundaries

- Sequence-only conditioning: no MSA, no templates, no experimental priors, and
  only 8–16 generation steps, so helix content in beta-rich domains is
  under-predicted.
- The ESM-3 checkpoint is 1.4 B parameters and runs CPU inference in roughly
  20 s per 130-residue sequence; GPU is supported but was not exercised.
- The real test is skipped when the ESM package or weights are unavailable;
  the operator itself raises a clear install hint in that case.
