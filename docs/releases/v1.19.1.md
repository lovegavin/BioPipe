# Operon backend 1.19.1

Patch release on the 1.19 line. SDK remains 3.1.0, the operator protocol
remains v3 and the library stays at **474 operators / 100 Readers**, seven
providers and 24 route templates; no capability was added, renamed or removed.

## Fix

`proteinmpnn_design` now passes POSIX-style paths to the official ProteinMPNN
runner for `protein_mpnn_run.py`, `--pdb_path`, `--out_folder`,
`--path_to_model_weights` and `--fixed_positions_jsonl`, and uses the same
POSIX spelling as the fixed-position JSONL key.

The upstream runner derives the output FASTA name with
`args.pdb_path.split("/")[-1]`, which cannot split a Windows backslash path.
On Windows the previous argument list therefore produced names such as
`<temp>//seqs/<profile>\...\mini.fa` and the run failed with
`OSError: [Errno 22] Invalid argument`. `Path.as_posix()` is used on both
platforms because it is a no-op on POSIX, so the same argument list keeps
working under Linux and WSL.

## Evidence

- `tests/test_extension110.py` now asserts that `--pdb_path` and the
  fixed-position JSONL key are the same POSIX spelling and contain no
  backslashes; the fake-runner command test and the gated real-runner test
  (official ProteinMPNN checkout plus `v_48_020.pt` weights, CPU, one sequence)
  still pass.
- Windows 11 verification on `<Operon-directory>` with Windows Python 3.12: the new
  `proteinmpnn_design` smoke run (`<ProteinMPNN-checkout>`, CPU, one sequence)
  completes and returns a `[design, statistic]` form.

## Bookkeeping

`docs/releases/v1.19.0.md` no longer labels the two extended Readers as
version 1.1.0: `FastaReader` and `PdbReader` keep protocol version 1.0.0 and
only gained additive columns/options, which the release note now states
explicitly.
