# Operon Studio 2.0.4

This release candidate retains the integrated backend 2.0.0 library and layered
CLI/MCP/API interfaces from the preceding candidates. Protocol v3, SDK 3.1,
independent parameter JSON, memory planning, streaming, spill and SSH remain intact.

The 2.0.3 test-PC report passed the agent checks in both editions and normal exits
in Full (0.40 and 0.47 seconds). Lite still reached the eight-second timeout twice.
Its newly captured shutdown stacks identified dependency bytecode compilation
running inside the backend thread pool. Owning installer subprocesses alone did
not cover that in-process phase.

Provider and dependency precompilation now runs in an owned child process with
the same Python interpreter. Cancellation covers directory traversal and a
single long compilation, instead of relying on checks between files. No provider
module is imported or executed to compile it. Hash invalidation modes and relative
filenames are retained. A cancelled compilation cannot publish a completed
target receipt or activate its dependency paths.

Regression tests reproduce the old shutdown failure through the real desktop
backend, with only the compiler blocked by an instrumented fixture. The fixed
backend exits while that single compilation is still blocked. A separate
transaction test verifies cancellation before compilation leaves no ready
receipt; normal compilation tests verify both hash modes and Unicode paths.

The existing shutdown diagnostics and fallback deadline remain unchanged. Prior
candidates are retained for comparison. Test-PC Explorer double-click launch,
agent interaction, and first/repeat normal exits of both new editions are still
required before final promotion. Completed checks and pending gates are recorded
in the release asset `VERIFICATION.md`.
