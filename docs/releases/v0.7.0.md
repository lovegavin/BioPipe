# BioPipe Studio 0.7.0

0.7.0 is a source and agent-facing usability release. It makes the existing
78 operators and 16 Readers strict and documented, adds repeatable SOP tooling,
and fixes Studio import/path handling for tasks stored outside the default
Studio workspace. It does not add new analysis operators or Readers.

## Strict contracts

- All 16 Readers and 78 operators now expose `additionalProperties: false`
  schemas. The 30 historical operators were migrated from the generated UI
  parameter list to source declarations; `operator_ui.json` now contains only
  presentation metadata.
- `Step`/`Reader` base classes enforce strict schemas so a new extension cannot
  silently fall back to permissive validation.
- Parameter titles, basic/advanced groups, order and units are normalized in
  descriptors; schema-less legacy behavior is no longer used for built-ins.
- Reader options that were previously accepted loosely are checked before any
  data is read.

## Agent and SOP documentation

- Added the shared [route authoring SOP](../route_sop.md), [LLM guide](../llm_guide.md)
  and [human user guide](../user_guide.md).
- Added generated reference pages for every operator and Reader, plus
  `operator_index.json` / `reader_index.json`, curated notes for high-risk
  behavior, `ANALYSIS.md`/`task.yaml` templates and a route-architect prompt.
- Added `AGENTS.md` with the expected agent reading and validation flow.
- Added `python -m biopipe inspect` for shape, dims, labels, missingness and
  value ranges, and `python scripts/run.py tasks/<dir> --check` for static task
  preflight.
- The canonical flow is demonstrated by `tasks/sop_demo/`.

## Studio import and path fixes

- Task YAML imports now search `code_root` (the source checkout) instead of only
  `~/.biopipe/studio/workspace`. A task in `tasks/<name>/` therefore finds its
  `input/` without manual file selection.
- Explicit project absolute paths are supported in YAML. They are useful when
  the Studio profile and the project live on different Windows drives. Exported
  YAML is still relativized when possible.
- Re-pointing an existing source file preserves its dims, labels and Reader
  arguments (including `args.reader`); a new source starts from Reader defaults.
- Reader option lookup honors `args.reader`, so a `.txt` table can be read with
  the CSV Reader without the UI switching to TxtReader.
- The engine-only `_input_names` key is stripped at runner, graph compile and
  YAML import boundaries. Old graphs containing it remain runnable.
- Cross-drive Windows jobs keep absolute source paths instead of calling
  `os.path.relpath` across drives.

## Safety and resource limits

- `heatmap` now rejects selected matrices above `max_cells` (default
  4,000,000) before converting to float64 or rendering, and clamps the auto
  figure to `max_pixels` (default 40,000,000). This prevents the 5247 x 5247
  correlation case from attempting a 168 GiB Matplotlib allocation.
- Reader and operator precision handling, missing-value declarations and strict
  parameter normalization remain covered by the SOP tests.

## Verification

- Full pytest: **439 passed, 12 skipped, 0 failed**.
- 14/14 verify scripts and 49/49 demo tests pass.
- 29 independent SOP tests; 16/16 Readers and 78/78 operators pass the strict
  schema assertion.
- `biopipe registry check`, `ruff --select F`, `compileall` and the portability
  audit pass.
- Studio-style workspace import was exercised against a real project task; a
  cross-drive (C: workspace, D: data) job completed successfully.

## Compatibility notes

- Relative task paths remain the default and the recommended form for shared
  routes. Absolute YAML paths are a single-machine convenience.
- The nine remaining route-template pytest skips are synthetic-fixture coverage
  gaps; their real-data demo tests are part of the 49/49 above.
- Frontend visual testing remains the user's responsibility; the production
  bundle is rebuilt and the frontend unit suite passes.
- [Windows environment snapshot](../environment/windows-biopipe-conda.yml) and
  [pip freeze](../environment/windows-biopipe-pip-freeze.txt) are included for
  reproducing the tested Windows x64 environment.
