# Operon v1.25.0

Release date: 2026-11-02

Backend 1.25.0 adds five capabilities for inverse folding, interface contact
mapping, antibody loop quality control and tautomer handling. The library now
contains **503 operators and 101 Readers** in seven packages and 24 routes.
Operator protocol 3.1.0 and SDK 3.1.0 are unchanged, so existing workflows keep
their pins and saved values.

## Capabilities

| ID | Category | Purpose |
|---|---|---|
| `esm_if_design` | Machine Learning | Sample sequences for a fixed backbone with the official ESM-IF1 model. |
| `esm_if_score` | Machine Learning | Score a chain, or a supplied sequence, against its backbone with ESM-IF1. |
| `interface_contact_map` | Machine Learning | Binder-residue by target-residue contact matrix (binary or minimum distance). |
| `antibody_cdr_physchem` | Machine Learning | Length, mass, pI, charge, hydrophobicity and PTM motifs per Kabat CDR loop. |
| `rdkit_tautomer` | Machine Learning | Enumerate RDKit tautomers and report the canonical tautomer. |

### esm_if_design

Wraps the inverse-folding utilities of the official `fair-esm` package. The
structure form supplies the N/CA/C backbone of the selected chain; the operator
runs the official autoregressive decoder (`GVPTransformerModel.sample`) and then
re-scores each sample with the official `get_sequence_loss` helper. Output is a
`[sample, statistic]` form with `mean_log_prob` and `sequence_recovery` against
the structure sequence, and the sampled strings are kept in `info.sequences`.

Parameters: `chain`, `model_path`, `num_samples` (1–64), `temperature`,
`seed`, `sample_dim`, `output`. The seed is applied with `torch.manual_seed`
before sampling, so a fixed seed gives identical designs on the same machine.

### esm_if_score

Scores one chain of a structure form against the ESM-IF1 inverse-folding model.
When `sequence` is empty the operator scores the sequence read from the
structure; otherwise it scores the supplied one-letter sequence after checking
its length and alphabet. Output is `[residue, statistic]` with one `log_prob`
per residue, and `info.mean_log_prob` equals the official `score_sequence`
mean over coordinate-bearing residues.

Both ESM-IF operators are CPU-only: the `fair-esm` inverse-folding utilities
build CPU tensors and expose no device switch, so `supports_cuda` is false and
no GPU is requested.

### interface_contact_map

Builds a binder-by-target matrix from two chain groups. With
`value="binary"` every contacting residue pair is 1; with
`value="min_distance"` each cell holds the shortest heavy-atom distance for that
residue pair and `NaN` when the pair is not in contact. The operator shares the
chain-selection and heavy-atom helpers of `structure_contacts`,
`interface_hotspots` and `interface_bsa`, so all interface operators agree on
chain derivation and residue labels.

### antibody_cdr_physchem

Annotates the Kabat CDR-H1/H2/H3 loops with the `antibody_cdr_kabat` numbering
and reports eight statistics per loop. Molecular weight follows the peptide
convention `sum(free amino acids) - (n - 1) * water`, sequons follow the
N-X-S/T rule, deamidation counts NG and NS motifs, and the isoelectric point and
net charge reuse the pKa table of `protein_properties`.

### rdkit_tautomer

Runs the RDKit `TautomerEnumerator` with a configurable cap and reports the
canonical tautomer, whether canonicalization changed the input, heavy atoms,
hydrogen-bond donors and acceptors, and aromatic rings. The enumerated SMILES
list is preserved in `info.tautomer_smiles`.

## Evidence

- `tests/test_extension135.py` (8 tests): contact-map values on a hand-built
  two-chain PDB, a brute-force distance oracle, `include_intra` behaviour and
  parameter errors.
- `tests/test_extension136.py` (8 tests): ANARCI-derived VHH loops, hand-computed
  lengths/motifs/fractions, Biopython `ProteinAnalysis` comparison for mass,
  charge and pI, and error paths.
- `tests/test_extension137.py` (6 tests): 2-pyridone canonicalization, the
  ketone/enol pair of acetic acid, direct `TautomerEnumerator` comparison on
  four molecules, and error paths.
- `tests/test_extension138.py` (6 tests): deterministic ESM-IF designs, per-residue
  scores compared with the official `score_sequence` mean, custom-sequence
  scoring, runner-level contract validation, and error paths. Gated on a local
  `esm_if1_gvp4_t16_142M_UR50.pt` checkpoint.

Focused run: `28 passed` for `test_extension135.py`–`test_extension138.py`, with
the official ESM-IF1 checkpoint and CPU inference. Registry check reports
`503 operators, 101 readers, 7 packages, 24 routes, errors []`.

## Limits

- ESM-IF1 weights are 1.7 GB and are never downloaded automatically; point
  `model_path` at a local checkpoint. Only minimal test backbones are used here.
- `fair-esm` 2.0 imports `biotite.structure.filter_backbone`, which biotite 2.0
  renamed; the operator installs a one-line alias before importing the model.
  PyTorch 2.6+ also defaults to `weights_only=True`, so the loader falls back to
  the official checkpoint payload when required.
- ESM-IF1 inference is CPU-only in `fair-esm`; GPU inference is not wired.
- `antibody_cdr_physchem` uses the Kabat hybrid numbering of
  `antibody_cdr_kabat`, not full HMM-based ANARCI numbering. pI and charge use
  the operator's pKa table rather than Biopython's, which can differ by up to
  ~0.7 pH units on very short loops.
- `rdkit_tautomer` reports the RDKit enumerator result; molecules with more than
  `max_tautomers` forms are truncated by RDKit's internal ordering.

## Compatibility

- Operator protocol and SDK versions are unchanged.
- The five new IDs are additive; no existing ID, port or parameter changed.
- Saved workflows keep their pinned versions and values.
