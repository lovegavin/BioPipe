# Operon backend 1.2.0

Backend/application release 1.2.0 adds one columnar table Reader and four
statistics operators. It is an expansion batch: the second version digit moves
from 1.1 to 1.2 while the authoring protocol (v3) and SDK (3.1.0) stay
unchanged.

## Added capabilities

| Kind | ID | Provider | Purpose |
| --- | --- | --- | --- |
| Reader | `ArrowReader` | `operon-readers` | Arrow IPC, Feather and ORC tables via `pyarrow` |
| Operator | `seasonal_decompose` | `operon-core` | Classical additive/multiplicative decomposition |
| Operator | `patterson_fst` | `operon-genetics` | Patterson's Fst between two labelled groups |
| Operator | `dxy` | `operon-genetics` | Mean pairwise difference between two groups |
| Operator | `heterozygosity` | `operon-genetics` | Observed/expected heterozygosity and F_IS |

`ArrowReader` accepts `.arrow`, `.feather`, `.ipc` and `.orc`, reads Arrow IPC
files and streams, restores encoded text columns and can take the first column
as row labels.

`seasonal_decompose` reads one numeric column of a `[sample, feature]` table and
returns `observed`, `trend`, `seasonal` and `resid` for a fixed period, with the
moving-average endpoints left as NaN.

`patterson_fst`, `dxy` and `heterozygosity` take diploid hard calls from a
`[variant, sample]` genotype matrix. The Fst-family operators take the group
column from a `[sample, feature]` metadata table. All three follow the
scikit-allel definitions: Patterson's numerator is
`(p_a - p_b)^2 - h_a/n_a - h_b/n_b` with denominator `num + h_a + h_b`,
Dxy is `1 - (ref_a*ref_b + alt_a*alt_b)/(n_a*n_b)`, and expected heterozygosity
is `2p(1-p)`.

## Oracle basis

- `ArrowReader` is checked against `pyarrow` round-trips for Feather, IPC file,
  IPC stream and ORC, plus text encoding, row-label extraction and error paths.
- `seasonal_decompose` is checked against R `stats::decompose` for the additive
  and multiplicative models (trend, seasonal and residual agree to the
  float32 storage tolerance of the output Form).
- `patterson_fst` and `dxy` are checked against scikit-allel
  `patterson_fst` and `mean_pairwise_difference_between`; `heterozygosity` is
  checked against `heterozygosity_observed` / `heterozygosity_expected`.

STL decomposition is intentionally not part of this batch. On the same fixture,
statsmodels `STL` and R `stats::stl` differ by up to 0.14 in the seasonal
component under matching window settings (and more with `robust=True`), so a
per-value oracle is not honest yet. The classical moving-average decomposition
does match R exactly and is shipped instead.

## Limits

- `ArrowReader` requires `pyarrow>=14`; `seasonal_decompose` requires
  `statsmodels>=0.14`.
- `heterozygosity` accepts diploid hard calls only.
- `patterson_fst` and `dxy` require at least two genotyped samples per group;
  monomorphic and all-missing variants yield NaN rather than a fabricated value.
- `seasonal_decompose` requires at least two full periods and finite values.
