# BioPipe Studio 0.2.0

This release combines the upstream bioinformatics engine with the desktop workflow
editor, a public operator SDK and interfaces for the user's own AI agent.

## Included

- A Windows desktop host with packaged UI and automatic Python backend startup.
- Branched workflows, reusable route operators, multiple canvas tabs, selection,
  copy/paste, shared batch undo and adjustable side panels.
- 31 built-in operators, 13 readers and GWAS, RNA-seq DE, Proteomics DE and survival
  route templates. Analysis data must be supplied by the user.
- A versioned JSON operator catalog with typed input/output contracts, static
  connection checks, runtime validation and info/axis_info propagation.
- SDK v1, JSON Schemas, operator/reader scaffolding and hot installation of local
  plugin wheels. Saved workflows retain their plugin version pins.
- CLI and MCP selection context, graph validation, atomic revision-checked edits,
  shared undo, events and separately authorized execution. No AI service is bundled.
- Fixed initial memory budgets, planning informed by actual sizes, disk caching and
  emergency spill for evictable data.
- Shared profile discovery across desktop, development, CLI and MCP entry points.
- English protocol, SDK, plugin, agent, desktop and portability documentation.
- Correct vertical alignment of the empty-canvas add-input icon and label.

## Download and launch

Download `BioPipe-Studio-v0.2.0-Windows-x64.zip`, extract the entire folder, and read
`START_HERE.txt`. A configured Python 3.11+ environment and WebView2 Runtime are
required; .NET runtime and the UI are bundled. Install `.[agent]` from the extracted
folder to enable the MCP adapter and CLI. Optional analysis and reader dependencies
are listed separately. `SHA256SUMS.txt` provides attachment checksums.

The wheel contains the Python engine, SDK and CLI/MCP; it does not contain the
compiled desktop UI. Developers can clone the repository or use GitHub's source archive.

## Compatibility and limits

Existing YAML tasks, Steps, Readers and saved routes remain supported. Default user
data stays in `~/.biopipe/studio`; user registries, inputs, credentials and runtime
profiles are never included in the release. Start Studio before connecting MCP.

An emergency spill cannot preempt a native allocation already in progress. New SDK
plugins currently run in full-memory mode; generic chunk execution and CUDA kernels
are not implemented. The desktop package is unsigned and has no automatic updater.

## Legacy source

`legacy/` preserves the previous source at commit
`9a80642d1ce5168e4f12847764387954fbdfff83`, with byte-level checksums and the original
README. Generated outputs, compiled frontend/exe and IDE settings are excluded from
that source snapshot. The complete old tree remains in Git history, and upstream
example analysis outputs remain in the current root `tasks/` directory.
