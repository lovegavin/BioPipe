# Operon 1.83.0

Twenty-fourth real-computation batch: **AutoDock Vina docking through the
official Python engine**. The library grows to **672 operators and 101
Readers**.

## Added

- `vina_dock_python` (`VinaDockPythonStep`, category Docking, arity 1, output
  `[pose, statistic]`):
  - converts the receptor Form into a rigid PDBQT block (AD4 atom types, zero
    charges, hydrogens dropped) and accepts a prepared ligand PDBQT;
  - runs the official `vina` Python engine with configurable box, search
    exhaustiveness, modes, seed, CPU count and scoring function (`vina` or
    `vinardo`);
  - reports the per-pose scoring terms (`total`, `inter`, `intra`, `torsion`,
    `intra_best`), writes the poses to PDBQT and records the best affinity and
    box geometry in info.

## Fixed

- `ligand_pdbqt_prepare` now wraps the ligand in `ROOT`/`ENDROOT` before
  `TORSDOF`; Vina rejects ligand PDBQT files without these tags. Ligands
  remain rigid (`TORSDOF 0`).

## Evidence (authority: AutoDock Vina 1.2.7 engine)

- Aspirin (RDKit ETKDG conformer, PDBQT via `ligand_pdbqt_prepare`) docked into
  1MEL: box at the ligand centroid, exhaustiveness 8, 5 modes in **2.0 s**;
  affinities **-3.00, -2.98, -2.84, -2.83, -2.81 kcal/mol**, all poses written.
- `pytest tests/test_extension312.py`: 4 passed, including the real-engine
  test and the receptor PDBQT contract test.

## Boundaries

- The receptor is rigid and carries zero partial charges; Vina's scoring does
  not use them, but the output is not suitable for force-field rescoring as is.
- Ligands are rigid (`TORSDOF 0`); flexible-ligand torsion trees are not
  generated yet.
- No receptor flexibility (no flexible side chains), no metal coordination
  terms and no water-mediated interactions.
