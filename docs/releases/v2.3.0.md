# Operon Studio v2.3.0

This release separates the application from the reference operator library and
repairs automatic Linux deployment and large-catalog SSH handshakes.

## Application and library

- Application code and releases use `vX.Y.Z`. Analysis implementations, Reader
  implementations, parameter JSON, Markdown and route templates live under
  `library/seed/` and use independent `library-vYYYY.M.D` releases.
- The application wheel can start without a reference library. A separate
  `operon_builtin_library` wheel supplies the factory library. Lite and Full
  desktop archives include that seed for first use.
- User-installed provider generations, disabled packages, workflow pins and
  frozen workflow parameters remain independent of application updates.
- The reference seed is 2026.11.5 (716 operators, 101 Readers). The seven genome
  adapters introduced upstream are included without changing protocol v3.

## Server repairs

- Base installation validates the application, its Python requirements and the
  Hi-C toolchain without eagerly installing every optional model or database.
  Missing optional capabilities retain explicit failed states and remedies;
  they are never advertised as ready.
- Installer logs start before upload/extraction, retain failure output and append
  on retries. The exact selected server log path is shown to the client.
- The installer isolates inherited Conda configuration, invokes micromamba by its
  verified executable name and writes portable archive timestamps.
- Large catalog transfers use an inactivity timeout renewed by unique valid
  frames, with an overall time limit. Duplicate frames cannot extend the wait.
- Dependency receipts survive unrelated site-package changes while retaining
  implementation, dependency and interpreter compatibility checks. Cached
  receipts never overwrite a newly failed dependency check.

## Compatibility and evidence

Protocol v3, lazy discovery, independent parameter JSON, memory admission,
streaming/disk Readers, spill, resumable upload, CLI/MCP services and desktop
editing remain in place. Lite requires a suitable Python environment; Full
includes a tested Windows CPU runtime. Linux-only tools still require Linux.

See the attached verification report for exact build and acceptance results.
The seven new external-tool adapters have synthetic contract tests; inclusion
does not claim that their native tools or large biological databases were
executed in this release's Hi-C acceptance environment.
