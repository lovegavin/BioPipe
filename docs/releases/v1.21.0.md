# Operon backend 1.21.0

Backend release on the 1.x line. SDK remains 3.1.0, the operator protocol
remains v3 and the library grows to **483 operators / 101 Readers**, seven
providers and 24 route templates. This is an additive expansion: no operator
or Reader was renamed, removed or re-versioned.

## New capabilities

| Capability | Kind | Provider | Reference implementation |
| --- | --- | --- | --- |
| `proteinmpnn_score` | operator | `operon-core` | official ProteinMPNN `protein_mpnn_run.py --score_only` |
| `antibody_developability` | operator | `operon-core` | Biopython `ProtParam` conventions (in-house implementation) |
| `esm_pseudo_likelihood` | operator | `operon-core` | fair-esm `ESM2` checkpoints |
| `rdkit_scaffold` | operator | `operon-core` | RDKit `MurckoScaffold` |
| `PdbqtReader` | reader | `operon-readers` | AutoDock PDBQT fixed-column format |

The registry counts move from 479 operators / 100 Readers to **483 operators /
101 Readers**. One Reader is added in this release.

### `proteinmpnn_score`

Scores fixed backbone/sequence pairs with the official ProteinMPNN runner
(`--score_only 1 --path_to_fasta`). The sequence FASTA is parsed with the
official chain separator removed, the runner writes one `score_only/*.npz` per
sequence and the operator reports `mean_nll`, `global_nll`, `nll_std` and
`n_residues` in a `[sequence, statistic]` Form, with the scored sequences in
`info.sequences`. Paths are passed in POSIX form so the operator also runs on
Windows. `seed` defaults to `1` because the upstream runner treats `0` as "pick
a random seed", which makes scores irreproducible.

### `antibody_developability`

Computes twelve whole-sequence developability statistics for antibody domains
and nanobodies: length, molecular weight, isoelectric point, net charge at two
pH values, cysteine count, deamidation (NG/NS) and isomerization (DP) motifs,
N-X-S/T sequons, longest hydrophobic run, hydrophobic fraction and charge
asymmetry. Molecular weight follows the standard peptide formula
(Σ free amino-acid masses − (n−1)·water) and matches Biopython `ProtParam`;
the histogram-based hydrophobic panel can be overridden with a residue set.

### `esm_pseudo_likelihood`

Scores every position of a single protein sequence with a masked-marginal
pseudo-likelihood: each position is masked in turn and the operator reports the
log probability of the wild-type residue under a local ESM2 checkpoint. Scores
are returned in a `[position, statistic]` Form (`log_prob`, labels `"1"`,
`"2"`, ...), with `info.mean_log_prob` and `info.total_log_prob` summarizing
the sequence. Masked positions are scored in batches to bound memory.

### `rdkit_scaffold`

Extracts the Bemis-Murcko scaffold of every molecule in a `SMILES [name]` list
and reports scaffold atoms and bonds, ring and aromatic-ring counts and the
number of side-chain atoms in a `[molecule, statistic]` Form. Acyclic molecules
get an empty scaffold string and all heavy atoms become side-chain atoms.

### `PdbqtReader`

Reads AutoDock PDBQT files into the same `[atom, field]` layout as `PdbReader`
(serial, coordinates, occupancy, B-factor, residue number, chain, residue name,
element) extended with the AutoDock `partial_charge` and `atom_type` columns.
Charges and atom types are read from their fixed columns and, for relaxed
files, from the last two whitespace-separated tokens; halogen elements are
normalized to the two-letter PDB spelling.

## Evidence

- `tests/test_extension117.py` (5 tests) checks PDBQT dispatch through
  `pick_reader(...).implementation()`, the fourteen output columns, coordinate
  rounding, the fixed-column and token charge/atom-type paths, halogen element
  mapping, and malformed/empty inputs.
- `tests/test_extension118.py` (5 tests) compares scaffold rows against RDKit's
  `MurckoScaffold` directly, checks hand-computed benzene values
  (6 atoms / 6 bonds / 1 ring / 1 aromatic ring), acyclic empty scaffolds and
  duplicate-name disambiguation.
- `tests/test_extension119.py` (6 tests) validates the developability panel
  against Biopython `ProtParam` (`molecular_weight` within 1e-4 relative,
  `isoelectric_point` within 0.25 pH, `charge_at_pH(7.4)` within 0.6), plus
  hand-computed motif, sequon and hydrophobic-run counts and the empty-sequence
  NaN row.
- `tests/test_extension120.py` (5 tests) checks the masked marginal against an
  analytic `-ln(27)` for a uniform 27-token vocabulary, verifies that batched
  masking reproduces the per-position computation for a context-dependent stub
  model, and covers the error paths. When `OPERON_ESM_CHECKPOINT` points at
  `esm2_t6_8M_UR50D.pt` the real checkpoint path runs end to end.
- `tests/test_extension121.py` (8 tests) checks the ProteinMPNN command
  construction (posix paths, `--score_only 1`, `--pdb_path_chains`, cwd and
  `CUDA_VISIBLE_DEVICES`), the npz summary arithmetic, FASTA parsing and the
  error paths. A gated oracle runs the official runner through a manual
  subprocess and compares its per-sequence scores with the operator output
  using the real `v_48_020` weights.
- Batch suite (`tests/test_extension110.py` through `tests/test_extension121.py`
  plus `test_extension8.py`, `test_protocol_v2.py` and `test_reference_docs.py`)
  runs 93 passed / 3 skipped. The real ESM checkpoint test is gated on
  `OPERON_ESM_CHECKPOINT`, the ProteinMPNN oracle on a local official
  checkout.
- `python -m operon registry check` reports 483 operators, 101 Readers,
  7 packages, 24 routes and no errors.

## Limits

- `esm_pseudo_likelihood` reports un-renormalized masked log probabilities over
  the model vocabulary; they are meant for relative ranking, not as calibrated
  perplexities. It accepts exactly one protein sequence per Form and costs one
  batched forward pass per masked position.
- `antibody_developability` uses the Biopython peptide molecular weight; the
  earlier `protein_properties` operator keeps its historical convention, so the
  two molecular-weight values differ by a length-dependent amount.
- `PdbqtReader` reads PDBQT but does not write it, and it keeps no torsion-tree
  columns.
- `proteinmpnn_score` needs a local ProteinMPNN checkout and weights; no model
  is downloaded. Multi-chain structures must select chains explicitly with the
  `chains` parameter. `seed = 0` is passed through and means "random".
- `rdkit_scaffold` reports the Murcko scaffold only; scaffold networks and
  generic frameworks are future work.

## Compatibility

Existing workflows, frozen parameter values and saved routes are unaffected.
The four operators are new IDs and `PdbqtReader` is a new Reader for a new
extension (`.pdbqt`), so no existing file resolves differently. The generated
operator index and builtin package snapshot are rebuilt from the source
declarations, and the packaged library stays pinned to the 1.21.0 execution
identity.
