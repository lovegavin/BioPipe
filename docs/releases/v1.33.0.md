# v1.33.0 — Inverse-folding entropy, active-site design, bias scans and SMILES augmentation

**Released:** 2026-11-02 · **Backend:** 1.33.0 · **Registry:** 539 operators / 101 Readers / 7 packages / 24 routes

## Capabilities

| Operator | Input | Output | What it does |
| --- | --- | --- | --- |
| `esm_if_position_entropy` | structure `[atom, field]` | `[position, statistic]` | Samples the official ESM-IF1 model for a fixed backbone and reports per-position sequence entropy (base 2), native recovery and consensus frequency. |
| `ligandmpnn_active_site_design` | — (uses `structure_path`) | `[design, statistic]` | Finds the protein residues within a cutoff of a bound ligand and redesigns only those positions with the official LigandMPNN, keeping the rest of the protein fixed. |
| `proteinmpnn_bias_scan` | — (uses `structure_path`) | `[position, amino_acid]` | Runs the official ProteinMPNN sampler with and without an amino-acid bias and reports the per-position frequency shift induced by the bias. |
| `rdkit_smiles_augment` | — (uses `smiles`) | `[molecule, statistic]` | Enumerates seeded random SMILES strings per molecule and reports unique-variant and length statistics for training augmentation. |

## Design notes

- **`esm_if_position_entropy`** reuses the ESM-IF1 loader and backbone extraction introduced in v1.25.0. Sampling is CPU-only in this fair-esm build and is seeded through `torch.manual_seed`; `num_samples` must be at least 2 because a single design has zero sampled variance. Entropy is computed as `-Σ p log2 p` over the 20 standard amino acids, recovery is the frequency of the native residue and `max_frequency` is the consensus mass.
- **`ligandmpnn_active_site_design`** parses the PDB itself (fixed-column ATOM/HETATM records) so that ligand atoms are available even when the backbone reader is not used. Active-site residues are defined by any heavy atom within `cutoff` angstrom of a ligand heavy atom; every other protein residue is passed to the official runner through `--fixed_residues`. The official runner uses `--number_of_batches`/`--batch_size` rather than a single sequence-count flag.
- **`proteinmpnn_bias_scan`** parses `--bias_AA_jsonl` dictionaries (`{"W": 1.5, "C": -0.5}`) and runs the official sampler twice with the same seed, temperature and model. The output matrix is `frequencies_biased - frequencies_baseline`, so positive values mark amino acids enriched by the bias; `info["top_changes"]` lists the largest absolute shift per position. The operator documents that ProteinMPNN applies biases only in the sampling branch, not in the conditional-probability mode.
- **`rdkit_smiles_augment`** uses `Chem.MolToRandomSmilesVect` with an explicit seed so that augmentation is reproducible. The numeric output keeps the matrix shape while the generated strings live in `info["variants"]`.

## Evidence

- `tests/test_extension174.py` — augmentation determinism, unique counts, step labels, bounds, empty/invalid SMILES.
- `tests/test_extension175.py` — hand entropy/recovery on a two-design example, non-standard residue rejection, parameter errors, and a real ESM-IF1 run on `tests/fixtures/backbone_1bc8_c60_75.pdb` chain C (16 positions × 3 statistics).
- `tests/test_extension176.py` — bias parsing, hand frequency/shift values, fake-runner command and output assertions, error propagation, and a gated official-runner bias shift with `W:3.0` on the same fixture.
- `tests/test_extension177.py` — structure/ligand parsing of `tests/fixtures/ligand_1bc8_c60_75.pdb`, active-site and fixed-residue partitioning, fake-runner output, parameter errors, and a gated official LigandMPNN active-site design run.
- Focused batch: `43 passed, 1 skipped`; the skip is the gated official ProteinMPNN bias scan when `OPERON_RUN_PROTEINMPNN` is not set.

## Dropped from this batch

`structure_dssp` was deferred again: matching DSSP's Kabat–Sander ladder/turn assignment exactly requires an independent implementation, and using `mkdssp` as both engine and oracle would make the check circular. It stays in the backlog with the existing geometry helpers as a starting point.

## Compatibility

- Purely additive: four new operator ids, no existing contract, parameter schema, route or reader changed.
- `esm_if_position_entropy` needs a local ESM-IF1 checkpoint, `torch`, `fair-esm` and `biotite`.
- `ligandmpnn_active_site_design` and `proteinmpnn_bias_scan` need the corresponding official checkouts on disk; no weights are bundled.
