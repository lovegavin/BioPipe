# Operon 1.23.0

Release date: 2026-11-02

`1.23.0` is an expansion batch for structural comparison, interface analysis and
ligand triage. It adds five operators and keeps the `3` operator protocol and the
`3.1.0` SDK unchanged.

## Capabilities

| Operator | Category | Purpose |
| --- | --- | --- |
| `structure_rmsd` | Machine Learning | Kabsch superposition of two `PdbReader` coordinate forms with global and per-residue Cα/all-atom RMSD |
| `interface_hotspots` | Machine Learning | Per-residue interface contact counts, nearest cross-chain distance and buried solvent-accessible area |
| `rdkit_similarity` | Machine Learning | Tanimoto/dice/cosine similarity matrix over Morgan fingerprints |
| `pains_filter` | Machine Learning | PAINS substructure alerts with per-molecule counts and named alerts |
| `ligand_efficiency` | Machine Learning | Ligand efficiency, LLE and BEI from ligand activities |

The registry now contains **493 operators, 101 Readers, seven packages and 24
route templates**.

## `structure_rmsd`

Two `[atom, field]` forms from `PdbReader` are matched by
`(chain, residue number, insertion code, atom name)`. Only heavy atoms are
considered and an optional `atom_names` list restricts the set (`"CA"` for Cα
RMSD, `"CA,N,C,O"` for backbone). Matched atoms are superposed with the Kabsch
algorithm (SVD with reflection correction); the fitted rotation and translation
are applied to the mobile coordinates and the global RMSD is reported. When
`fit_residues` is empty, the matched set itself is fitted; otherwise only the
selected residues define the superposition and every matched residue reports its
own displacement. The output is `[residue, statistic]` with `rmsd` and `n_atoms`
columns plus `info.rotation`/`info.translation` (`moved = R @ mobile.T + t`).

Evidence: unit tests recover a known rigid transform to 1e-6, compare against
Biopython's `SVDSuperimposer` on a synthetic complex, and check per-residue
ranking after a single displaced residue. Eleven tests cover Kabsch geometry,
identity structures, `fit_residues`, atom-name filtering and error paths.

## `interface_hotspots`

Binder and target chains are selected from the `[atom, field]` PDB form; one side
may be omitted and is then derived from the remaining chains, and waters or other
excluded resnames are ignored. Every heavy-atom pair within `cutoff` counts as a
contact; per residue the operator reports `contact_count`, `min_distance` and
`buried_area`, where the buried area is the free-minus-complex Shrake–Rupley
solvent-accessible surface (probe radius 1.4 Å, 92 points) clipped at zero.
`min_contacts` filters the output, `sort_by` chooses contact- or burial-first
ordering, and `info` carries per-chain atom counts and interface statistics.

Evidence: contact counts and distances are compared with an independent
brute-force distance loop on a hand-built two-chain complex, burial totals match
`interface_bsa` on the same file, and the output respects `min_contacts`, water
exclusion and derived chain selection.

## `rdkit_similarity`

`SMILES [name]` lines are parsed to molecules and Morgan bit fingerprints
(`radius` 1–6, `n_bits` 64–16384, optional atom features). The operator writes a
square `[molecule, comparison]` matrix for the selected metric (Tanimoto default,
dice, cosine). `info.molecules` stores the names.

Evidence: every cell is compared with `DataStructs.TanimotoSimilarity`,
`DiceSimilarity` and `CosineSimilarity`; symmetry, unit diagonal and parameter
validation are covered.

## `pains_filter`

The operator builds an RDKit `FilterCatalog` for `pains`, `pains_a`, `pains_b` or
`pains_c`, returns the number of distinct PAINS alerts per molecule, and lists
the alert descriptions in `info.alerts`. Molecules without alerts still get a
row so the molecule axis is preserved.

Evidence: alert counts and descriptions match a direct `FilterCatalog` query for
the full and PAINS-A catalogues.

## `ligand_efficiency`

Input lines are `SMILES activity [name]` with activity in `nM`, `uM` or `mM`
(`assay_unit`). For each molecule the operator computes the heavy-atom count, the
p-activity, the binding free energy `ΔG = −RT ln(10) pActivity` at `temperature`,
then `ligand_efficiency = −ΔG / heavy_atoms`, `LLE = pActivity − cLogP` and
`BEI = 1000 · pActivity / molecular_weight`. `info.molecules` documents every
intermediate and the display unit.

Evidence: ethanol at 6 pActivity is compared with a hand calculation at 298.15 K,
unit conversion (`nM` vs `uM`) and the temperature dependence are checked, and
invalid lines, non-numeric activities and non-positive activities raise
`StepError`.

## Limits

- `structure_rmsd` matches atoms by name, so two files must expose compatible
  `atom_name` columns; alternative-location atoms are not disambiguated beyond
  the first matched occurrence.
- `interface_hotspots` buried area uses Bondi radii and a fixed 92-point sphere,
  so absolute values differ from Freesasa by a few percent; contact counts are
  exact for the given cutoff.
- `rdkit_similarity` supports Morgan bit fingerprints only (not count
  fingerprints or MCS-based similarity).
- `pains_filter` reports RDKit's PAINS catalogue entries, not a full
  structural-alert panel such as Brenk or NIH.
- `ligand_efficiency` requires a known activity and unit; it does not estimate
  activities or convert between assay types.

## Compatibility

- Operator protocol stays at version `3` and the SDK at `3.1.0`; no existing
  operator or Reader contract changed.
- `_structure_common.pick_chain_sides` is shared by `interface_bsa` and
  `interface_hotspots`; the messages of `interface_bsa` are unchanged.
- Saved workflows keep their pinned operator and package versions; the registry
  count increases from 488 to 493 operators.
