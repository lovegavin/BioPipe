# Operon 1.117.5

Patch release that resolves the remaining hard blockers found on a glibc 2.17
HPC host.

## Findings

- `pysam` publishes `manylinux_2_24`/`manylinux_2_28` wheels, which require
  glibc >= 2.28; the host runs glibc 2.17, so pip reported
  `No matching distribution found for pysam` and the whole install aborted.
- `cooltools==0.7.1` is published as an sdist only, so a wheel-only solve can
  never cover it; it is pure Python and needs no compiler.

## Change

- `pysam` joins `CONDA_PROVIDED` and is installed by micromamba from
  conda-forge/bioconda (`pysam=0.22.1`), which ships binaries built for older
  glibc. pip no longer sees it.
- The pip repair is now three-stage: wheel-only solve, then a source-allowed
  solve (`--prefer-binary`, which covers pure-Python sdists such as
  `cooltools`), then — only if that fails — install `gxx_linux-64`, `cmake`,
  `make` into the environment and retry with the conda toolchain.
- Tests updated for the new micromamba package list and the `pysam` filter.

## Verification

- `pytest tests/test_remote_provision.py tests/test_remote_installation.py`:
  27 passed (full remote trio: 48 passed before this change).
- Server: `pysam 0.22.1` imports from the managed environment; the pip solve
  without `pysam` is being re-run against the full 63-spec list.

## Boundaries

The install still requires outbound HTTPS to the configured mirror (Tsinghua
for pip, conda-forge/bioconda for micromamba). No compilers are installed
unless a source build actually fails.
