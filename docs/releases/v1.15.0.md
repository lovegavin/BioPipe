# Operon backend 1.15.0

1.15.0 is the thirteenth expansion batch after the 1.0.0 backend baseline. It
adds 24 beta-diversity indices, Tsallis diversity, variation partitioning and a
CCP4/MRC volume Reader. The protocol, SDK and execution engine are unchanged.

## Added capabilities

| Capability | ID | Provider | Kind |
| --- | --- | --- | --- |
| Beta diversity (24 methods) | `betadiver` | `operon-microbiome` | operator |
| Tsallis diversity | `tsallis` | `operon-microbiome` | operator |
| Variation partitioning | `varpart` | `operon-microbiome` | operator |
| CCP4/MRC volume | `MrcReader` | `operon-readers` | Reader |

### `betadiver`

Computes the 24 presence/absence beta-diversity indices exposed by
`vegan::betadiver` (`w`, `-1`, `c`, `wb`, `r`, `I`, `e`, `t`, `me`, `j`, `sor`,
`m`, `-2`, `co`, `cc`, `g`, `-3`, `l`, `19`, `hk`, `rlb`, `sim`, `gl`, `z`).
For a pair of samples it uses the shared species count `a`, the species unique to
each sample `b` and `c`, and returns the full symmetric sample-by-sample matrix
with a zero diagonal. `maxdist` is reported for normalizing distances.

Reference: R `vegan::betadiver` (all 24 methods) on a 6 x 4 abundance fixture.

### `tsallis`

Computes Tsallis diversity `(1 - sum p^q) / (q - 1)` with the standard limits
`q = 0` (species richness minus one), `q = 1` (Shannon) and `q = Inf`
(`-log(max(p))`). Optional `norm` divides by the richness-dependent normalizer;
optional `hill` returns the Hill-number form. `norm` and `hill` are mutually
exclusive.

Reference: R `vegan::tsallis` with scales `0, 0.5, 1, 2`, plain, `norm` and
`hill` variants.

### `varpart`

Two-set variation partitioning of a response matrix `Y` on `X1` and `X2`.
Predictors are standardized before fitting. The output reports `[a]`, `[b]`,
`[c]`, `[d]`, the individual `X1`, `X2` and union models, with `R2`, adjusted
`R2` and degrees of freedom. Adjusted fractions follow
`1 - (1 - R2)(n - 1)/(n - m - 1)`.

Reference: R `vegan::varpart` on a 24 x 3 response with two 24 x 2 predictor
matrices. Fractions `[a] = -0.0228991`, `[b] = -0.0826498`, `[c] = 0.00179027`,
`[d] = 1.1037586` agree with R.

### `MrcReader`

Reads CCP4/MRC and MRC2014 volume files. The Reader detects the CCP4 (extended
label at byte 208) and MRC2014 (label at byte 136) header layouts, derives the
machine byte order from `machst` with a plausibility fallback, decodes modes 0,
1, 2 and 6, and returns a `slice` by `voxel` matrix. Header fields such as
`nx/ny/nz`, voxel size, cell dimensions, origin, symmetry and labels are exposed
in `info`. Slicing with `slice_start`/`slice_stop` avoids materializing the whole
volume, and `max_cells` (default 4,000,000) bounds the decoded data.

Reference: `mrcfile` 1.5.4 on a generated 2 x 3 x 4 float32 volume.

## Limits

- `betadiver` works on presence/absence and rejects non-finite values; pairs where
  a method is undefined (for example both samples empty) raise an error instead of
  returning a numeric result.
- `tsallis` normalizes each sample by its own total; all-zero samples produce
  `NaN` and are counted in `info.zero_samples`.
- `varpart` implements the two-set design only; `[c]` is not individually
  testable and negative adjusted fractions are expected when predictors do not
  explain variance.
- `MrcReader` supports the common real-valued modes only; complex and unsupported
  modes are rejected. The Reader is independent of `mrcfile`, which is used only
  as the test oracle.

- Backend version 1.15.0; SDK 3.1.0; operator protocol v3.
- No changes to `Form`, the Reader/Step bases, the runner or registry discovery.
- Existing workflows keep their pinned parameter JSON and require no repinning.
- `mrcfile` is not a runtime dependency; it is only used by the R/format oracle
  test when installed.
