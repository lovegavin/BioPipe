# Operon 1.35.0

Backend release of 2026-11-02. This expansion batch adds four sequence-design and
cheminformatics capabilities: interface-focused ProteinMPNN redesign, a sliding
window ESM-IF masked-redesign scan, per-position native recovery, and RDKit
pharmacophore feature counts. The registry grows from 543 to **547 operators**
with **101 Readers**, seven packages and 24 route templates.

## New capabilities

| Operator | Category | What it does |
| --- | --- | --- |
| `proteinmpnn_interface_redesign` | Machine Learning | Finds the binder residues within a cutoff of the target chains and redesigns only those, keeping the rest of the structure fixed. |
| `esm_if_masked_region_scan` | Machine Learning | Slides a masked window along one chain, samples an ESM-IF design per window, and reports per-window recovery and mean log-probability. |
| `proteinmpnn_native_recovery_scan` | Machine Learning | Reports per-position native recovery, dominant substitution and observation counts across sampled ProteinMPNN designs. |
| `rdkit_pharmacophore_features` | Machine Learning | Counts RDKit pharmacophore families (donor, acceptor, aromatic, hydrophobic, ionizable) per molecule. |

## Design notes

- `proteinmpnn_interface_redesign` parses the structure itself, groups standard
  residues, builds a KD-tree over target heavy atoms, and writes a
  `--fixed_positions_jsonl` payload that lists every chain of the structure.
  ProteinMPNN positions are sequential 1-based indices inside each chain, never
  PDB author numbering.
- `esm_if_masked_region_scan` marks only the window with `<mask>` and samples from
  the official checkpoint; each design is scored with a teacher-forced forward
  pass, so the reported log-probability is the model likelihood of the sampled
  sequence. Windows are clamped to the chain ends and `window > length` is an error.
- `proteinmpnn_native_recovery_scan` reads the native sequence from the first
  FASTA record and the designs from the remaining records. `num_seq_per_target`
  must be at least two so the recovery is meaningful.
- `rdkit_pharmacophore_features` builds the standard RDKit feature factory from
  `BaseFeatures.fdef` and counts seven families plus a total column. Feature
  definitions are RDKit-version specific; tests compare against the same factory.

## Evidence

- 22 new tests (`tests/test_extension183.py`–`tests/test_extension186.py`):
  structure grouping and sequential fixed positions, the interface-redesign
  command and its captured fixed payload, the official ProteinMPNN run on the
  bundled 1MEL VHH fixture, masked-window arithmetic, sliding-window scoring with
  a deterministic stub model, native recovery hand values, the official sampling
  run on a 16-residue backbone, and pharmacophore counts against a direct RDKit
  feature-factory oracle.
- Focused regression suite (new tests plus extension8, protocol v2 and reference
  docs) green; the packaging group (builtin pins, dependencies, library bundle,
  operator images, release build, release agent harness) green.

## Limits

- `proteinmpnn_interface_redesign` shells out to a local ProteinMPNN checkout; it
  needs a PDB with full N/CA/C/O backbone atoms and the official weights.
- `esm_if_masked_region_scan` is CPU-only because the fair-esm inverse-folding
  sampler builds CPU tensors, and it scores one design per window unless
  `num_samples` is increased.
- The pharmacophore families follow `BaseFeatures.fdef`; custom feature
  definitions are not configurable yet.

## Compatibility

No operator or Reader was removed or renamed. Existing workflows and pins keep
working; the new capabilities are additive. Versioning follows
`docs/backend_versioning.md`: this is a MINOR expansion batch, so the backend
version moves to 1.35.0.
