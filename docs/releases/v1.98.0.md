# Operon 1.98.0

One hard capability: **`esm3_fold`** (687 operators, 101 Readers). It predicts a
protein structure from sequence with the official ESM-3 open model and returns
the annotated atom table plus pLDDT and pTM summaries.

## Operator

- Input: a `[sequence, position]` protein Form (exactly one sequence).
- Parameters: `num_steps`, `device`, optional `output_path` (persist the PDB),
  `output`.
- Output: a 12-column `[atom, field]` structure Form; info `mean_plddt` (0-1
  scale), `ptm`, `sequence`, `n_atoms`, `num_steps`, `model`.
- The ESM-3 structure track writes a PDB which is read back through the normal
  reader path, so every structure operator can consume the result.

## Verification

- `tests/test_extension327.py`: 3 passed, 1 skipped by default — PDB writing on
  a stub model, operator round trip, multi-sequence rejection.
- Real run (`OPERON_ESM3_REAL=1`) on the 1MEL chain A sequence (132 residues,
  10 steps, CPU): 527 atoms, **mean pLDDT 0.900**, **pTM 0.836**, and a
  Kabsch-aligned **CA RMSD of 1.97 A against the crystal structure** in 21 s.
- Registry check: 687 operators / 101 Readers / 7 packages / 24 routes,
  `errors []`.

## Boundaries

- Single chain, backbone/all-atom output as ESM-3 produces it; no MSA and no
  templates.
- The pLDDT scale is 0-1, unlike ColabFold/OpenFold which report 0-100.
- Quality depends on the model, not this wrapper; the crystal comparison above
  is a sanity check on one domain.
