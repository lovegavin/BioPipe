# Operon 1.65.0

Sixth real-inference batch: the Pfam/HMMER path is verified against the real
Pfam-A 38 release, and the domain test is now environment-neutral. The library
stays at **654 operators and 101 Readers**.

## Evidence

- Database: `Pfam-A.hmm.gz` from `ftp.ebi.ac.uk`, 418,160,514 bytes, downloaded
  with 32 parallel range connections (~1.2 MB/s, 831 s), decompressed to a
  2.1 GB `Pfam-A.hmm` and pressed with `hmmpress` (h3f 508 MB, h3i 2.9 MB,
  h3m 886 MB, h3p 1.1 GB).
- Real `hmmer_domains` run on the 132-residue 1MEL VHH: 4 domains, 3 Pfam
  families, `V-set`, `I-set`, `I-set`, `Ig_3`, 0.42 s on 2 CPUs — the expected
  immunoglobulin-fold assignment.
- `pytest tests/test_extension253.py` with `OPERON_PFAM_HMM` set: 4 passed;
  without it the real test skips. The validation case now clears the env
  variable so the "hmm_path is required" branch is reachable.

## Fixed

- `test_run_errors` no longer depends on whether `OPERON_PFAM_HMM` is exported;
  it clears the variable before asserting the missing-path error.

## Boundaries

- The pressed database (~5 GB) is user-supplied; the operator never downloads it.
- `hmmscan` must be on PATH or passed explicitly; CPU count is capped by the
  operator parameters.
