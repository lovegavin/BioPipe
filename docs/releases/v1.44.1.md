# Operon 1.44.1

Patch: `proteinmpnn_masked_design` now always forwards an explicit
`--path_to_model_weights` directory, defaulting to
`<proteinmpnn_path>/vanilla_model_weights`. The official runner derives that
folder from `os.path.realpath(__file__)` with `rfind("/")`; on Windows the
backslash path makes the index `-1` and the computed checkpoint path becomes
`protein_mpnn_run.p/vanilla_model_weights/v_48_020.pt`, so the designer failed
with `FileNotFoundError` even though the weights were present.

## Verification

- `tests/test_extension225.py` asserts the forwarded weights directory and the
  fake runner fixture now ships a stub `vanilla_model_weights/v_48_020.pt`.
- Focused suite `tests/test_extension225.py`–`228.py` passes (25 tests).
- Registry counts are unchanged (588 operators, 101 Readers).
- The Windows smoke rerun with the real `<ProteinMPNN-checkout>` checkout now
  produces masked designs.

## Compatibility

Operator ID, contract, parameter schema and output dimensions are unchanged;
only the forwarded command line and its default weights directory changed.
