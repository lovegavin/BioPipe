# Operon 1.117.13

Patch release from the first full manual deployment on a glibc-2.17 host.

## Finding

After the pip solve finished (7.8 GB environment), the installer's operator
probe aborted with:

```
Operator dependency checks failed: {"boltz_complex_confidence": "... No module named 'boltz'",
"foldseek_align": "... No module named 'foldseek'", "sequence_rna_accessibility": "... 'RNA'",
"structure_protonation_pka": "... 'pdb2pqr'"}
```

`pdb2pqr` and ViennaRNA (`import RNA`) are ordinary PyPI wheels but were not part
of the policy requirement set; `boltz` and `foldseek` are not importable Python
modules at all (CLI binaries / gated weights), so a missing import is expected
on a host without them.

## Change

- `_ensure_python_extras()` installs `pdb2pqr` and `ViennaRNA` from the mirror
  with the same transfer flags and constraints after the main pip solve.
- `OPTIONAL_MODULES` now also contains `boltz` and `foldseek`: their absence is
  reported as an optional extra instead of failing the installation.
- Tests cover the extra-install command and the optional classification.

## Verification

- `pytest tests/test_remote_installation.py tests/test_remote_provision.py`:
  29 passed.
- Server re-run on the same environment is in progress; the target is a
  `operon-ready.json` receipt, `pip check` clean, and a processed probe.

## Boundaries

Boltz and Foldseek still require the user to provide the CLI/binary plus weights
(see `docs/large_resources.md`); the operators stay resource-gated.
