# Operon 1.117.4

Patch release completing the managed-install fix from v1.117.3.

## Change

`python -m operon.remote.install_linux` runs a dependency probe over every
operator after pip finishes. Operators that import OpenMM failed that probe with
`No module named 'openmm'`, which aborted the whole install even though pip had
succeeded. The probe result is now split: mandatory failures still raise, while
missing `pdbfixer`/`openmm` are reported as an optional extra with the
conda-forge command to enable them.

## Verification

- `pytest tests/test_remote_provision.py tests/test_remote_installation.py
  tests/test_remote_handshake.py`: 48 passed, including a new test that a
  missing `openmm` or `pdbfixer` does not fail the install.
- Server-side sanity check on the managed target: `pyarrow 20.0.0`,
  `numpy 2.2.6`, `libcst` installed from the mirror with `pip check` clean
  (96 s) after the constraints and the slim micromamba environment.

## Boundaries

MD/energy operators remain unavailable until the optional conda-forge packages
are installed; the installer prints the exact command.
