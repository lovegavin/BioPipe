# Operon 2.0.0

Operon 2.0 marks the operator library as a verified, installable capability
layer rather than a growing list of wrappers. The library ships **709 operators
and 101 Readers** (7 packages, 24 routes) with registry hashes, generated
documentation and oracle-backed tests.

## Highlights

- **Real model integrations** with recorded verification: ProteinMPNN and
  LigandMPNN (design, scoring, bias, tied, masked, noise), ESM-2/ESM-IF/ESM-3
  (embeddings, pseudo-likelihood, inverse folding, structure and sequence
  generation), Boltz-1/Boltz-2 (structure and affinity), AntiFold,
  OpenFold, ESMFold, ColabFold, Foldseek, ViennaRNA, OpenMM, PDBFixer,
  PROPKA/pdb2pqr, fpocket, Prodigal, HMMER/Pfam, mkdssp and Vina.
- **Declarative isolated environments.** Operators that cannot share the base
  stack (AntiFold's NumPy 1.26, ESM-3's torch 2.6, Boltz's strict pins) declare
  `resources.environment`; the installer builds each interpreter, the runtime
  bridges inputs and outputs, and dependency checks run inside the right
  interpreter.
- **Large resources are a contract.** `operon/resources.json` and
  `scripts/provision_resources.py` record official URLs, sizes, checksums and
  install commands; `docs/large_resources.md` documents "download once, then
  usable", including huggingface mirror settings.
- **Installation and readiness are observable.** Managed Linux installs are
  idempotent and resumable, every dependency round records the interpreter,
  command, stderr and verdict (`logs/dependency-checks.log`,
  `scripts/diagnose_dependencies.py`), and the handshake prefers the verified
  readiness receipt over stale snapshots.
- **Agent-first surfaces.** Studio canvas edits, HTTP API, MCP tools with
  paginated labelled artifact tables, bilingual agent bootstrap prompts and
  quickstarts for local and server execution.

## Verification

- `python -m operon registry check`: 709 operators / 101 Readers / 7 packages /
  24 routes, `errors []`.
- Focused and packaging test suites pass on Linux; the Windows checkout runs
  the same registry checks, route checks, reader/operator smoke tests and the
  frontend suite.
- Real-inference evidence for each model integration is recorded in
  `docs/design/hard_capability_status.md` and the corresponding release notes.

## Compatibility

- Protocol version 3 authoring is unchanged; existing workflows keep their
  execution identity.
- Version counters move to the 2.x series; the public extension API remains
  `operon_sdk`.

Backend version: 2.0.0 (operators 709, Readers 101).
