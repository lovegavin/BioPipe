# Operon 1.58.1

Documentation patch that records the curation policy for the operator library
and stops the small-operator series. Counts stay at **651 operators and 101
Readers**; no execution behaviour changes.

## Added

- `docs/design/extension_policy.md`: what qualifies for core (hard model
  wrappers, non-obvious correctness, contract-heavy integrations), what does not
  (trivial arithmetic, niche formats, unverifiable logic), and how a user asks
  the agent to add a capability on demand.
- `docs/README.md` links the policy under "Design notes".

## Changed

- The backlog now lists only hard, high-value capabilities (Boltz-2 prediction,
  Foldseek search, AntiFold scoring, OpenFold prediction). Easy, low-value or
  niche operators are documented as on-demand extensions instead of being
  shipped in batches.

## Verification

- Registry: 651 operators / 101 Readers / 7 packages / 24 routes, `errors []`.
- Focused documentation gate: `test_reference_docs.py` and `test_protocol_v2.py`.

## Boundaries

- AntiFold remains blocked: the packaged model download from OPIG stalls in this
  environment, and the current environment fix (biotite `filter_backbone`
  aliasing) needs a verified run before shipping an operator. It is listed as a
  hard capability to retry, not as a shipped operator.
