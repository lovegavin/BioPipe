# Operon 1.116.1

Patch release for the managed Linux server installer. Backend version 1.116.1;
the operator library is unchanged at 707 operators and 101 Readers.

## Changed

- `operon/remote/install_linux.py`: pip now runs against
  `https://pypi.tuna.tsinghua.edu.cn/simple` with `--trusted-host`, transfer
  retries/timeouts, and `--only-binary=:all:` so a wheel is preferred. If no
  wheel exists for the complete requirement set (for example an older pyarrow),
  the installer prints the pip tail and retries the same request **without**
  `--only-binary=:all:`, compiling against the env-local toolchain.
- `compiler_environment()` exports `CC`/`CXX` from the conda-forge compiler
  package (`x86_64-conda-linux-gnu-cc/c++`, falling back to `gcc/g++`) so the
  source-build retry does not need sudo.
- `operon/remote/provision.py`: the micromamba environment now also installs
  `gxx_linux-64 cmake make` next to the existing `c-compiler cxx-compiler`, so
  every new managed environment has a C++ toolchain without root.

## Verification

- `tests/test_remote_provision.py`: 10 passed, including a new test that forces
  the wheel attempt to fail and asserts a second, mirror-pinned source attempt
  without `--only-binary=:all:`, and a test that the bootstrap script installs
  `gxx_linux-64`, `cmake` and `make`.

## Boundaries

- The mirror is pinned to Tsinghua; a server that cannot reach it still needs a
  local wheel mirror or `PIP_INDEX_URL` override.
- The source-build retry still needs network access for build dependencies
  (setuptools/wheel) unless they are already cached.
