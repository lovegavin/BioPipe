# Operon 1.123.0

## Fixed

- A managed install aborted with
  `Operator dependency checks failed: {"esm3_*": "No module named 'esm'"}` when a
  declared environment existed but its imports were incomplete. Environment-backed
  operators are now **optional for the deployment gate**: the shared installation
  completes, the environment is reported as `unavailable: <reason>`, and the
  operator explains the missing interpreter at run time.
- The installer verifies every declared environment with
  `operon.environments.probe` after building it and prints a single
  ready/unavailable line, so logs no longer end with a bare traceback.
- The ESM-3 recipe is pinned to the combination verified on the server
  (Python 3.12, torch 2.6.0, transformers<4.48.2, ESM 3.2.2 from GitHub).

Backend version: 1.123.0 (operators 709, Readers 101).
