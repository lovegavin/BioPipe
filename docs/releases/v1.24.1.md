# Operon v1.24.1

Patch release. No operators or Readers were added; the counts stay at
**498 operators / 101 Readers / 7 packages / 24 routes**.

## Fix

The three operators added in 1.24.0 declared a human-readable description in
their output contract `info` schema:

```json
"info": {"missing_code": "Missing scalar value code stored on the output form."}
```

The protocol schema expects every `info` entry to be a rule object, not a
string. `step.run` never reads that schema, so the operator unit tests passed,
but the runner validates the returned Form through
`src/core/contracts.py` and crashed with:

```
AttributeError: 'str' object has no attribute 'get'
```

The affected operators are `structure_hbonds`, `ligandmpnn_design` and
`ligandmpnn_score`. Their output contracts now rely on `info_open: true` only,
which is how the other operators declare open execution metadata, so workflow
runs accept their forms again.

## Regression coverage

`tests/test_extension134.py` drives the five 1.24.0 operators through
`src.task.runner.run` with a real `Context`, so the declared output contracts
are validated the same way a saved workflow validates them. The earlier unit
tests call `step.run` directly and cannot catch this class of bug.
