# Operon 1.50.0

Release date: 2026-11-02

The 1.50.0 batch extends the sequence-design loop with interface-restricted
scoring, microbial gene annotation, domain annotation against a Pfam profile
database, antibody humanization scoring and PDBQT ligand preparation. The
operator library now holds **615 operators and 101 Readers** in seven packages
across 24 service routes.

## New capabilities

| Operator | Category | What it does |
| --- | --- | --- |
| `proteinmpnn_masked_interface_score` | Machine Learning | Runs ProteinMPNN in `--conditional_probs_only` mode and reports the mean negative log-likelihood of the interface residues versus the rest of the chain, so candidate designs can be ranked on interface quality alone. |
| `prodigal_genes` | Sequence | Predicts coding sequences with the official Prodigal binary and exposes coordinates, strand, length and the partial flag for every gene, plus the translated proteins. |
| `hmmer_domains` | Sequence | Annotates protein sequences with `hmmscan` against a Pfam profile database and reports per-domain envelopes, alignments and E-values. |
| `vhh_humanization_score` | Machine Learning | Aligns a VHH framework to human IGHV3-23*01 plus IGHJ4*01 and reports per-framework and overall mismatch fractions, the standard humanization acceptance metric. |
| `ligand_pdbqt_prepare` | Chemistry | Builds a 3D conformer with RDKit, assigns Gasteiger charges and AutoDock 4 atom types, and writes a ready-to-dock PDBQT ligand. |

## Verification evidence

- Hand-computed cases: sequential residue numbering across chains, interface
  residue selection at a 4.5 Å cutoff, Prodigal GFF parsing (strand, partial
  codes 00/10/11), HMMER domtbl parsing (22 columns, envelope versus alignment
  coordinates), Kabat framework mismatch fractions, and the PDBQT serial/charge
  column layout.
- Reference-oracle checks: the interface scorer is driven through a fake
  ProteinMPNN runner that writes the official `score_only` `.npz` layout, so the
  parsing and the region split are exercised end to end without weights. The
  gene and domain operators use fake executables that emit the official GFF and
  `--domtblout` formats; the real binaries are gated behind
  `operon/resources.json` entries (`prodigal`, `pfam`) because neither the
  Prodigal binary nor a Pfam-A.hmm database ships with the host.
- Property checks: RDKit conformer embedding is validated by the atom count,
  the absence of NaN coordinates, and the AD4 type set (`A`, `OA`, `H`, `HD`).
- `pytest tests/test_extension251.py`–`255.py` reports **16 passed**; the
  focused group with `test_protocol_v2.py` and `test_reference_docs.py`
  reports the same tests plus the protocol suite.

## Resources

`operon/resources.json` now lists ten resources: the previous eight plus
`prodigal` (`OPERON_PRODIGAL_PATH`) and `pfam` (`OPERON_PFAM_HMM`). Neither
binary nor database is bundled; `python scripts/check_resources.py` prints what
is missing and how to install it.

## Boundaries

- `proteinmpnn_masked_interface_score` inherits ProteinMPNN's fixed-position
  rules: `--score_only` does not accept fixed positions, so the interface is
  scored but not masked.
- The Prodigal and HMMER wrappers require the external executables and their
  databases; without them they raise a resource-gated `StepError` naming the
  environment variable and the download command.
- The humanization score compares Kabat framework segments only; it is a
  germline-distance metric, not a developability prediction.
