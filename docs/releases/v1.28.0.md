# Operon 1.28.0

Expansion batch adding four capabilities around inverse-folding redesign,
synthetic accessibility, structure flexibility and sequence complexity.
Registered counts: **516 operators / 101 Readers / 7 packages / 24 routes**.

## Capabilities

| Operator | Purpose |
|---|---|
| `esm_if_redesign` | Partial ESM-IF inverse-folding redesign that keeps a chosen residue set fixed |
| `rdkit_sa_score` | Ertl synthetic accessibility score with an easy/moderate/hard bucket |
| `structure_bfactor_profile` | Per-residue B-factor mean/max/atom count with flexibility ranking |
| `sequence_complexity` | k-mer Shannon entropy, linguistic complexity and low-complexity windows |

### `esm_if_redesign`

Redesigns selected positions of a protein backbone with the official ESM-IF1
model (`esm_if1_gvp4_t16_142M_UR50.pt`) while keeping the remaining residues as
fixed context. Sampling uses the official `model.sample(partial_seq=...)` API
with `"<mask>"` tokens at the design positions, followed by a teacher-forced
`get_sequence_loss` pass to score each sampled sequence. The output has dims
`[sample, statistic]` with `mean_log_prob`, `designed_recovery` and
`n_designed`; sampled sequences, native sequence and design/fixed positions are
kept in `info`.

The operator runs on CPU because the fair-esm inverse-folding decoder builds
CPU tensors without a device argument.

### `rdkit_sa_score`

Wraps the official RDKit contribution scorer (`Contrib/SA_Score/sascorer.py`,
Ertl 2009). Scores are between 1 and 10; the operator also reports the usual
`easy` (<3), `moderate` (<5), `hard` (<7) and `very hard` buckets in `info`.

### `structure_bfactor_profile`

Aggregates crystallographic B-factors per residue over heavy atoms, sorted from
most to least flexible. Columns are `mean_bfactor`, `max_bfactor` and
`n_atoms`; `info` carries the global mean/median/standard deviation, units and
the most/least flexible residue labels. Solvent residues are excluded by
default (`HOH,WAT`) and can be kept with an empty `exclude_resnames`.

### `sequence_complexity`

Computes k-mer Shannon entropy (k = 1..3), normalized 3-mer entropy,
linguistic complexity (mean observed/possible k-mer ratio) and the fraction of
low-complexity windows. One row per input sequence, seven statistics, with the
window size and entropy threshold configurable.

## Evidence

- `tests/test_extension149.py`: SA scores match `sascorer.calculateScore`
  exactly for ethanol, benzene and aspirin (1.9803, 1.0000, 1.5800).
- `tests/test_extension150.py`: fixed-context masking helpers plus real ESM-IF
  redesign on the 16-residue fixture — designed positions 1-2 vary, positions
  3-16 stay native, scores match a direct forward pass.
- `tests/test_extension151.py`: fixture profile matches recomputed B-factors;
  water exclusion/inclusion, ordering and error paths.
- `tests/test_extension152.py`: hand-computed entropies (homopolymer 0 bits,
  `ACGT` 2 bits, `ACGTACGT` 2-mer 1.9502 bits), linguistic complexity and
  low-complexity windows; parameter and input errors.
- `tests/test_extension153.py`: runner-level contracts for all four operators.

## Limits

- ESM-IF needs a local 1.7 GB checkpoint; the model is CPU-only through the
  official API and design quality depends on the checkpoint.
- `rdkit_sa_score` reproduces the RDKit implementation, not the original
  published fragment table if RDKit changes it.
- B-factor profiles use crystallographic B-factors as provided; they are not
  normalized across structures.
- Complexity metrics are descriptive and do not predict expression or
  aggregation on their own.

## Compatibility

No existing operator or Reader changes schema or IDs. Workflows pinned to
1.27.0 keep their saved parameters; new nodes default to the 1.28.0 library.
