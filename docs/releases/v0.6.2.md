# BioPipe Studio v0.6.2

Start existing desktop workspaces reliably and prepare a Linux execution server
directly from the SSH connection panel. Both Windows distributions include these
changes; the calculation engine, protocol v3 and independent route parameters
remain unchanged.

## Downloads

- **Windows-x64.zip** includes portable Python 3.11 and the tested Windows CPU
  analysis/Reader dependencies. Extract the entire folder and double-click
  `BioPipe Studio.exe`; no Python or Conda installation is needed.
- **Windows-x64-Lite.zip** uses the same desktop application and backend source
  with an existing compatible Python environment.
- The SDK wheel, bundled PLINK 2 native source, verification report and SHA-256
  checksums accompany the desktop archives.

## Desktop startup repair

Older built-in profile registries could stop the backend before the editor opened.
Migration could also reject unfinished canvas drafts whose required run parameters
had not yet been entered. The desktop now upgrades its selected supported profile
once, with recoverable backups, before starting services. Drafts remain editable;
supplied values and execution requirements are still validated. Historical jobs
and their frozen locks are preserved.

Unknown protocols and incompatible external legacy packages still produce an
actionable error instead of a partial migration. The startup screen now includes
the backend's diagnostic rather than only reporting an early exit. See
[migration and recovery](../migration_v2.md).

## Automatic SSH deployment

New server configurations default to **Automatic deployment: BioPipe + Hi-C**.
After SSH authentication and host-key verification, BioPipe uploads a checksummed
application bundle, creates a private Python 3.11 environment, installs BioPipe
and the native Hi-C tools, then verifies the environment before connecting.

- No preselected server Python, global Conda activation or sudo is required.
- The installation directory defaults to the server user's home and can be changed.
- BWA, samtools, pairtools, cooler and cooltools are included in the deployment.
- Same-version connections reuse the installation. Missing or incompatible direct
  and transitive Python dependencies trigger repair; healthy environments are checked
  without reinstalling packages.
- Progress, cancellation and setup errors are available in the connection panel;
  persistent setup logs remain on the server.
- Existing manual connection profiles retain their selected environment.
- Only application code and declarations are uploaded. Input data, analysis outputs,
  independent parameter JSON and execution remain on the server. Existing memory
  planning, file-backed processing and emergency spilling are retained.

Automatic deployment currently supports Linux x86_64 with standard shell/archive
tools, writable storage and outbound HTTPS. The Windows runtime does not contain
Linux binaries. An installer still needs network access and a satisfiable dependency
set; errors remain visible and reconnecting retries preparation. See
[server setup](../REMOTE_EXECUTION.md#prepare-the-server) for requirements and limits.

## Validation

The implementation passed actual Windows double-click startup, real Linux Hi-C
toolchain tests, desktop-submitted remote execution, same-version reconnect and
deliberately removed dependency recovery. See
[automatic deployment validation](../AUTO_DEPLOY_VALIDATION.md) and the release
attachment **VERIFICATION.md** for final package checks.
