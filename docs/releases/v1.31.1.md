# Operon 1.31.1

Backend patch release **1.31.1** (no capabilities added or removed). Registry:
**530 operators, 101 Readers, seven packages, 24 routes**.

## Fix

`proteinmpnn_position_entropy` started the official ProteinMPNN runner through
`python3` when `python_executable` was empty. On Windows that name resolves to
the Microsoft Store alias, so `subprocess.run` failed with
`[WinError 3] The system cannot find the path specified` before the designer
ever ran. The operator now defaults to `sys.executable`, the interpreter that is
executing Operon, which is also the interpreter that has numpy and the rest of
the runtime dependencies on every platform.

## Evidence

- WSL: `tests/test_extension164.py`–`169.py` → 32 passed, including a real
  ProteinMPNN sampling pass on the tiny backbone fixture.
- Windows (<Operon-directory>): `tests/test_extension164.py`–`169.py` → 31 passed,
  2 skipped after the fix; previously `test_extension164.py::test_runner_failures`
  and `tests/test_extension169.py::test_entropy_through_runner` failed with the
  same WinError.
- Windows smoke (`smoke_windows131.py`) exercises PCA, nearest neighbours,
  disulfide bonds, salt bridges and a real ProteinMPNN entropy run.

## Compatibility

No contract, parameter, Reader or workflow change. Existing pins and saved
values keep working; only the default interpreter used to start the external
ProteinMPNN process changed.
