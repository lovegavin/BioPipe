# Operon 1.35.1

Patch release of 2026-11-02. It fixes a Windows-only failure in the new
`rdkit_pharmacophore_features` operator and adds no capability, so the operator
and Reader counts are unchanged (**547 operators**, **101 Readers**).

## Fix

RDKit's C++ feature factory opens `BaseFeatures.fdef` through a narrow-character
path. On Windows profiles whose user directory contains non-ASCII characters
(for example a localized user name), that call fails with
`OSError: File: <profile>\...\BaseFeatures.fdef could not be opened`, even
though Python can read the file. The operator now checks whether the RDKit data
path is ASCII-only; when it is not, it copies the definition file into an
ASCII-safe shared directory (`%ProgramData%\operon\BaseFeatures.fdef`, falling
back to `%PUBLIC%` or the temporary directory) and builds the factory from that
copy. POSIX installations are unaffected because their RDKit paths are already
ASCII and take the direct path.

## Verification

- `tests/test_extension186.py` passes on Linux and on a Windows profile with a
  non-ASCII user directory (previously three tests failed there with the
  `OSError` above).
- Focused regression suite and the packaging group are green.
- The Windows smoke run exercises `rdkit_pharmacophore_features` through the
  runner and returns the expected `(2, 8)` feature matrix.

## Compatibility

No operator or Reader was added, removed or renamed; existing workflows and pins
keep working. This is a PATCH release, so the backend version moves to 1.35.1
while the library stays at the 1.35.0 capability set.
