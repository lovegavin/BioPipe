# BioPipe Studio 0.5.0

This release introduces SDK 3.0 and operator protocol v3, with implementation-free
catalog startup, per-operator parameter schemas, installation-time compilation and
independent workflow parameter values. The numerical kernels and existing disk,
streaming, memory planning and emergency spill capabilities are retained.

The release is built from **`release/v0.5.0`**. The author's subsequent upstream
work remains on `main` for separate integration. This tested catalog includes
**64 operators, 15 Readers, six provider packages and five reusable routes**:
GWAS, RNA-seq DE, Proteomics DE, survival analysis and 16S microbiome.

## Operator and Reader authoring

Each extension owns its Python implementation and a neighboring parameter JSON.
The class's literal `definition` describes identity, ports, resources, dependencies
and optional presentation. Its parameter JSON defines types, defaults, constraints
and form hints. Registry maintenance reads AST/JSON without executing top-level
operator code. Generated indexes are maintained by `biopipe registry check/build`.

The service reads descriptors only. Workers import implementations when needed.
Installation compiles immutable code and dependency directories; metadata-only
refresh reuses code, dependency targets and bytecode. The Full archive also ships
application bytecode compiled by its bundled Python 3.11.

See the [protocol](../operator_protocol.md), [SDK quickstart](../sdk_quickstart.md),
[Step guide](../step_extensions.md) and [Reader guide](../reader_extensions.md).

## Saved values and portable routes

- Saving a route materializes its actual parameter values into an independent,
  versioned JSON file, including Reader arguments and nested-route values.
- Editing an operator's defaults cannot change those saved values. Each job also
  keeps its own `parameters.json` beside `task.yaml` and `plugins.lock.json`.
- Portable `.biopipe.zip` files contain `graph.json` and `parameters.json`. The UI
  and CLI can import them; self-contained graph JSON and inline YAML remain usable.
- Missing or mismatched parameter files produce an error instead of silently
  substituting current defaults.
- Graph pins use execution identity. Compatible declaration-only rebuilds allow
  old routes to open in fresh profiles without historical registry snapshots.
  Bundled index fingerprints are excluded when `code_sha` is present; wheel
  artifact hashes remain strict. Existing job descriptors and locks stay intact.

See [workflow parameter values](../workflow_parameters.md).

## Upgrading existing installations

**Protocol v3 is an explicit migration.** Graph schema 2 and workspace schema 1
are separate and remain unchanged. Close Studio and preview migration on a copy
before applying it. Keep v0.4.1 and the resulting backups until validation finishes.

For the Full Windows package, run from the extracted folder:

```text
runtime\python\python.exe -I -m biopipe migrate
runtime\python\python.exe -I -m biopipe migrate --apply
```

Add `--profile-dir <profile>` to select a non-default profile. The migration keeps
original bytes and leaves historical jobs untouched. Third-party v1/v2 operators
must be converted and rebuilt for SDK 3; see the
[migration guide](../migration_v2.md). Startup does not silently migrate a profile.
The old `legacy/` source remains available in Git tag `v0.4.1` and is no longer
duplicated in the active distribution.

## Downloads

- **BioPipe-Studio-v0.5.0-Windows-x64.zip**: Full package with CPython 3.11, the
  declared built-in CPU dependencies, .NET and the official WebView2 bootstrapper.
  New users extract the complete archive and double-click `BioPipe Studio.exe`.
- **BioPipe-Studio-v0.5.0-Windows-x64-Lite.zip**: desktop host and application for
  users with an existing compatible Python environment and WebView2.
- **biopipe_studio-0.5.0-py3-none-any.whl**: Python/SDK distribution.
- **pgenlib-0.95.1-biopipe-windows-source.tar.gz**: corresponding native extension
  source for the Windows PLINK 2 wheel included in Full.
- **SHA256SUMS.txt** and **VERIFICATION.md**: file checksums and release validation.

Missing WebView2 and new extension dependencies require internet access. Native
platform support and GPU drivers remain separate requirements. Both desktop
variants use the same profile resolver, with no developer-machine paths or user
data bundled in the release.
