# Operon 1.64.0

Fifth real-inference batch. `colabfold_predict` now runs the official ColabFold
pipeline against real AlphaFold-2 parameters, and a wrapper defect exposed by the
real CLI is fixed. The library stays at **654 operators and 101 Readers**.

## Fixed

- `boltz`-style device handling in `colabfold_predict`: ColabFold 1.6.3 has no
  `--device` flag, so every real invocation died with
  `unrecognized arguments: --device cpu`. The wrapper now passes the device only
  through `CUDA_VISIBLE_DEVICES` and forwards `--num-models`, `--num-recycle`
  and `--msa-mode` unchanged. Test 244 asserts the new argv.

## Evidence

- Parameters: official `alphafold_params_2021-07-14.tar`, 3,722,752,000 bytes,
  downloaded from `storage.googleapis.com` with 64 parallel range connections
  (~9.7 MB/s aggregate, 683 s) and extracted to `~/.cache/colabfold/params/`
  with `download_finished.txt`.
- Real `colabfold_batch` on a 118-residue VHH with `--msa-mode single_sequence
  --num-models 1 --num-recycle 1`: 15 s on CPU, `pLDDT=32 pTM=0.252`.
- Real run through `colabfold_predict`: 879 atoms, `[atom, field]` 12 columns,
  **mean pLDDT 31.94**, **pTM 0.210**, **max PAE 29.33**, 18.5 s.
- Registry 654/101/7/24 `errors []`; `pytest tests/test_extension244.py`: 7 passed;
  packaging gate passes.

## Boundaries

- Single-sequence mode only here: MSA generation needs `api.colabfold.com`,
  which is unreachable in this environment. Single-sequence folds are expected to
  be low-confidence (pLDDT ~32); they verify the pipeline, not the biology.
- CPU only; GPU inference is untested.
