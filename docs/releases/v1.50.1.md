# Operon 1.50.1

Release date: 2026-11-02

Patch release for a defect in the new `proteinmpnn_masked_interface_score`
operator.

## Fix

The operator originally launched ProteinMPNN with `--score_only`, which writes a
single scalar score per structure. The per-residue split (interface versus the
rest of the chain) therefore could not be produced and the operator failed on a
real run with "the scorer produced no score_only npz". It now runs with
`--conditional_probs_only`, reads `log_p`/`S` from
`conditional_probs_only/<stem>.npz`, and reports the negative log-likelihood of
each native residue, aggregated over the interface and non-interface partitions.
Residue indices follow the sorted chain order used by the official runner, and
the reported residue count is cross-checked against the structure file.

## Verification

- Real ProteinMPNN run on `tests/fixtures/vhh_1mel.pdb` (chains A/L interface,
  4.5 Å): 42 interface residues, run completes in about 69 s on CPU.
- `tests/test_extension251.py`–`255.py`: **16 passed**; the fake runner now emits
  the official `conditional_probs_only` archive layout.

## Boundaries

`--conditional_probs_only` scores a single sequence; it does not accept design
bias or fixed positions, which only apply to the sampling modes.
