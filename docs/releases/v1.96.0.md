# Operon 1.96.0

One hard capability: **`esm3_embedding`** (685 operators, 101 Readers).
It loads the official EvolutionaryScale ESM-3 open model (`esm3_sm_open_v1`,
1.40 B parameters) from the Hugging Face cache and returns per-residue
embeddings for protein sequences.

## Operator

- Input: a `[sequence, position]` protein Form.
- Parameters: `model_name` (`esm3-sm-open-v1`), `device` (cpu/cuda), `output`.
- Output `[sequence, position, embedding]` (1536 dims for the open model);
  info `model`, `device`, `embedding_dim`, `n_sequences`, `lengths`.
- The model is loaded lazily, cached per (model, device), cast to float32
  (the checkpoint ships bfloat16 and otherwise fails on CPU), and queried
  through the official `ESM3.from_pretrained` + `forward(sequence_tokens=...)`
  API with BOS/EOS tokens stripped.

## Verification

- `tests/test_extension325.py`: 3 passed, 1 skipped by default — BOS/EOS
  stripping on a stub model, operator round trip, device validation, and a real
  gated run (`OPERON_ESM3_REAL=1`) that produced a finite `(1, 14, 1536)`
  tensor in 6.0 s on CPU.
- Weights came from `hf-mirror.com` via `HF_ENDPOINT` (the direct Hugging Face
  host is unreachable here); `docs/large_resources.md` documents the install and
  cache requirements, and `hard_capability_status.md` records ESM-3 as verified.
- Registry check: 685 operators / 101 Readers / 7 packages / 24 routes,
  `errors []`.

## Boundaries

- Only the open 1.4 B model is wired; the larger ESM-3 checkpoints are not
  mirrored and were not tested.
- The package installs from GitHub (`git+https://github.com/evolutionaryscale/esm`)
  and requires torch 2.11 on Python 3.12; that upgrade is recorded in the
  release environment and does not change existing operators (the real
  Antifold/Boltz/OpenFold/ESMFold tests still pass).
