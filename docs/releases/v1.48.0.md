Operon 1.48.0 closes the gap between "Operon can run a model" and "a fresh
machine can get to a first result": it ships a machine-readable large-resource
manifest, a preflight operator that reports exactly what is missing, and the
first structure-prediction loop built on the official ColabFold and ESMFold
implementations.

## New operators

| id | what it does |
| --- | --- |
| `resource_preflight` | Reads `operon/resources.json`, resolves each resource's root (explicit `root` → environment variable → default roots) and emits one row per expected file with presence and size. `strict` stops the workflow with the installation command. |
| `colabfold_predict` | Runs the official `colabfold_batch` on one sequence (FASTA → rank-001 PDB), then reads the ColabFold scores JSON for mean pLDDT, pTM and maximum PAE. |
| `esmfold_predict` | Folds one sequence with the official `esm.pretrained.esmfold_v1()` implementation and returns the predicted PDB with its mean pLDDT. |
| `structure_plddt_profile` | Aggregates the B-factor column of a predicted structure into per-residue mean/min/max pLDDT; reports whether the values are on the 0–1 or 0–100 scale. |
| `structure_pae_summary` | Summarises an N×N PAE matrix into per-residue mean PAE, maximum PAE and the fraction of partners below a confidence threshold. |

## Large-resource manifest

`operon/resources.json` lists eight resources — `proteinmpnn`, `ligandmpnn`,
`esm2`, `esm_if1`, `esmfold`, `colabfold`, `alphafold2`, `rfdiffusion` — with
the override environment variable, the default search roots (WSL and Windows),
the exact expected files, the official URL and a copy-paste installation
command. `scripts/check_resources.py` prints the same information from the
command line, and `docs/large_resources.md` documents the
"download once → verify → run" workflow. No weights or databases are shipped
with the repository.

## Verification

* `tests/test_extension241.py` — manifest integrity, root-resolution order,
  ok/partial/missing states, `require()` remedies, the operator's file table and
  the CLI exit codes.
* `tests/test_extension242.py` — hand-computed per-residue aggregation
  (`A:ALA:1` → 70/60/80 with two atoms), the fraction-scale report, missing
  `bfactor` and empty-form errors, runner round trip.
* `tests/test_extension243.py` — 2×2 PAE matrix with mean 10/25, maximum 15/30
  and threshold fractions 0.5/0.0; non-square, negative and dimension errors.
* `tests/test_extension244.py` — fake `colabfold_batch` executable that writes a
  rank-001 PDB and scores JSON; asserts the captured argv (`--device cpu`,
  `--num-models`, `--num-recycle`), parsed metrics and the failure paths
  (exit code, no output, unknown MSA mode, missing binary).
* `tests/test_extension245.py` — injected ESMFold loader (no 2.5 GB download)
  returning a fixture PDB; checks the pLDDT mean, single-sequence restriction,
  device validation and the missing `fair-esm` message.

Focused run: **32 passed** for the five new modules. Registry after the batch:
**605 operators, 101 Readers, 7 packages, 24 routes, errors []**.

## Boundaries

* `esmfold_predict` and `colabfold_predict` were tested with fake runners and an
  injected loader; a real minimal inference requires the user to install the
  2.5 GB ESMFold checkpoint or the ColabFold databases. Neither resource is
  available on the build host, so no real-weight run is claimed here.
* `alphafold2` and `rfdiffusion` are listed in the manifest for the upcoming
  wrappers; no operator consumes them yet.
* pLDDT/PAE parsing covers the ColabFold `scores_rank_001.json` and PDB
  B-factor conventions; other formats (mmCIF, AlphaFold pickle) need a
  converter first.
