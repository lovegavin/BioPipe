# v5 — single-cell, GC skew, peak-to-gene, annotation analysis

## Scope

- 15 readers, 67 operators, 6 provider packages, 6 routes.
- The annotation operators (`gff_feature_stats`, `gene_structure`,
  `annotation_gaps`) were introduced for GFF3. This release makes
  them work on GTF as well, and adds the `gtf_annotation` route as
  the first end-to-end pipeline that consumes a GTF.

## Patch: GTF annotation route

### Code

- `src/task/step/steps/_annotation_columns.py`: new private helper.
  Resolves a column by role (`seqid`/`seqname`, `type`/`feature`,
  `attributes`/`attribute`) so the same operator body works on Forms
  produced by `GtfReader` and `Gff3Reader`. Parses GTF `key "value"`
  and GFF3 `key=value` attribute syntaxes in one place.
- `src/task/step/steps/gff_feature_stats.py`: uses the helper.
  Before this patch the operator was documented as GFF3/GTF
  compatible but rejected GTF with
  `StepError: 'type' column is not encoded`.
- `src/task/step/steps/gene_structure.py`: uses the helper and
  attributes exon/CDS records through the annotation's own parent
  chain (GTF `gene_id "X"` directly on the exon/CDS row; GFF3
  `Parent=transcript:Y` on the exon/CDS row, `Parent=gene:X` on the
  transcript row). Span containment is kept only as a fallback for
  attribute-less fixtures.
- `src/task/step/steps/annotation_gaps.py`: uses the helper.

### Route

- `routes/gtf_annotation/task.yaml`: `gff_feature_stats` →
  `gene_structure` → `annotation_gaps`, with histograms.

### Demo

- `tasks/gtf_annotation_demo/`: Ensembl release 110
  S. cerevisiae R64-1-1 GTF and GFF3, downloaded from
  `https://ftp.ensembl.org/pub/release-110`.
- `tasks/gtf_annotation_demo/test_gtf_annotation.py`: standalone,
  not pytest. Includes LF/CRLF consistency, a hand-counted
  two-gene fixture, cross-format equality, and negative cases.

### Verification

- `tasks/verify_gtf_annotation.py`: 18 checks. External references
  are SGD chromosome lengths for R64-1-1 and Ensembl release 110
  feature counts. Cross-format comparison uses the same Ensembl
  release dumped twice; CDS totals are compared modulo the Ensembl
  stop-codon convention.
- Existing demos and pytest fixtures pass.

## Honest statement on correctness

Verified:

- Column-role resolution on both GTF and GFF3.
- Parent-chain attribution on the Ensembl 110 S. cerevisiae GTF and
  GFF3: 0 records fell back to span containment.
- Feature-type counts, gene counts, and chromosome set against
  SGD and Ensembl release 110.
- LF/CRLF equivalence of the GTF reader.
- Existing GFF3 demos and the corresponding pytest fixtures still
  pass.

Not verified:

- Plot operators have no numeric contract and are not covered.
- Ensembl GTF excludes the stop codon from CDS, GFF3 includes it.
  CDS totals are checked to differ by a multiple of 3, not to be
  identical. This is upstream Ensembl behavior, not a BioPipe bug.
- GTF collapses ncRNA and pseudogene records into type `gene`;
  GFF3 keeps them as separate feature types. The gene counts of the
  two dumps differ by design.
- `regress` logit branch, `cluster_axis` hierarchical/louvain,
  `reduce` umap/tsne are not covered by the annotation verification.
