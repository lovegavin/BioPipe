## Provisioning engine

- manifest-driven: each resource declares `files`, optional `downloads`,
  `sha256` and `sizes`; the Boltz entry gained mirror download URLs and a
  verified SHA-256 for `ccd.pkl`.
- files are downloaded with resume (HTTP Range), retries with backoff, a read
  timeout, and an atomic `.part` rename; a checksum mismatch deletes the file.
- `--from-dir` copies a validated staging tree instead of re-downloading, which
  is the recommended path for servers with slow uplinks.
- `--plan`, `--offline`, `--json`, `--only`, `--file`, `--jobs`, `--mirror`,
  `--rewrite` cover planning, verification, filtering, parallel download and
  mirror routing; a lock file prevents concurrent provisioning runs.

## Boundaries

- Only resources with `downloads` URLs can be fetched; the rest still require
  the documented manual install command (reported as `missing`).
- Checksums exist only where a file was verified locally, so size is the only
  guard for most GB-scale weights.
- Provisioning is a host-level action; job steps must not download resources.
