# Operon backend 1.14.0

Released 2026-11-01. Backend application version **1.14.0**; authoring protocol
v3; SDK 3.1.0. The factory library now contains **459 operators, 93 Readers,
seven providers and 24 route templates**.

This batch adds discriminant and correspondence analysis, a nestedness metric
and Rényi diversity profiles. No Reader or route is added, and the execution
core is unchanged.

## New capabilities

| Operator | Provider | Category | Behaviour | Reference implementation |
| --- | --- | --- | --- | --- |
| `lda` | `operon-core` | Machine Learning | Fit linear discriminant analysis on labelled samples and report class predictions plus discriminant scores | R `MASS::lda` |
| `corresp` | `operon-core` | Statistics | Simple correspondence analysis of a two-way table: row/column scores, eigenvalues and inertia | R `MASS::corresp` |
| `nestedness` | `operon-core` | Statistics | NODF nestedness of a binary occupancy matrix with ordered rows and columns | R `vegan::nestednodf` |
| `renyi` | `operon-microbiome` | Omics | Rényi generalised entropy profiles over a requested set of alpha orders | R `vegan::renyi` |

All four use the protocol v3 triple: an implementation module, a parameter JSON
schema and an adjacent Markdown page. They require no Reader and no new
dependency; `numpy` is the only runtime dependency.

## Evidence

The batch was validated against the reference implementations, not only against
hand-computed values:

- `lda`: on a 12-sample, two-variable, three-class fixture, the scaling matrix,
  singular values (`11.840689, 6.512048`), prior class probabilities, class
  means and the first four discriminant scores match `MASS::lda`; predictions
  reproduce the R class assignments.
- `corresp`: on the 3×3 table `[[10, 5, 0], [2, 8, 4], [0, 3, 7]]`, row and
  column scores match `MASS::corresp` after sign normalisation (SVD signs are
  arbitrary), and `cor = [0.717565, 0.244841]`, total inertia `0.574847`.
- `nestedness`: a 6×5 occupancy matrix gives `N.columns = 90`, `N.rows = 60`,
  `NODF = 72` and `fill = 0.466667`, identical to `vegan::nestednodf` with
  `order = TRUE, weighted = FALSE`.
- `renyi`: six samples with four taxa at scales `[0, 0.5, 1, 2]` match
  `vegan::renyi`; the `alpha = Inf` branch matches the same reference.

`tests/test_r_oracles95.py` runs the R comparison from an R script against CSV
fixtures and is skipped when `Rscript` is unavailable. `tests/test_extension99.py`
keeps deterministic reference values so the operators stay covered without R.

## Boundaries

- `lda` fits on all labelled samples; it is not a cross-validated classifier.
  It requires at least two classes and rejects variables that are constant
  within groups and perfectly collinear discriminant directions. Reported
  posteriors use the Gaussian plug-in rule.
- `corresp` implements simple correspondence analysis for two-way non-negative
  tables only; empty rows or columns and negative values are rejected.
- `nestedness` treats any positive cell as presence; ordering is `fill`-based
  and deterministic. All-zero matrices are rejected.
- `renyi` reports `NaN` for samples with zero total abundance and records their
  count in `info.zero_samples`; `hill = true` exponentiates the profiles.

## Compatibility

Protocol v3 and SDK 3.1.0 are unchanged. Existing workflows keep their saved
parameter values, and no engine-owned contract changed. The new operators are
opt-in; earlier workflows do not reference them.
