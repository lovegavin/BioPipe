# Operon Studio 2.0.1

This integrated release merges the author's backend 2.0.0 and the layered agent
interfaces into one desktop and headless implementation. SDK 3.1.0 and operator
protocol v3 remain unchanged. The factory library contains 709 operators,
101 Readers, seven providers and 24 route templates.

## Agent and third-party application interfaces

- Start with `operon help` or MCP `operon_guide`, then retrieve a task guide,
  brief search results, selected schemas and individual documentation sections.
  Guides are bundled for offline use and support conditional SHA-256 retrieval.
- MCP and CLI default to five brief search results, schema-focused descriptions,
  compact job receipts and bounded plain-text logs. Full views remain explicit.
  HTTP API defaults remain compatible with existing clients.
- Bounded job waits return the accepted job identity on timeout. They do not
  cancel or resubmit work. Saved workflows, independent parameters, managed
  memory, streaming, emergency spill and host admission remain in the engine.
- The authenticated `/api/v1/openapi.json` and guide endpoints document the API.
  `docs/api_quickstart.md` and `examples/api_client/run_workflow.py` cover workflow
  submission, reconnection, artifact links and explicit native-file handoff.
- The author's paginated artifact tables and canvas replacement/configuration
  capabilities are retained. `operon_open` defaults to replacement in 2.x;
  choose `mode="append"` for a separate tab. Related edits remain one undo entry.

## Integration and packaging fixes

- Remove an accidentally committed `nul` command log that Windows cannot check
  out, while retaining the author's Git history.
- Fix the duplicate frontend icon import and register the File icon.
- Generate extension scaffold dependency bounds for the current application
  major version, instead of the impossible `>=2.0.0,<2` range.
- Include resource/environment manifests and agent guides in installed wheels.
- Replace author-machine resource defaults with portable locations and preserve
  explicit resource overrides.
- Preserve Windows process settings, axis metadata, encoders and missing values
  through dedicated interpreter execution; clean temporary bridge files on
  success and failure. Keep dedicated dependency pins outside the shared runtime.
- Ship resource inspection/provisioning helpers with both desktop variants.
  Clarify that read-only MCP needs `--read-only`, in addition to removing run
  permission.
- Defer optional Torch, RDKit and Biopython imports until operator execution so
  library validation does not eagerly load those stacks. Fix resource download
  resumption when a server ignores HTTP Range, and verify staged file sizes.
- Keep dependency readiness tied to the actual declaration and runtime; a stale
  installer receipt cannot report a changed requirement as passed.
- Declare missing ViennaRNA and PDB2PQR packages so dependency repair can install
  them. Launch the default PDB2PQR command through the selected Python, preserving
  explicit custom executable paths. The independent library bundle requires
  Operon 2.0.1 for its current engine adapters.
- Stop tracking generated `.studio` state. Existing local files remain in place;
  jobs, profile registries and caches are not source or release payloads.

## Verification and availability

Release acceptance covers source/registry checks, frontend tests/build, headless
CLI/MCP/HTTP execution, memory/storage, SSH transfers and desktop lifecycle, plus
the packaged agent harness and real double-click acceptance of Lite and Full.
See the release's `VERIFICATION.md` for actual results and any limitations; this
document is not itself an acceptance receipt.

Full bundles portable Python and tested shared CPU dependencies. Model weights,
GPU drivers, Linux executables and dedicated model environments are not implied
by the word Full. Their readiness is checked separately. Lite uses an existing
compatible Python environment. Both variants include the same application and
operator library.
