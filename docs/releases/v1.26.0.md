# Operon 1.26.0

Release date: 2026-11-02

Application version: `1.26.0`. Protocol version: `3`. Library counts: **508 operators, 101 Readers, seven built-in packages, 24 route templates**.

This expansion adds five capabilities around inverse folding, solubility and substructure analysis, and antibody CDR quality control. All new operators are authored with protocol version 3 (code, adjacent parameter JSON, generated Markdown) and are covered by hand-computed checks plus an authoritative integration oracle.

## Capabilities

| Operator | Category | Description |
| --- | --- | --- |
| `esm_if_mutation_scan` | Machine Learning | ESM-IF1 inverse-folding mutation scan of a protein chain: LLR and log-probabilities for every substitute at the requested positions |
| `rdkit_esol` | Machine Learning | Delaney (ESOL) aqueous solubility estimate from RDKit descriptors |
| `rdkit_smarts_matches` | Machine Learning | SMARTS substructure match counts for a molecule × pattern matrix |
| `interface_hydrophobic_patch` | Machine Learning | Clusters binder-interface residues by CA proximity and reports hydrophobic patches and contact density |
| `antibody_cdr_hydrophobicity` | Machine Learning | CDR hydrophobicity and hydrophobic-moment profile derived from Kabat numbering |

## Operator design notes

### `esm_if_mutation_scan`

- Input: a PDB form with dims `[atom, field]`; `chain` selects the chain to scan (default `A`).
- One teacher-forced inverse-folding pass yields the per-residue 20-amino-acid log-probabilities; each requested position contributes nineteen substitution rows with `llr = mut_log_prob - wt_log_prob`. `mutant_rank` is 1 for the best substitution.
- Output: `[mutation, statistic]` with columns `llr`, `wt_log_prob`, `mut_log_prob`, `mutant_rank`; labels use `wild-type + position + substitute` (for example `C2A`).
- The local ESM-IF1 checkpoint (about 1.7 GB) is supplied through `model_path`; the operator is CPU-only because this fair-esm build samples and scores on CPU.
- The inverse-folding decoder returns logits shaped `(batch, vocabulary, position)`; the operator transposes them before `log_softmax`, which is the layout used by the official `score_sequence` helper.

### `rdkit_esol`

- Implements the Delaney (2004) ESOL regression: `logS = 0.16 - 0.63*cLogP - 0.0062*MW + 0.066*rotatable_bonds - 0.74*aromatic_proportion`.
- Output: `[molecule, statistic]` with the raw descriptors, `esol_log_molar`, and `esol_solubility_mg_l`.
- This is a published regression, not a fitted model; values reproduce the published coefficients exactly.

### `rdkit_smarts_matches`

- Accepts one SMARTS pattern per line (or separated by semicolons) and reports the number of substructure matches per molecule and pattern.
- `unique=true` counts uniquified matches (RDKit `uniquify=True`); `unique=false` counts every embedding. The two differ for symmetric molecules: benzene has 12 non-unique matches for the aromatic pattern.
- Output is a dense molecule × pattern matrix, so it composes with the other table operators.

### `interface_hydrophobic_patch`

- Uses heavy-atom contacts within `cutoff` across the binder and target groups (the same constants as the other interface operators) and clusters interface residues by single-linkage CA distance (`ca_cutoff`, default 10 Å).
- Output: `[patch, statistic]` with `n_residues`, `n_hydrophobic`, `hydrophobic_fraction`, `n_contacts`, `mean_contacts`; patches are ordered by size first, then by the first residue index.
- Hydrophobic residues are configurable through `hydrophobic_resnames`; the default set is the Kyte-Doolittle nonpolar group.

### `antibody_cdr_hydrophobicity`

- Reuses the Kabat CDR boundaries of `antibody_cdr_kabat`, so it inherits the same hybrid numbering limits described in that operator's documentation.
- Per CDR region it reports length, hydrophobic fraction, the longest hydrophobic run, the maximum hydrophobic moment over a `window`-residue scan, and the net charge at pH 7.4.
- The hydrophobic moment uses the Kyte-Doolittle scale and a 100° per-residue rotation (Eisenberg); it is computed as `hypot(sum(h*cos), sum(h*sin)) / window`.
- Output: `[region, statistic]` in the requested region order.

## Limits

- `esm_if_mutation_scan` requires the local ESM-IF1 checkpoint and CPU inference; the 142M-parameter model is slow on large chains and positions above 256 are rejected.
- The mutation scan scores single substitutions only; it does not model combinations, and the score is conditional on the backbone conformation provided.
- `rdkit_esol` is a published linear regression and can be inaccurate outside its training domain; the output is a prediction, not an experimental measurement.
- `rdkit_smarts_matches` uses RDKit SMARTS semantics and heavy atoms only.
- `interface_hydrophobic_patch` treats every non-listed heavy atom as protein, so ligands included in the structure form act as contacts; use `exclude_resnames` to skip them.
- `antibody_cdr_hydrophobicity` inherits the `antibody_cdr_kabat` heuristics and does not perform full IMGT or Kabat HMM numbering.

## Compatibility

- No existing operator or Reader ID changed, moved, or was removed.
- `antibody_cdr_hydrophobicity` imports `kabat_regions` from `antibody_cdr_kabat`; that helper exists in 1.22.0 and later.
- `interface_hydrophobic_patch` reuses `pick_chain_sides` and `contact_stats` from shared modules; no contract change for existing operators.
- `rdkit_esol` and `rdkit_smarts_matches` are new authors that require no new dependency versions beyond `rdkit>=2022.9`, which the library already declares.
- Workflows pinned to earlier releases keep their operator versions; the new capabilities are opt-in.
