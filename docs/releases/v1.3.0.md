# v1.3.0 — Phylogeny-aware diversity

Released 2026-11-01. Backend/application version `1.3.0`; operator protocol v3,
SDK `3.1.0` and the frontend package version are unchanged.

## New capabilities

| Capability | Provider | Kind | Output |
| --- | --- | --- | --- |
| `faith_pd` | `operon-microbiome` | operator | sample × `pd`, `n_taxa_observed`, `n_tips` |
| `unweighted_unifrac` | `operon-microbiome` | operator | sample × sample distance matrix |
| `weighted_unifrac` | `operon-microbiome` | operator | sample × sample distance matrix |
| `patristic_distance` | `operon-core` | operator | tip × tip distance matrix |
| `PhyloXmlReader` | `operon-readers` | Reader | node × `parent`, `branch_length`, `depth`, `is_leaf` |

Trees reach operators as the same node × field table produced by `NewickReader`
and `PhyloXmlReader`. Abundance inputs are sample × taxon count tables; missing
counts are read as zero, negative or non-finite values are rejected, and every
taxon must be a tip of the supplied tree.

## Oracle evidence

The implementation was checked value by value against scikit-bio 0.7.4 and
Biopython 1.88:

- `faith_pd` — sample PD `1.3` and `1.6` on the reference tree, matching
  `skbio.diversity.alpha_diversity("faith_pd")`.
- `unweighted_unifrac` — `0.619048`, matching
  `skbio.diversity.beta_diversity("unweighted_unifrac")`.
- `weighted_unifrac` — `0.85`, matching
  `skbio.diversity.beta_diversity("weighted_unifrac")`; an all-zero sample gives
  `1.0` (unweighted) and `0.9` (weighted), as in scikit-bio.
- `patristic_distance` — identical to `TreeNode.tip_tip_distances()` and to
  `Bio.Phylo` pairwise `tree.distance()` values on the PhyloXML fixture.
- `PhyloXmlReader` — tip order, branch lengths, parent links and pairwise
  distances agree with `Bio.Phylo.read(..., "phyloxml")`.

## Notes and limits

- Weighted UniFrac divides by the original per-sample totals, not by a sum over
  propagated node counts.
- The root may omit its branch length; every other node needs a finite,
  non-negative length.
- `PhyloXmlReader` reads `branch_length` from the clade attribute and falls back
  to a child element. It rejects unnamed tips, more than one `<phylogeny>` and
  phylogenies without a clade.
- UniFrac is not normalized: `weighted_unifrac` returns the raw sum of
  branch-length-weighted abundance differences.
- No protocol, SDK or frontend change is part of this release.
