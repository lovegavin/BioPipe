# Operon Studio 0.116.0

This release brings the unified main branch to the Windows desktop. The shared
workflow, task and artifact services also run without an open Studio window.
Operator authoring remains on protocol v3, with SDK 3.1.0.

## Application and agent interface

- CLI, MCP and the authenticated application API share saved workflows,
  revision checks, task admission, retained artifacts and logs.
- Read, edit and run permissions are separate. MCP execution requires explicit
  run permission. Repeating a submitted request can reuse its receipt instead
  of launching a second computation.
- A connected Studio window exposes its actual selection and accepts visible
  agent edits as a batch that can be undone once. A headless service does not
  fabricate an active canvas or selection.
- Workflow and submitted-job parameter JSON remain independent. Existing
  memory planning, spilling, streaming contracts and remote execution remain.

## Operator library and documentation

The bundled catalog contains 405 operators and 88 Readers, across seven
providers, with 24 route templates. Every descriptor has a Markdown usage
document discoverable on demand. Static metadata discovery does not execute
operator implementations. Desktop archives include these documents and the
task parameter JSON sidecars.

The separately installable library bundle is version 1.1.0. Updating an existing
detached library remains an explicit library operation; an application upgrade
does not overwrite a user's installed library or local edits.

## Specialist-tool handoff

The optional [IGV example](../../examples/igv_handoff/README.md) exports computed
merged intervals into standard BED and bedGraph files, with coordinate and
reference metadata. Clients retrieve the native artifacts through the public
API and open them in IGV. The example includes a relocatable session and a
reproducible synthetic two-chromosome acceptance procedure. IGV remains a
separate application; this is not an embedded browser or automatic viewer button.

## Windows packages

- **Full:** includes a relocatable Python 3.11 runtime and the Windows-compatible
  catalog's declared Python dependencies. No system Python is required.
- **Lite:** the same application, without Python; select an existing supported
  environment or use the documented installation requirements.
- Both variants contain the same frontend, v3 metadata, Markdown guides and
  independent parameter files. No user profile or developer paths are included.
- Linux-native tools, Unix-only Readers and separately managed R runtimes are
  not Windows Python dependencies. Their catalog entries remain available for
  an appropriate execution environment. The runtime manifest records which
  extensions' dependencies were included or excluded.

ExcelReader now declares its openpyxl dependency explicitly. Windows runtime
construction excludes pysam and pyBigWig adapters and Linux execution tools
instead of trying to install them into the Windows interpreter.

Release asset `VERIFICATION.md` records the exact candidate hashes, acceptance
results and any platform-specific limits. The archived previous main source is
retained under the `legacy-main-20261101` release.
