# Operon 1.119.0

This release closes the first four gaps from the agent canvas-loop review.

## Canvas <-> agent

- `operon_open` accepts `document_id` (write into the user's existing tab) and
  `mode="replace"|"append"`; it returns `{document_id, revision}`.
- `operon_apply` accepts `set_graph` for a whole-graph replacement in one
  transaction; `configure` already carried `runtime`, now documented and
  exercised through the new `operon_set_execution` tool
  (`{kind:"local"|"ssh", profile_id?, mode?}`), which re-pins `plugin_lock`
  exactly like the UI does.
- `operon_status` reports connection, scopes, workspace, instance and canvas
  sessions; the MCP client re-handshakes once on a capability 403 instead of
  failing every later call.

## Structure correctness

- `PdbReader` gained `records` (`all|atom|hetatm`) and `exclude_solvent`; the
  Form info reports `records`, `exclude_solvent` and `n_excluded_solvent`.
- `structure_interface_core` is **polymer-only by default**: water, ions and
  ligands are excluded and counted in `n_nonpolymer`; pass
  `include_nonpolymer=true` for a ligand-only complex. On 1MEL this changes the
  interface from the silently-wrong 99 (58 core / 41 rim) to **88**
  (52 core / 36 rim), matching the pure-protein reference.
- Its export now carries `n_rim`, `sides`, `core_by_side`, `rim_by_side`,
  `chain_counts`, `n_nonpolymer` and the residue label list;
  `sequence_liability_scan` exports the site table (position, kind, residue,
  motif, context, severity).

## Paths

- Canvas validation now resolves files through the configured `input_roots`, so
  a path that executes is also a path the canvas accepts.

## Verification

- `pytest tests/test_agent_canvas_loop.py tests/test_studio.py`: 17 passed.
- Reader suites (`conformance`, `selection`, `new_readers`): 10 passed.
- Transport/headless/protocol/reference: 9 + 51 passed.
- Registry: 709 operators / 101 Readers / 0 errors.

## Still open

- Remote artifact table/preview (`operon_artifacts` on an ssh job) and
