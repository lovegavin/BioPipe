# Operon 1.118.2

Patch release from the managed-install verification and the remote-connection
documentation pass.

## Registry routes in installed layouts

`python -m operon registry check` resolved routes at `site-packages/routes`
once Operon was pip-installed, so the managed environment reported
`Route directory does not exist`. `operon.registry.default_route_roots()` now
resolves, in order: `OPERON_ROUTES`, `<root>/routes`, the source tree paired
with this environment (`env-<digest>` → `code-<digest>/routes`), and
`<sys.prefix>/routes`; the last resort is the newest `code-*/routes` directory,
never a union (merging every code dir produced 24 `Duplicate route ID` errors).
`tests/test_registry_layout.py` covers the pairing, the fallback and the
override.

Verified inside the managed server environment: `registry check --json` from
`/tmp` without `--route-root` prints
`COUNTS 709 101 7 24 errors 0`.

## MCP run permission by default

The MCP configuration shown in Studio and the bootstrap `agent_config` now
launch `operon ... mcp --allow-run`, so analysis submission works without a
manual flag. The panel note states that removing the flag restores read-only
mode; no server-side permission changes.

## Remote connection field reference

`docs/quickstart_full_flow.md` section 6 now documents every field of the
server form — name, host, port, username, environment (managed/existing),
managed root, Operon directory, Python, run directory, authentication mode,
password, key path, passphrase, SSH gateway mode and menu index — with required
conditions, defaults, absolute-path validation, and the first-connect flow
(fingerprint, source upload, micromamba environment, `operon-ready.json`).
