# Operon 2.2.2

## Fixed

- Runtime state was committed by mistake: `.studio/` (936 files, ~28 MB,
  including job outputs, plugin locks and agent session data) was tracked since
  the 2.2.0 tree. It is removed from the repository and disk, ignored going
  forward, and `tests/test_repository_hygiene.py` fails if runtime state, build
  output, logs, keys or credentials are ever tracked again.
- `frontend/src/icons.tsx` imported `File` twice, which `tsc` rejects with
  `TS2300: Duplicate identifier 'File'`. The duplicate import is removed.

## Security

Git history still contains the removed `.studio/` tree in every commit from
2.2.0 up to this release, including any token that was written into it. Treat
any token that appeared there as compromised: revoke and reissue it. Rewriting
history (`git filter-repo --path .studio --invert-paths`), force-pushing and
re-tagging removes the objects from the remote, and should be followed by
re-cloning or `git reset --hard origin/main` in every existing checkout.

Existing Windows clones recover with:

```
git fetch --all --tags
git reset --hard origin/main
Remove-Item -LiteralPath .\.studio -Recurse -Force
```
