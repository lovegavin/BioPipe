# Operon 1.117.2

Patch release that makes the managed Linux install independent of conda-only
packages and of a preinstalled compiler.

## Problem

- `pdbfixer` has no PyPI release, so pip aborted with
  `No matching distribution found for pdbfixer`.
- `libcst` fell back to a Rust sdist and `pyarrow` to an Arrow C++ source build;
  both failed with `Failed building wheel`.
- Creating the micromamba environment with `gxx_linux-64` pulled a large
  toolchain and was slow on shared filesystems even when every wheel existed.

## Change

- A pure-Python `pdbfixer` wheel ships inside the source tree at
  `operon/bundled/pdbfixer-1.12.0-py3-none-any.whl`; the installer passes
  `--find-links operon/bundled` so pip resolves it locally. `openmm` comes from
  the PyPI wheel.
- The micromamba environment now holds only `python=3.11`, `pip`, `bwa` and
  `samtools`; a marker file records the package set and older environments are
  repaired on the next install.
- Wheel-first pip installs keep the `pyarrow<22`/`libcst<1.8` constraints.
  Compilers (`gxx_linux-64`, `cmake`, `make`) are added only when the source
  fallback actually runs, and `packaging` is bootstrapped when missing.

## Verification

- Fresh environment: `pdbfixer 1.12.0`, `openmm 8.6.1`, `pyarrow 21.0.0`,
  `libcst 1.7.0`, `pip check` clean, no compiler installed.
- cp311 wheels confirmed for `pyarrow 20.0.0`, `libcst 1.7.0`, `openmm 8.1.1`.
- `tests/test_remote_provision.py tests/test_remote_installation.py
  tests/test_remote_handshake.py`: 47 passed.

## Boundaries

- The bundled `pdbfixer` wheel is unmodified third-party code (MIT, OpenMM) and
  exists only to make the managed install hermetic. Rebuild it with
  `python -m pip wheel --no-deps -w /tmp/wheel pdbfixer`.
