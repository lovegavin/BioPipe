# Operon 1.118.8

Patch fixing the managed-install bootstrap on real servers.

## Finding

A clean install from Studio failed immediately after micromamba started:

```
critical libmamba Error parsing version "3.11 pip bwa=0.7.19 samtools".
Version contains invalid characters in 3.11 pip bwa=0.7.19 samtools.
```

`provision.py` passed the whole `CONDA_PACKAGES` string through `shlex.quote`,
so micromamba received one argument and tried to parse the entire spec list as a
single version.

## Change

- `CONDA_SPECS` expands the package list into separate shell-safe tokens, and
  the bootstrap command uses it for `--strict-channel-priority`.
- Regression test asserts the generated line is
  `--strict-channel-priority python=3.11 pip bwa=0.7.19 samtools=1.22.1`
  (separate arguments, never one quoted blob).

## Verification

- Reproduced on the target server before the fix, then ran the corrected
  command directly with the managed micromamba 2.10.0:
  `micromamba create -y -p ~/bp_check/env-specs ... python=3.11 pip bwa=0.7.19 samtools=1.22.1`
  → `RC=0`, `bin/bwa` and `bin/samtools` present.
- `pytest tests/test_remote_provision.py tests/test_remote_installation.py`:
  29 passed.
