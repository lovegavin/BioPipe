# Operon 1.35.2

Patch release of 2026-11-02. It fixes two follow-ups to the 1.35 line and adds
no capability, so the counts stay at **547 operators** and **101 Readers**.

## Fixes

1. **Pharmacophore oracle on non-ASCII Windows paths.** The 1.35.1 release made
   the operator copy RDKit's `BaseFeatures.fdef` into an ASCII-safe directory,
   but the test suite still built its independent oracle straight from the
   RDKit data directory. On Windows profiles whose path contains non-ASCII
   characters that oracle failed with `OSError: ... could not be opened`. The
   test now resolves the definition file through the same helper
   (`_feature_file()`), so the comparison runs on every platform.
2. **Multi-chain ProteinMPNN FASTA in `proteinmpnn_native_recovery_scan`.** The
   official runner joins chain sequences with `/` in both the native and the
   generated records. The scan treated that separator as a residue and raised
   `design contains the non-standard residue '/'`. Records are now normalised by
   removing the separator, so multi-chain designs are concatenated in structure
   order and align with the native residue numbering.

## Verification
