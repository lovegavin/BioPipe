# BioPipe Studio v0.8.1

This release separates server connection from software installation, adds direct
result access from run history, and saves publication figures as ordinary output
files. Both Lite and bundled-environment Windows packages contain these changes.

## Downloads

- **BioPipe-Studio-v0.8.1-Windows-x64.zip**: Python 3.11, SSH support and the tested
  built-in Windows CPU analysis/Reader dependencies are included. Extract the
  whole archive and double-click `BioPipe Studio.exe`. No Python setup is needed.
- **BioPipe-Studio-v0.8.1-Windows-x64-Lite.zip**: the same editor and application
  code, using an existing compatible Python environment.
- The wheel supports source/SDK installation. The pgenlib source archive retains
  the corresponding Windows native-library source. `SHA256SUMS.txt` and
  `VERIFICATION.md` accompany the packages.

WebView2's official bootstrapper needs internet access if that Windows component
is missing. Linux Hi-C executables remain on the Linux execution host.

## Connect once, reuse an installed server

Ordinary SSH connection negotiates protocol capabilities and reads the server's
installation, operator registry and dependency-readiness documents. It does not
upload desktop code, recursively scan operators or resolve dependencies on every
connection. Multiple compatible desktop clients reuse the same installation and
server-owned jobs. Application versions need not be identical when their declared
interfaces and requested operator implementations are compatible.

**Server maintenance → Install / upgrade server** explicitly prepares or updates
the application and private environment. **Refresh operators and dependencies**
is a separate operation; it checks entries without a valid passed receipt. Passed
receipts remain reusable across compatible reconnects, with documented invalidation
and forced-verification controls. Background maintenance leaves task/status/log
requests responsive. Existing manual environment configurations remain supported.

Older servers need a one-time explicit upgrade to support the handshake; an
incompatible live daemon is not silently replaced. Finish running work before an
intentional daemon upgrade. See [server handshake](../SERVER_HANDSHAKE.md).

## Open previous results without replacing the canvas

Each history row separates **View results**, **View logs** and **Load canvas**.
Local, coordinated and recovered SSH jobs share bounded previews, step reports,
figures and retained output files. Failed runs can retain their partial outputs.
Connection/preview failures offer an actionable error and retry; rapid selection
changes cannot replace a newer selection with an older response.

Server previews are sampled remotely. Opening a complete output fetches only that
file into a verified resumable cache; inputs and unrelated outputs stay on the
server. Reconnect the server to access its archived results.

## Automatically saved publication figures

All 14 built-in plotting operators save a white-background PNG at 300 DPI plus
PDF and SVG during execution. **Saved figures** provides links that open these
existing originals directly. Studio's sampled interactive preview remains separate.

Figures use dark readable labels, thin axes and consistent typography. PDF embeds
TrueType fonts; SVG retains editable text. Axes/text stay vector while dense
artists can be rasterized at the selected DPI. Physical width/height, base font
size and DPI are ordinary parameters in each operator's separate JSON schema and
are frozen with a saved route. Size/resolution controls are collapsed under advanced
parameters. Choose final dimensions and resolution for the target journal.

Repeated filenames do not overwrite previous figures. Step/run records retain
format and size metadata, and links follow a moved complete workspace. Historical
runs retain their original files and styles; rerun a route for the new formats.
Third-party plotting operators remain responsible for their own styling.
See [publication figures](../PUBLICATION_FIGURES.md).

## Compatibility, validation and branch policy

Protocol v3 / SDK 3, stable operator IDs, independent parameter/execution JSON,
streaming, planned storage, emergency spill and per-host resource admission remain.
The catalog still contains 67 operators, 19 Readers, seven provider packages and
eight route templates. No separate upstream operator changes are merged here.

The handshake implementation passed real Linux reuse/reconnection acceptance;
details and scope are recorded in [server validation](../SERVER_HANDSHAKE_VALIDATION.md).
Final package, regression and Windows double-click evidence is in the release
attachment **VERIFICATION.md**. Skipped native/Linux cases are reported separately.
