# Operon 1.59.3

Patch that promotes `foldseek_search` from fake-runner verification to a
**real run**. Foldseek 10-941cd33 (linux-avx2 static binary) was installed under
`~/tools/foldseek`, a small database was built with `foldseek createdb`
from two fixtures, and `foldseek_search` returned 5 hits for 1MEL with
`alntmscore 1.008` on the top self-hit. Counts stay at **653 operators and 101
Readers**.

## Fixed

- `--max-hits` is not an easy-search option (Foldseek rejects it: "Unrecognized
  parameter"); the operator now truncates parsed hits in Python instead.
- `tests/test_extension293.py` gains a real-run test that activates when
  `OPERON_FOLDSEEK_BIN` and `OPERON_FOLDSEEK_DB` are set, and skips otherwise.

## Added

- `docs/large_resources.md` documents the Foldseek binary download, `createdb`
  invocation and the environment variables for the real test.

## Verification

- Real run: `foldseek_search` on `tests/fixtures/vhh_1mel.pdb` against a local
  DB built from `vhh_1mel.pdb` + `backbone_1bc8_c60_75.pdb` → shape (5, 6),
  top targets `vhh_1mel_L`, `vhh_1mel_M`, `vhh_1mel_A`.
- `pytest tests/test_extension292.py`–`293.py`: 8 passed with the real assets
  configured (7 passed + skip elsewhere).
- Registry: 653 operators / 101 Readers, `errors []`; Windows verification runs
  the same modules with the real-run test skipped.

## Boundaries

- Boltz-2 remains fake-runner verified; its weights were not downloaded here.
- The documented Foldseek database is a demo built from fixtures, not PDB100.
