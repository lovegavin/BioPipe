# Operon Studio 2.5.0 - Unified Windows Setup

Download **Operon_Setup.exe**, run it, and launch Operon from its shortcut.
The installer includes its own Python environment. Users no longer need to choose
between Lite and Full or prepare a separate Python/Conda environment.

## Installation and isolation

- Each installation or reinstallation receives a fresh application directory and
  an independent profile. Old profiles, workflows and analysis files are retained
  for explicit import; old plugin registries are not attached automatically.
- The application always uses its bundled interpreter. Startup and shutdown do
  not rewrite the shared `~/.operon/runtime.json` used by other installations.
- Setup validates payload hashes and the runtime before activating the new copy.
  It registers Windows uninstall support and creates application shortcuts.
- Uninstall refuses while that installation is running. It removes manifest-owned
  files and preserves profiles and changed or unexpected files.

## Reliability and identity

- Fixed an installation stall caused by repeated temporary-file attempts after a
  Windows permission denial. Runtime inspection now returns its report to the
  installer; the installer saves it. JSON write failures return promptly while
  preserving the previous file.
- Inspection progress is logged as it happens; stalled inspections record stacks.
- A locked desktop log falls back to a process-specific log without disrupting
  startup or shutdown.
- A consistent DNA icon now identifies the application, installer, shortcuts,
  Windows uninstall entry and browser favicon. Editable SVG and multi-size ICO
  assets are included in the source tree.

## Library and compatibility

The application and operator library remain independently versioned and released.
This release retains the previously tested reference library 2026.11.5.2; it does
not silently substitute a newer library from `main`. Library updates can be
installed independently. SDK v3, frozen workflow parameter JSON, managed memory,
streaming, SSH execution, CLI, MCP and artifact/viewer interfaces are preserved.

Core Python dependencies are bundled. Optional operator dependencies, external
tools, model weights and first-time WebView2 installation can still require
internet access. This release does not claim every optional operator has been
tested or that third-party applications are bundled.

## Acceptance and known limits

The rc3 candidate passed independent-PC interactive installation, shortcut reopen,
reinstallation, Agent six-stage checks and Windows uninstall. Both inspections
returned `inspect: ready`; the shared runtime hint stayed byte-for-byte unchanged.
The retained profile's 107 checked files matched the baseline. That run did not
inject a permission error; permission-failure regression was verified separately
on the development machine with a live reproduction and regression tests.

The icon build retains the rc3 execution and isolation changes. Final artifact
checks and checksums are recorded with the release. The test PC reported 168
compiled cache files remaining after uninstall; these were retained by conservative
cleanup, and no claim of complete removal of generated caches is made.

See [Windows Setup](../windows_setup.md) for log locations, installation ownership,
build commands and the distinction between managed installations and portable ZIPs.
