# BioPipe Studio v0.7.1

Workflows can now use local inputs on an SSH server without manually copying
datasets. Automatic or manual placement, resumable file transfers and a concurrent
task manager are included in both Windows desktop packages.

## Downloads

- **Windows x64** includes Python 3.11 and the tested Windows CPU analysis/Reader
  dependencies. Extract the complete ZIP and double-click `BioPipe Studio.exe`.
- **Windows x64 Lite** includes the same application and frontend, using an existing
  compatible Python environment. It does not bundle Python or analysis dependencies.
- The Python wheel, native dependency source, checksums and final **VERIFICATION.md**
  accompany the two desktop archives.

Keep the adjacent folders with the EXE. A missing WebView2 runtime can be installed
by the full package's official Microsoft bootstrapper; that step needs internet.
Linux-only Hi-C tools run on the Linux server, not inside Windows Python.

## Input uploads and stage handoff

Local inputs, declared Reader companions and reference-path parameters are staged
automatically. Uploads use bounded chunks, checksums, persisted receipts and atomic
publication. Reconnecting can resume a verified prefix; completed content can be
reused across runs. Progress and failures are visible in the task panel and logs.

Mixed workflows support local-to-SSH and SSH-to-local stage boundaries, preserving
Form metadata, axis metadata, file-backed artifacts and existing streaming/spill
capabilities. The handoff format uses JSON and NumPy payloads, not remote pickle.

## Per-workflow execution settings

Execution settings now offer **Automatic** and **Manual** placement. Automatic mode
uses compatible dependencies, file locality, transfer estimates and queue pressure.
Manual mode enables per-node environment choices in the right-click menu; those
choices are disabled in automatic mode. A route operator always runs its internal
graph in one environment.

Each saved workflow has its own versioned `execution.json`, alongside independent
`parameters.json`. Editing another document or changing defaults does not change a
submitted task's frozen settings. Existing two-file bundles remain importable.

## Concurrent tasks and resource accounting

The task manager supports concurrent submissions, resource queues, per-task stop,
upload progress, scientific-step progress and logs. Windows and Linux each retain
their own startup memory snapshot and shared per-user host admission pool. Jobs
reserve memory and CPU capacity before starting. Existing planned disk writes,
streaming and emergency spill remain active within each scientific worker.

Remote jobs continue through SSH disconnection. Reconnection recovers logs and
uses stable submission identities to avoid duplicate scientific jobs. Internal
stage jobs remain grouped under their parent task after reconnecting. Inspector
forms put methods and required analysis parameters first, with tool and resource
settings in collapsed groups.

## Compatibility and limits

- SDK 3 / operator protocol v3 and existing operator IDs are retained.
- Automatic placement uses a bounded heuristic, not an exhaustive optimum.
- Resumption covers verified transfers and completed stages. A terminated
  scientific tool is not checkpointed inside its calculation.
- Cancellation while disconnected remains pending until the server acknowledges it.
- Admission coordinates BioPipe processes for the same OS user, not unrelated
  software, other users or a GPU cluster. Sustained excess worker memory may stop
  the affected task if emergency spill cannot recover.
- Transfer caches are retained for reuse; automatic eviction is not included.
- Existing manually configured servers need matching application code. Managed
  deployment prepares the matching version when reconnecting.

See [execution environments](../EXECUTION_ENVIRONMENTS.md) and
[SSH deployment](../REMOTE_EXECUTION.md) for usage and recovery details.

## Validation and publication

Real Windows double-click startup and Linux acceptance covered paired FASTQ,
all five Hi-C structure methods, local plotting after remote analysis, SSH
disconnect/reconnect and parallel task admission. Final archive checks and test
counts are recorded in the release attachment **VERIFICATION.md**.
