# Operon 1.120.1

## Fixed

- `operon.client.Client.request` re-discovers the live Studio bridge and
  re-authenticates when a request returns 403. Studio restarts publish a new
  discovery record (instance id, secret and in-memory connection table), so the
  MCP server's old token and old secret both become invalid while the stdio
  transport stays open. Previously every call then failed with
  `Agent connection requires 'context' capability`; now the client reloads the
  discovery file, rebuilds its HTTP client, mints a token and retries once.

## Documentation

- `docs/agent_bootstrap.md` notes that `operon_status` exists from Operon
  1.119; older servers expose `operon_sessions` and `operon_context` instead.

Backend version: 1.120.1 (operators 709, Readers 101).
