# Operon 3.0.2 — explicit format contracts (SDK 3.7)

## Downloads

- **Windows:** `Operon_Setup.exe` includes the lightweight management runtime.
- **Linux server:** `Operon-3.0.2-Server.zip` includes command-line installation and the application wheel.
- **Protocol for developers:** `Operon-Protocol-3.7.zip` contains schemas, guides and authoring instructions.
- Verify downloads against `SHA256SUMS.txt`.

## What changes

- New `protocol_revision: "3.7"` declarations require explicit input and output format arrays, including empty arrays for absent ports. The base protocol remains version 3.
- Registration, graph preparation and execution validate format declarations. Form, file artifacts and scientific logical types are not interchangeable.
- Existing Form readers retain their normal path. An explicitly annotated native NumPy array can be wrapped as a Form without copying its payload; dimensions, labels, info and axis metadata are required. This does not blindly decode arbitrary files or reinterpret a matrix as a list.
- `operon registry formats PATH` inspects legacy declarations without importing analysis code. `--apply` applies determinate proposals with backups and rollback protection; ambiguous cases remain listed for review.
- New SDK scaffolds include the 3.7 declarations. Parameters remain in separate JSON files; saved workflow values are not replaced by current defaults.

## Compatibility and maintenance

Existing v3, v3.5 and v3.6 declarations remain supported. Historical locks are not rewritten by the read-only compatibility projection. The tested factory library is unchanged; this is an application/protocol release, not an operator-library update.

New 3.7 operators require Operon 3.0.2 on the actual execution host, including a remote Linux server. Updating only the desktop does not upgrade an older server.

Application maintenance continues on the existing `fix/3.0.1-installation` branch; library development remains independent on `library/main`. `main` is retained but is not a maintenance/merge target for this release.

Validation evidence and limitations are supplied in `VERIFICATION.md`. Build success is not a claim that every scientific operator or a fresh test-machine GUI installation has been verified.
