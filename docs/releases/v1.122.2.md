# Operon 1.122.2

## Verified

- ESM-3 generation was executed **through the multi-environment bridge** with the
  real `esm3_sm_open_v1` weights: prompt `MKTAYIAKQR________`, two steps,
  result `MKTAYIAKQRLLLIALTL` (18 residues). The host interpreter never imports
  the model; the proxy serializes the input Form, runs `env_worker` in the
  declared interpreter and rebuilds the output Form.

## Documented

- The ESM-3 environment recipe is Python 3.12 + `torch>=2.11` +
  `transformers<5` + ESM from GitHub. Hosts with glibc < 2.28 (the CentOS-7
  class server `licai-srv-node80` is 2.17) cannot install those wheels —
  `pip` rejects the `manylinux_2_28` build as unsupported and conda-forge has no
  matching CPU build. `docs/design/hard_capability_status.md` records this ABI
  limit; ESM-3 runs on a modern host, and the bridge makes that transparent to
  workflows.
- The managed installer's `NameError: prefix` crash from v1.121.4 is fixed in
  v1.122.1 (`Path(sys.prefix)`), so fresh installs can create the dedicated
  environments again.

Backend version: 1.122.2 (operators 709, Readers 101).
