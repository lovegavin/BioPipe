# Operon backend 1.20.0

Backend release on the 1.x line. SDK remains 3.1.0, the operator protocol
remains v3 and the library grows to **479 operators / 100 Readers**, seven
providers and 24 route templates. This is an additive expansion: no operator
or Reader was renamed, removed or re-versioned.

## New capabilities

| Capability | Kind | Provider | Reference implementation |
| --- | --- | --- | --- |
| `rdkit_descriptors` | operator | `operon-core` | RDKit `Descriptors`, `Crippen`, `Lipinski`, `rdMolDescriptors` |
| `rdkit_morgan_fingerprint` | operator | `operon-core` | RDKit `GetMorganFingerprintAsBitVect` |
| `smiles_standardize` | operator | `operon-core` | RDKit `MolStandardize.LargestFragmentChooser` / `Uncharger` |
| `esm_embedding` | operator | `operon-core` | fair-esm `ESM2` checkpoints |
| `interface_bsa` | operator | `operon-core` | Shrake-Rupley SASA (in-house implementation) |

The registry counts move from 474 operators / 100 Readers to **479 operators /
100 Readers**. No Reader is added in this release.

### `rdkit_descriptors`

Reads a multiline `SMILES [name]` list and writes a `[molecule, descriptor]`
Form with twelve descriptors in a fixed column order: molecular weight, Crippen
logP, molar refractivity, TPSA, hydrogen-bond donors and acceptors, rotatable
bonds, ring and aromatic-ring counts, heavy atoms, heteroatoms and fraction sp3.
Names default to `mol1`, `mol2`, ... and are made unique; blank lines and `#`
comments are ignored. Output values are float32 and non-finite descriptors are
rejected.

### `rdkit_morgan_fingerprint`

Builds a Morgan bit vector (`radius`, `n_bits`, optional `use_features`) and
writes a `[molecule, bit]` Form of 0/1 values with `"0" ... "n_bits-1"` column
labels. `info.on_bits` records the number of set bits per molecule so the
fingerprint can be inspected without a second operator.

### `smiles_standardize`

Canonicalizes SMILES strings, optionally keeps only the largest fragment
(salts, counterions and solvent are dropped) and optionally neutralizes charges
with RDKit's `Uncharger`. The output is a `[molecule, statistic]` Form with atom
count, heavy-atom count, fragment count and ring count; the canonical strings
and per-molecule change flags live in `info.canonical_smiles` and
`info.changed`.

### `esm_embedding`

Loads a local ESM2 checkpoint through `fair-esm` and returns the mean-pooled
final-layer embedding of every sequence in a FASTA-derived sequence Form.
Sequences are decoded with the shared `sequence_codes` representation, so the
input must come from `FastaReader` (protein alphabet) or an operator that keeps
`info.alphabet_map` intact. Parameters cover `model_path`, `device`
(`cpu`/`cuda`) and the sequence/position dimension names; the output Form is
`[sequence, embedding]` with one row per input sequence.

fair-esm 2.0.0 calls `torch.load` without `weights_only`; torch 2.6 changed the
default and rejects the checkpoint's `argparse.Namespace`. The operator first
tries the official loader and, only when the error is that specific
`weights_only` rejection, re-reads the trusted local checkpoint with
`weights_only=False` and hands it to the same official model builder.

### `interface_bsa`

Computes solvent-accessible surface area with the Shrake-Rupley algorithm for
two chain groups alone and in complex, then reports the buried area of every
interface residue as a `[residue, statistic]` Form (`buried_area`,
`complex_area`), sorted by buried area. Residues are labelled
`chain:resname:number`; `info` carries the total, binder and target buried
areas, the chain groups, probe radius and sample count. Parameters cover the
chain groups (`binder_chains`, `target_chains`; either may be derived from the
other), `probe_radius`, `n_points`, `min_buried` and `exclude_resnames`.

Water is excluded by default and hydrogens are ignored. The implementation is
in-house because Operon cannot depend on a compiled SASA library: atom radii
are the Bondi set, points are a deterministic golden-spiral set and the
implementation uses a KD-tree neighbour search with an O(N^2) brute-force fallback
covered by tests.

## Evidence

- `tests/test_extension114.py` (8 tests) checks the twelve descriptors against
  hand-computed values for ethanol, benzene and aspirin (molecular weight
  from the RDKit atomic weights, donor/acceptor/ring/rotatable counts), the
  Morgan bit vector against RDKit's own `GetMorganFingerprintAsBitVect`, and
  the standardization output against RDKit's largest-fragment and uncharger
  behaviour. Error paths cover empty SMILES lists, unparsable SMILES, and
  out-of-range radius/bit counts.
- `tests/test_extension115.py` (4 tests, one gated) verifies the embedding
  arithmetic against a deterministic stub model, checks determinism and the
  error paths, and — when `OPERON_ESM_CHECKPOINT` points at
  `esm2_t6_8M_UR50D.pt` — runs the real checkpoint and asserts the documented
  320-dimensional output for a 10-residue sequence.
- `tests/test_extension116.py` (6 tests) validates the SASA core against the
  analytic value of an isolated atom (`4*pi*(r+probe)^2`), the analytic cap of
  two overlapping spheres, and the full interface output against an independent
  O(N^2) brute-force reference on a four-atom two-chain fixture. Error paths
  cover invalid probe radius and point count, single-chain inputs, missing or
  overlapping chains, fully hydrogen structures, and a Form without structural
  columns.
- Batch suite (`tests/test_extension110.py` through `tests/test_extension116.py`
  plus `test_extension8.py`, `test_protocol_v2.py` and `test_reference_docs.py`)
  runs 64 passed / 3 skipped. The real ESM checkpoint test is additionally gated
  on `OPERON_ESM_CHECKPOINT`.

## Limits

- `esm_embedding` needs a local checkpoint; no weights are downloaded
  automatically. GB-scale checkpoints are expected to be exercised minimally.
- `esm_embedding` mean-pools the final layer; per-residue embeddings and
  attention maps are out of scope.
- `interface_bsa` uses fixed Bondi radii and a deterministic point set, so
  absolute areas differ slightly from Freesasa/Biopython defaults; relative
  comparisons and interface ranking are the intended use.
- `rdkit_descriptors` reports only the twelve documented descriptors; other
  RDKit descriptor sets are future work.

## Compatibility

Existing workflows, frozen parameter values and saved routes are unaffected.
The five operators are new IDs; no Reader was modified and no protocol schema
moved. The generated operator index and builtin package snapshot are rebuilt
from the source declarations, and the packaged library stays pinned to the
1.20.0 execution identity.
