# Upstream v3

Third version of the BioPipe engine. Extends the five classical analysis paths of v2 with a complete GO enrichment pipeline, and fills in the foundational operators for generic tabular input, key-value lookup, multi-value expansion, long-to-wide reshaping, and top-N ranking.

The core change in this version is moving format knowledge from user preprocessing back into Readers: real GAF, GWAS Catalog, ClinVar and similar formats are read directly by dedicated Readers, no more `awk`/`sed` column splitting.

## Scope

- 2 new Readers (`GafReader`, `TsvReader`).
- 1 Reader change (`CsvReader` gains `columns`, `info_columns`).
- 1 Reader change (`TxtReader` drops `.tsv`).
- 7 new Steps: `annotate`, `prioritize`, `order_axis`, `explode`, `pivot`, `enrich_go`, `enrichment_plot`.
- 3 Step contract fixes: `annotate`, `prioritize`, `order_axis`.
- 1 end-to-end pipeline: GO enrichment.
- 1 demo task: `tasks/go_enrichment_demo`.

## Reader changes

### New: GafReader

Handles `.gaf` (GO Annotation File). The standard GO Consortium annotation format: tab-separated, 17 fixed columns, comment lines starting with `!`. Compressed `.gaf.gz` is read directly without framework decompression.

The column layout is fixed; no parameters let the user pretend it is some other format.

| # | Column | Meaning |
|---|---|---|
| 1 | db | source database |
| 2 | db_object_id | database-specific identifier |
| 3 | db_object_symbol | gene symbol |
| 4 | qualifier | NOT / contributes_to / ... |
| 5 | go_id | GO term identifier |
| 6 | db_reference | reference |
| 7 | evidence_code | EXP / IDA / ... |
| 8 | with_from | supporting identifiers |
| 9 | aspect | P / F / C |
| 10 | db_object_name | full name |
| 11 | db_object_synonym | pipe-separated synonyms |
| 12 | db_object_type | protein / gene / ... |
| 13 | taxon | NCBI taxonomy id |
| 14 | date | annotation date |
| 15 | assigned_by | assigning group |
| 16 | annotation_extension | structured extension |
| 17 | gene_product_form_id | isoform identifier |

`db_object_synonym` is a multi-valued column. It is read verbatim into `info["db_object_synonym"]`, declared in `axis_info`, and removed from `data`. The downstream `explode` operator splits it on `|`.

```yaml
sources:
  gaf:
    path: input/goa_human.gaf.gz
    dims: [annotation, field]
    labels:
      annotation: auto
      field: builtin
```

No optional parameters. GAF's layout is fixed by specification; it is not open for adjustment.

### New: TsvReader

Handles `.tsv`. It is a peer of `CsvReader`: same `header`, `encoders`, `columns`, `info_columns` arguments, with the sole difference that the separator is hardcoded to `\t` and not user-changeable.

TSV is a generic format, so generic capabilities are exposed as arguments:

| Argument | Purpose |
|---|---|
| `header` | Whether the first line is a header (default `True`) |
| `encoders` | Encoding strategy for non-numeric columns |
| `columns` | Restrict reading to these header names; label indices still refer to the original file |
| `info_columns` | Columns to read into `info` instead of `data` |

### Changed: CsvReader

Gains two optional arguments, `columns` and `info_columns`, aligning it with `TsvReader`.

- `columns`: restrict reading to these header names, in the order given. `labels` position indices still refer to the original file, independent of `columns`.
- `info_columns`: `{column_name: info_field_name}`. The column is read verbatim as strings into `info`, declared in `axis_info[row_dim]`, and removed from `data`.

Behavior is unchanged when neither is given.

### Changed: TxtReader

`.tsv` is removed from `extensions`, leaving `.txt` and `.tab`. The `.tsv` suffix is now owned exclusively by `TsvReader`. Delegation is retained for `.txt`/`.tab`, which have no dedicated Reader.

## Step changes

### New: annotate

Attaches reference fields onto a target by key label. This is the standard "external lookup table plus your own results table" operation.

Two sources of reference fields are supported:

- **data column**: a label on the reference's `field_dim`. Encoded columns carry their encoder across so code spaces stay comparable.
- **info field**: declared parallel to `source_dim` in `axis_info`, typically read by `info_columns`.

Matching is by label, not by position. Target labels without a reference match get NaN. The output contract is `unknown`: it does not change the data dimensions, only adds info fields, so output validation degrades to a numeric-tensor check.

```yaml
- name: annotate
  inputs: [variants, reference]
  params:
    target_dim: variant
    source_dim: variant_id
    fields: [mapped_gene, context, risk_allele_frequency]
    output: annotated
```

### New: prioritize

Ranks positions by a numeric info field and keeps the top N. Output order matches source order (not ranking order); only the kept subset remains.

```yaml
- name: prioritize
  inputs: [annotated]
  params:
    dim: variant
    by: risk_allele_frequency
    top_n: 10
    ascending: true
    output: top_rare
```

Encoded fields are rejected: encoded codes are not order-preserving. NaN ranks last regardless of direction.

### New: order_axis

Reorders one axis by an info field. Unlike `prioritize`, it keeps every position and only changes their order. Used to sort variants by genomic position before plotting, sort features by variance, or sort samples by a covariate.

```yaml
- name: order_axis
  inputs: [annotated]
  params:
    dim: variant
    by: risk_allele_frequency
    descending: false
    output: ordered
```

### New: explode

Expands a multi-valued info field (semicolon- or pipe-separated) into separate positions, replicating other axis-parallel fields. This is the standard "one-to-many annotation to long table" operation, preparing input for `enrich_go` and `pivot`.

The exploded field is removed from `info`; its values become the new labels. If that field had an encoder, the encoder is dropped too, avoiding an orphan-encoder error.

```yaml
- name: explode
  inputs: [gaf]
  params:
    dim: annotation
    field: db_object_synonym
    sep: "|"
    output: annotation_synonym_long
```

### New: pivot

Long-to-wide conversion. Two categorical columns become the row and column axes; an optional third column supplies the cell value.

The actual conversion uses `pandas groupby().agg().unstack()`, which is orders of magnitude faster than a Python loop. Aggregation methods: `sum`, `first`, `max`, `min`, `count`.

Hard memory cap: an output exceeding 200 million cells raises an error rather than attempting allocation, prompting the user to filter first. This prevents accidentally materialising a huge dense matrix from a sparse long table.

```yaml
- name: pivot
  inputs: [gaf]
  params:
    index_label: db_object_symbol
    columns_label: go_id
    index_name: gene
    columns_name: go_term
    agg: first
    output: gene_by_go
```

### New: enrich_go

Hypergeometric test with multiple-testing correction. Two 2D Forms, `hits` and `universe`, both as binary gene × term matrices. For every term:

```text
N          total genes in universe
n          total genes in hits
K          genes annotated to the term in universe
k          genes annotated to the term in hits
expected   n * K / N
P          P(X >= k | hypergeometric(N, K, n))
Q          P adjusted by the requested method
```

Output is `[term_dim, "statistic"]` with 5 columns: `term_size`, `n_hit`, `expected`, `P_VALUE`, `Q_VALUE`. Correction methods: `fdr`, `bonferroni`, `holm`, `hommel`, `fdr_by`.

Hits genes must be a subset of universe genes. `min_term_size` drops terms that are too small.

Statistics are delegated to `scipy.stats.hypergeom` and `statsmodels.stats.multitest`, not reimplemented.

```yaml
- name: enrich_go
  inputs: [hits, universe]
  params:
    gene_dim: gene
    term_dim: go_term
    correction: fdr
    min_term_size: 5
    output: enriched
```

### New: enrichment_plot

Standard visualization for GO enrichment: horizontal bars of `-log10(Q)` for the top N terms, with bar color mapped to `n_hit`.

```yaml
- name: enrichment_plot
  inputs: [enriched]
  params:
    q_column: Q_VALUE
    size_column: n_hit
    top_n: 20
    filename: go_enrichment.png
    title: "GO enrichment"
```

### Contract fixes: annotate, prioritize, order_axis

The `output_contract` for these three operators changed from `{"mode": "attach"}` / `{"mode": "subset"}` / `{"mode": "passthrough"}` to `{"mode": "unknown"}`.

Reason: the `field in known` check in `compatible` performs an O(n²) walk over 1.19 million labels, hanging on large tables. `unknown` skips that check at the cost of losing dimension and label assertions on the output. Structural correctness is guaranteed by each operator's own construction logic.

## End-to-end pipeline

### GO enrichment

| Task | Path | Data | Main steps |
|---|---|---|---|
| GO enrichment | `tasks/go_enrichment_demo` | GAF + KEGG p53 pathway gene set | `pivot` → `select` → `enrich_go` → `enrichment_plot` |

Real data, real gene set, end-to-end with no preprocessing:

```text
GAF (881,380 rows, 17 columns)
  → GafReader
  → pivot → universe (19702 × 17894)
  → select → hits (30 × 17894)
  → enrich_go → enriched (7424 × 5)
  → enrichment_plot → go_enrichment_p53.png
```

Result: 30 genes yield 137 GO terms at q < 0.05.

## Operator demos

Each new operator has a demo under `tasks/<operator>_demo/`, containing a `task.yaml`, a standalone unit test `test_<operator>.py`, and real input data.

## Breaking changes from v2

- `TxtReader` no longer handles `.tsv`. Sources pointing at `.tsv` are now served by `TsvReader`. Argument syntax is the same, but `TxtReader`'s `reader` delegation argument has no effect on `.tsv`.
- `annotate` / `prioritize` / `order_axis` output contracts changed from specific modes to `unknown`. Tools relying on output contracts for static type inference will see looser declarations.

## Non-breaking additions

- All v1/v2 `task.yaml` files continue to run.
- `CsvReader` behavior is unchanged when neither `columns` nor `info_columns` is given.
- `TxtReader` handling of `.txt` and `.tab` is unchanged.

## Design principles (newly explicit)

Three rules that were previously implicit are now stated:

1. **One suffix (or one suffix group) per Reader.** Format knowledge lives in the Reader; users are not asked to pass arguments that make a generic Reader pretend to be another format.
2. **Do not push preprocessing into Readers.** A Reader translates format to Form. It does not select columns, filter rows, or rename fields. New formats get new Readers; generic Readers do not gain format-specific parameters.
3. **Generic capabilities as arguments, format knowledge as code.** `columns` and `info_columns` are generic capabilities any tabular format may need and can be arguments. GAF's 17-column layout, `!` comments, and `db_object_synonym` multi-value semantics are GAF-specific and belong in code.

## Optional dependencies

v3 introduces no new optional dependencies. `enrich_go` relies on `scipy` and `statsmodels`, both already in `requirements-analysis.txt`.
