# Upstream v4

Fourth version of the BioPipe engine. Adds the first non-genotype,
non-tabular analysis domains to the built-in operator set: nucleotide
sequence analysis from FASTA, and genomic interval analysis from BED.
Extends the FASTA Reader with an explicit character-encoding contract
so any future sequence reader (FASTQ, 2bit, GenBank) can reuse the same
operators without changes.

## Scope

- 1 Reader contract extension (`FastaReader` declares `representation`,
  `alphabet_map`, `unknown_code` in `info`).
- 10 new built-in Steps.
- 3 end-to-end pipelines: sequence profiling, annotation QC, interval analysis.
- 10 new demo tasks under `tasks/<operator>_demo/`, all with real public data.
- No new optional dependencies. All new kernels use NumPy and existing pandas.

## Reader changes

### Changed: FastaReader

The FASTA reader now declares its character-encoding contract in
`info` instead of leaving the mapping implicit in code:

```python
info = {
    "missing_code": np.nan,
    "alphabet": "dna" | "rna" | "protein",
    "representation": "sequence_codes",
    "alphabet_map": {"A": 0, "C": 1, "G": 2, "T": 3, "U": 3, "N": 4},
    "unknown_code": 5,
}
```

`output_contract` is extended with matching type declarations.
Nothing else changes: the encoding values themselves, the layout
`[sequence, position]` with NaN padding, and the label rules are
identical. Existing tasks and demos are unaffected.

The reason for the change is contract reuse. Sequence-consuming
operators now read the mapping from `info["alphabet_map"]`; a future
`FastqReader` or `TwoBitReader` that declares
`representation == "sequence_codes"` is accepted by the same
operators without any operator change.

### No change: BedReader

BED records already expose standard column names (`chrom`,
`chromStart`, `chromEnd`, `name`, `score`, `strand`, ...) and encoded
non-numeric columns through `info["encoders"]`. Interval operators
consume that structure directly.

## Step changes

### New: sequence analysis

All four operators share the same input contract:

```python
input_contracts = [port(
    ndim=2,
    dims=[param("sequence_dim", "sequence"),
          param("position_dim", "position")],
    info={
        "missing_code": MISSING,
        "representation": {"type": "string", "const": "sequence_codes"},
        "alphabet_map": {"type": "object"},
        "unknown_code": {"type": "integer"},
        "alphabet": {"type": "string", "enum": ["dna", "rna"]},
    },
)]
```

| Step | Output | Notes |
|---|---|---|
| `sequence_stats` | `[sequence, statistic]` | statistic = `length`, `gc`, `n_ratio`, `valid_ratio` |
| `kmer_count` | `[kmer, sequence]` | all A/C/G/T words of length k; `k` = 1..6, default 3 |
| `find_orfs` | `[orf, statistic]` | statistic = `strand`, `frame`, `start`, `end`, `length_nt`, `length_aa`; `info["sequence"]` is axis-parallel; `min_aa` default 1 |
| `motif_scan` | `[motif, sequence]` | IUPAC motif search; `motifs` = `{"name": "pattern"}`; counts overlapping hits |

Windows crossing N, unknown codes, or the NaN padding are skipped.
`find_orfs` scans both strands, all three frames; each ATG is closed
by the first in-frame stop (TAA/TAG/TGA).

### New: GFF3/GTF annotation analysis

All three operators take the Gff3Reader / GtfReader output
`[record, field]` with `info.encoders`.

| Step | Output | Notes |
|---|---|---|
| `gff_feature_stats` | `[feature_type, statistic]` | statistic = `count`, `total_length`, `mean_length`, `min_length`, `max_length`, `mean_exons_per_gene` |
| `gene_structure` | `[gene, statistic]` | statistic = `n_exons`, `n_introns`, `gene_length`, `cds_total`, `strand`; gene linkage via `gene_id=` or `Parent=` in attributes |
| `annotation_gaps` | `[gap, statistic]` | statistic = `gap_length`, `left_start`, `left_end`, `right_start`, `right_end`; `info["seqid"]`, `info["left_gene"]`, `info["right_gene"]` are axis-parallel; `min_gap` filters small gaps |

`gff_feature_stats` computes `mean_exons_per_gene` from the whole
file's exon and gene counts, and reports it only on the `gene` row.

### New: genomic interval analysis

| Step | Output | Notes |
|---|---|---|
| `interval_stats` | `[chrom, statistic]` | statistic = `n_intervals`, `total_bp`, `mean_length`, `median_length`, `min_length`, `max_length`, `span_bp`; `median_length` is the usual average of the two middle values for even counts |
| `interval_merge` | `[merged_region, statistic]` | statistic = `start`, `end`, `length`, `n_intervals`; `info["chrom"]` is axis-parallel; merges when the gap between intervals is `<= min_overlap` (default 0) |
| `interval_overlap` | `[pair, statistic]` | statistic = `overlap_start`, `overlap_end`, `overlap_length`, `a_length`, `b_length`, `overlap_fraction_a`, `overlap_fraction_b`; `info["chrom"]`, `info["a_id"]`, `info["b_id"]` are axis-parallel; sweep-line, each pair emitted once; `min_overlap` default 1; `max_output` default 1,000,000 |

`interval_merge` and `interval_overlap` operate on half-open
intervals `[start, end)`. Book-ended intervals (touching, zero-length
gap) are merged by default in `interval_merge` and do not overlap in
`interval_overlap`.

## End-to-End Pipelines

| Task | Path | Data | Main steps |
|---|---|---|---|
| Sequence profiling | `tasks/sequence_profiling_demo` | SARS-CoV-2 genome + human BRCA1/TP53 mRNA + pUC19 + phiX174 | `sequence_stats` / `kmer_count` / `find_orfs` / `motif_scan` branched from one FASTA source |

| Interval analysis | `tasks/interval_analysis_demo` | ENCODE cCREs + Ensembl Regulatory Build | `interval_stats` → `interval_merge` → `interval_overlap` |

## Operator Demos

Each new operator has a demo under `tasks/<operator>_demo/` with a
`task.yaml`, a hand-counted unit test, and the required input
downloaded from a public source.

| Demo | Operator | Data |
|---|---|---|
| `sequence_stats_demo` | `sequence_stats` | SARS-CoV-2 + BRCA1 + TP53 FASTA |
| `kmer_count_demo` | `kmer_count` | same FASTA, k=3 |
| `find_orfs_demo` | `find_orfs` | same FASTA, min_aa=100 |
| `motif_scan_demo` | `motif_scan` | same FASTA, TATA-box / Kozak / polyA / ATG / stop |
| `gff_feature_stats_demo` | `gff_feature_stats` | S. cerevisiae GFF3 |
| `gene_structure_demo` | `gene_structure` | S. cerevisiae GFF3 |
| `annotation_gaps_demo` | `annotation_gaps` | S. cerevisiae GFF3, min_gap=500 |
| `interval_stats_demo` | `interval_stats` | ENCODE cCREs |
| `interval_merge_demo` | `interval_merge` | ENCODE cCREs, min_overlap=0 |
| `interval_overlap_demo` | `interval_overlap` | cCREs × Ensembl Regulatory Build, min_overlap=1 |

Every test includes a hand-computed reference (for example `kmer_count`
counts of `ACGTACGT` at k=2, ORF start/end on a known 20 nt chain, and
sweep-line boundary pairs in `interval_overlap`), not only shape checks.

## Breaking changes from v3

None.

## Non-breaking additions

- All v1/v2/v3 `task.yaml` files continue to run unchanged.
- Existing saved graphs, plugin pins, and installed wheels remain valid.
- `FastaReader` output layout, encoding values, and label rules are unchanged.
- No new optional dependencies. `kmer_count`, `find_orfs`, `motif_scan`,
  and all interval operators use only NumPy and the existing pandas install.

## Design principles (newly explicit)

Two rules applied for the first time in this version:

1. **Reader-declared encoding, operator-declared semantics.** A reader
   that emits a specific data model declares it in `info`. Operators
   that consume that model declare it in their input contracts. Neither
   side hard-codes a numeric mapping that could have been declared.
2. **Domain isolation.** Sequence analysis never touches genotype
   semantics (`representation == "hard_call"` / `"dosage"`); interval
   analysis never touches Form-level numeric operators. Each domain has
   its own set of readers, its own info conventions, and its own
   operators, and they do not share code paths that would couple them.
